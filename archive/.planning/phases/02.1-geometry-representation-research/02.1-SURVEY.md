## GEOM-01 — Flat-Target Class Membership

**The assumption, precisely:** the method's objective or solver seeks a Euclidean embedding and
treats input dissimilarities as realisable there. Phase 2 measured it failing: 5,029/10,000
eigenvalues negative, m=0.412071, r=0.052419 passing (diffuse tail, no dominant outlier), every
negative 10–11 orders above the float64 noise floor (7.174e-09 at k=15), reproduced four ways.

**The finding:** the assumption is shared far more widely than the diagnostic. LLE, Hessian LLE,
LTSA, Laplacian eigenmaps, MVU, t-SNE, UMAP all target flat space; none can produce a
negative-eigenvalue statistic.

| Method | Solver (one clause) | Flat target? | Euclidean-validity diagnostic? | Why not |
|---|---|---|---|---|
| Isomap | classical MDS on double-centred geodesic distances | Yes | **Yes** | — (the method this milestone measured) |
| Classical MDS | eigendecomposes `B = -1/2 J D² J` directly | Yes | **Yes** | — |
| LLE | eigenproblem on `(I−W)ᵀ(I−W)` | Yes | No | Gram-type product — PSD by construction on any input |
| Hessian LLE | local-Hessian quadratic form's null space | Yes | No | sum of squared local estimates — PSD by construction |
| LTSA | aligns local PCA tangent frames via a PSD alignment form | Yes | No | local covariances are Gram matrices — PSD by construction |
| Laplacian eigenmaps | generalized eigenproblem on `L = D − W` | Yes | No | `xᵀLx = Σ w_ij(x_i−x_j)² ≥ 0` for any non-negative weights |
| MVU | SDP maximising trace subject to local constraints **and an explicit PSD constraint** | Yes | No | a negative eigenvalue is *infeasible* under the solver's own constraint set [CITED — Weinberger & Saul formulation not re-verified this session] |
| t-SNE | KL divergence between neighbourhood distributions | Yes | No | never forms a Gram/Laplacian/covariance matrix — no spectrum to inspect |
| UMAP | fuzzy-set cross-entropy via SGD | Yes | No | same mechanism family — no Gram-type object ever constructed |

**Two mechanisms, distinct:** (1) PSD-by-construction (MVU, Laplacian eigenmaps, LLE/HLLE/LTSA) —
the eigendecomposed object cannot carry a negative eigenvalue regardless of input geometry;
(2) never-forms-a-Gram (t-SNE, UMAP) — the sign question cannot even be posed. Only Isomap and
classical MDS form a double-centred Gram *without* constraining it PSD — `B` is PSD iff `D` is
Euclidean, which is exactly the property under test.

**Within-family instance:** `Isomap.kernel_pca_.eigenvalues_` is truncated to n_components (18)
and structurally cannot contain a negative eigenvalue either — Phase 2 computed the full spectrum
by hand for exactly this reason (02-FINDINGS §3.2).

**Consequence:** a clean UMAP/t-SNE plot — or a clean truncated-attribute read on this exact fit —
means the failure became **invisible, not absent**. "Does not show negative eigenvalues" = "does
not measure the problem", never "does not have it". The honest test of any candidate is whether it
carries a validity diagnostic that could have failed and did not.

## GEOM-02 — Non-Flat-Target Candidates

Organising fact (from the ratified fork, not re-argued): candidates divide on whether they produce
a coordinate vector a decoder can differentiate against. All six described fully — a future reader
re-opening the fork needs the losing branch's numbers.

### Hyperbolic (Poincare ball / Lorentz)

- **Assumptions:** one constant negative curvature everywhere — Pitfall 3 flags likely-wrong for
  heterogeneous morphology; A7 is an inference from the diffuse-tail shape, tested by 02.1-03's
  delta probe (tree + flat-Euclidean anchors).
- **Cost:** Riemannian SGD fit from the existing matrix — wall-clock class ≥1 Isomap fit
  (78.5–104.5 s) per convergence; the delta probe itself is cheap (200,000 quadruples off
  dist_matrix_, no fit) and runs first.
- **Maturity:** `geoopt` 0.5.1 (2025-06-19), SUS (`unknown-downloads`, `no-repository` — signal
  gap, not a finding; gate applies anyway). Don't hand-roll exp/log maps + RSGD (silent NaNs near
  the ball boundary). The one sanctioned hand-roll anywhere: sampled Gromov delta (wrong way =
  naive C(10000,4) brute force).
- **Fork side:** coordinate-producing.
- **Phase 3 demand:** DEC-01/CURV-08 referent-amended; DEC-02..05, CURV-01..07 unchanged; none
  rewritten.

### Mixed-curvature product manifold

- **Assumptions:** heterogeneous curvature decomposing into few constant-curvature factors;
  substitutes a factor-count/signature model-selection problem for hyperbolic's single parameter,
  unresolved by this survey.
- **Cost:** same order as hyperbolic + the model-selection step (unpriced — depends on signatures
  compared).
- **Maturity:** `geoopt` (implements products) or `geomstats` 2.8.0 (2024-09-09, SUS, heavier,
  Supporting-tier; INRIA/JMLR [CITED]).
- **Fork side:** coordinate-producing.
- **Phase 3 demand:** identical to hyperbolic.

### Pseudo-Euclidean / Krein retention

- **Assumptions:** the indefinite bilinear form is the right object; the negative directions carry
  signal, not error — takes Phase 2's finding most literally. Forcing them away
  (Cailliez/Lingoes/clipping) is diagnostic-blind and self-defeating per Pattern 1 / Prohibited
  Moves.
- **Cost:** cheapest by a wide margin — the spectrum and matrix are on disk; **one bottom-40
  eigensolve** (same subset strategy as Phase 2's top block). The (p,q) ladder
  (P_LADDER=(1,2,3,5,8,13,18,25,40), Q_LADDER=(0,1,2,3,5,8,13,25,40)) costs nothing further.
- **Maturity:** zero new dependencies — `scipy.linalg.eigh` already in venv; the only candidate
  needing no gate. Neuc-MDS (NeurIPS 2024, arXiv:2411.10889 — optimised eigenvalue selection) has
  **no maintained Python package**; top-k-per-sign is the named lower-risk fallback.
- **Fork side:** coordinate-producing — a (p,q)-signature real vector per point; the indefinite
  form lives in the distance computation, not the coordinate type.
- **Phase 3 demand:** same bucketing as above, plus: the working dimension is a **pair (p,q)**,
  never collapsed (Working-Dimension Rule).

### Diffusion maps

- **Assumptions:** the kernel bandwidth defines what "diffusion distance" means; the failure mode
  is quiet — it answers a different question without raising an error.
- **Cost:** dense kernel build (~800 MB class) + leading-eigenvector solve — ~1 dense eigensolve
  (~100 s) class; cheaper in kind than RSGD, dearer than Krein.
- **Maturity:** `datafold` 2.0.2 (2026-03-13, most recent of all candidates, SUS); `pydiffmap`
  stale since 2019-02-04, deprecated, prefer datafold. Don't hand-roll bandwidth selection or the
  symmetric-conjugate stabilisation.
- **Fork side:** coordinate-producing.
- **Phase 3 demand:** same bucketing. Not on the shortlist (Supporting-tier, heavier than needed).

### Ollivier-Ricci

- **Assumptions:** the k*=15 graph faithfully discretises the manifold; continuum-limit
  convergence to Ricci [CITED only — arXiv:2307.02378, unread; specifically uncertain at ~20-25
  dims / n=10,000 ≈ 400-500 points per intrinsic dimension]. The fork verdict does NOT lean on
  this claim — the disqualification is structural (no coordinates).
- **Cost:** mandatory reuse of the k*=15 graph, exactly **150,000 edges** (another k re-opens the
  closed k-sensitivity question). Per-edge OT: exact LP intractable; Sinkhorn **necessary, not
  optional**. No embedding cost — but a tree-and-expander sanity fixture must be built before any
  number is trusted.
- **Maturity:** `GraphRicciCurvature` 0.5.3.2 (2024-06-26, SUS; repo manually verified — 290
  stars, Apache 2.0), `POT` 0.9.7.post1 (SUS `too-new` — false positive, mature since ~2016),
  `networkx` **not installed**. Three gates.
- **Fork side:** graph-native — scalar per edge, no coordinate vector.
- **Phase 3 demand:** all 13 ids rewritten: DEC-01..05 dropped (nothing to decode); CURV-01/02
  dropped; **CURV-03 replaced** — intrinsic Ricci (neighbourhood overlap across an edge) is a
  different mathematical object from the extrinsic mean-curvature vector (how a fitted surface
  bends from its tangent plane in ambient space); CURV-04/05 dropped; CURV-06/07 rearchitected
  around the graph fixture; CURV-08 rewritten to graph edges.

### Forman-Ricci

- **Assumptions:** same graph-fidelity assumption; **no continuum-limit claim** — closed-form
  combinatorial formula (degrees + shared triangles), at the cost of a less direct connection to
  differential-geometric Ricci.
- **Cost:** cheapest graph-native — one linear pass over 150,000 edges, no OT. Same fixture
  requirement.
- **Maturity:** same `GraphRicciCurvature` + `networkx` (not installed); no POT needed.
- **Fork side:** graph-native.
- **Phase 3 demand:** identical rewriting bucket to Ollivier-Ricci.
