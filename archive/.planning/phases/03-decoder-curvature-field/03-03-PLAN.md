<objective>
Close WR-01, WR-02 and WR-03 in `notebooks/pu_manifold/derivative_bridge.py` before the bridge is
run at PU scale for the first time.

The bridge is the only instrument in this phase that is independent of `torch.func` entirely. Plan
03-05's forward-versus-reverse equivalence test compares two autodiff paths and structurally cannot
catch a bug both paths share; finite differences can. Phase 3 is also the first thing ever to edit
`chart_curvature.py`, which makes it the first point at which such a shared bug could be introduced.
All three warnings are recorded in `02.6-REVIEW.md` (commit `1d3f666`) with their fixes already
specified, and none of them affects any number Phase 02.6 recorded — they start mattering the moment
this phase relies on the bridge.

WR-01 is the third defect of one species this codebase has produced: a contract that passes every
acceptance criterion at toy scale and fails at real scale (`02.6-FINDINGS-02.md` section 12 records
the other two). WR-03 is a fourth instance of the same species, masked today only because
`BRIDGE_N_POINTS` and `VMAP_CHUNK` happen to be numerically equal.

Purpose: make the independent verification instrument trustworthy before it is trusted.
Output: three closed warnings, three regression tests, unchanged reporting semantics.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| decode closure -> dtype guard | A closure or bound method reaches a guard written for a model object; the guard's per-parameter half silently no-ops |
| batch size -> autodiff chunk width | A batch larger than the fixed chunk width reaches an unchunked `vmap` call |
| near-zero reference -> relative-error column | A thin denominator produces a headline number a reader cannot distinguish from real disagreement |

ASVS L1, block on `high`. No network, auth, untrusted-input, secret or persistence surface. V5
applies only as internal contract checks. All threats are data-integrity, not adversarial.
