## Shared Patterns

### Gate-then-verdict-then-handoff (R6)
**Source:** `notebooks/pu_manifold/cae.py:1064-1187` (verdict_from_metrics,
write_cae_verdict, write_cae_handoff) and `notebooks/pu_manifold/topoae.py:647-817`
(the delegating wrapper + mirrored writer trio + clear_stale_handoff).
**Apply to:** `curvature_probe.py` (verdict function), both new runner scripts
(verdict + handoff calls).
**Rule:** verdict artifact is **always** written (PASS or FAIL); handoff is written
**only** on PASS (`write_*_handoff` raises `ValueError` if verdict != "PASS" —
`cae.py:1163-1166`, `topoae.py:765-768`); any stale handoff from a prior run is
**actively deleted** on FAIL (`clear_stale_handoff`, `topoae.py:794-817`, deletes
both the `.json` and its `.meta.json` sidecar, never raises if nothing is there).

### Absent/non-finite gating metric guard
**Source:** `cae.py:1077-1085`, mirrored verbatim in intent by `topoae.py:666-674`.
**Apply to:** any new `verdict_from_*` function in `curvature_probe.py`.
**Rule:** before evaluating any gate, raise `ValueError` naming the specific
missing/non-finite metric. "A missing or non-finite measurement can never become a
PASS" — halting is the honest behaviour.

### Cache discipline
**Source:** `notebooks/pu_manifold/cache.py` (all 122 lines read).
**Apply to:** both new runner scripts, never to `curvature_probe.py` itself (that
module stays pure-function, no I/O, matching `cae.py`'s own stated posture at
lines 2-4: "Tensors in, tensors and dicts out -- no file I/O, no cache handling;
the runners under notebooks/diagnostics/ own paths").
**Functions to reuse unmodified:** `cache.json_cache(stem, cfg, compute_fn)` for
verdict/handoff artifacts, `cache.joblib_cache` if any intermediate sweep array
needs persisting, `cache.cache_path`/`_assert_inside_cache` never called directly
by new code (always go through `json_cache`/`joblib_cache`/`npz_cache`). Cfg dicts
must include `{"fit_key": ..., "phase": "02.5"}` at minimum, following
`cae.py:1113` and `topoae.py:695` (`{"fit_key": fit_key, "phase": "02.4", ...}`
precedent) — thresholds go **inside** the cfg dict per `topoae.write_topoae_verdict`'s
documented rationale (`topoae.py:696-699`) so editing a threshold after the fact
raises a manifest-mismatch `ValueError` instead of silently re-verdicting.

### Exact chart-decoder differentiation composition point
**Source:** `notebooks/pu_manifold/cae.py:827-832`.
```python
def _decode_through_chart(model: "ChartAutoEncoder", z: torch.Tensor, chart_idx: int) -> torch.Tensor:
    """(batch, l) -> (batch, m): the two-hop decode through one named chart -- that
    chart's coordinate, its own chart decoder, then the single shared embedding decoder."""
    z_charts = model.chart_coords(z)
    w = model.chart_decoders[chart_idx](z_charts[:, chart_idx, :])
    return model.embedding_decoder(w)
```
**Apply to:** Stage 2 Arm B differentiation (RESEARCH.md Pattern 4). Note the exact
caveat RESEARCH.md records: `_decode_through_chart` differentiates through the
chart-coordinate-**producing encoder too** (it takes `z`, the initial-encoder
output). For curvature, the new code must differentiate only the **decoder half**
(chart coordinate → ambient) — i.e. call `model.chart_decoders[chart_idx]` and
`model.embedding_decoder` directly inside the `torch.func.jacrev`/`hessian`-wrapped
function, as RESEARCH.md's `chart_curvature` example does, rather than composing
`_decode_through_chart` itself under `jacrev`.
