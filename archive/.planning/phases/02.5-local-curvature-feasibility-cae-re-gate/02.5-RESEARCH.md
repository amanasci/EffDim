# Phase 02.5: Local Curvature Feasibility & CAE Local Re-Gate - Research

**Researched:** 2026-08-07
**Domain:** Second-fundamental-form / mean-curvature estimation from point clouds at high ambient dimension and low sampling density; local re-scoping of an existing Chart Auto-Encoder gate
**Confidence:** MEDIUM (the central mathematical correction is self-derived and numerically verified to high precision; the literature survey around it is directional, not exhaustive — several searches returned no citable closed-form sample-complexity bound and are flagged LOW/`[ASSUMED]` accordingly)

## Summary

This phase turns on one question the discussion already half-answered but did not derive: is the `d(d+1)/2`-coefficient count that motivated calling this "badly underdetermined" (ROADMAP re-scope) actually the number that binds? It is not, for the statistic this phase gates on. Mean curvature is the *trace* of the second fundamental form, and the classical identity `Δ_M x = H` (Laplace–Beltrami operator applied to the manifold's own coordinate embedding yields the mean curvature vector — a standard result restated in, e.g., Meyer/Desbrun/Schröder/Barr's discrete differential-geometry operators) means the trace is recoverable as **one unknown averaged over `k` samples**, not `d(d+1)/2` unknowns fit from `k` equations. This document derives that identity's finite-`r` bias from first principles (a uniform-ball second-moment calculation), verifies the constant D-00 already states (`r²/(2(d+2))`) exactly, and independently rederives and numerically confirms the analytic mean curvature of `sklearn.datasets.make_swiss_roll`'s surface — a closed form (`H(t) = (t²+2)/(2(1+t²)^{3/2})`) that appears nowhere in the searched literature and had to be worked out and checked against finite differences in this session.

The estimator this phase gates on (D-05) is therefore a **centroid-displacement mean-curvature estimator**, projected onto a locally-PCA-estimated normal space, with a local quadric/jet fit run alongside as a non-gating cross-check. Its two real failure modes are not "too few equations" but (a) `O(r²)` bias at finite neighbourhood radius, growing with the curvature itself, and (b) contamination by non-uniform sampling density, which displaces the centroid in a way statistically indistinguishable from curvature unless corrected — the exact D-06 concern, and the reason the fixtures must be deliberately non-uniform, since the Swiss roll (evenly sampled by construction) cannot exercise this failure mode at all.

Stage 2's CAE re-gate reuses `notebooks/pu_manifold/cae.py` unchanged (Phase 02.2's sealed artifact) and its three cached seed fits. Its central technical move — differentiating a chart decoder **exactly** via `torch.func.jacrev`/`vmap`/`hessian` rather than estimating curvature statistically — has a direct, already-implemented composition point: `cae._decode_through_chart(model, z, alpha)` is exactly the two-hop chart-decoder-then-shared-embedding-decoder map whose Jacobian and Hessian this phase needs; nothing in `cae.py` needs to change to differentiate it. The one real repo-hygiene decision this research surfaces and CONTEXT.md does not address: `notebooks/pu_manifold/curvature.py` already exists as a set of `NotImplementedError` stubs explicitly labelled `"Implemented in Phase 3 (CURV-0N)"`. This phase's stage-2 CAE arm needs the identical mathematical machinery (pullback metric, normal-projected Hessian, mean curvature vector via `g`-trace) — the planner must decide explicitly whether 02.5 implements those stubs (pulling CURV-01..03 forward) or builds parallel, phase-scoped functions elsewhere, and must not silently do the former.

**Primary recommendation:** Implement the centroid/Laplace–Beltrami estimator and its local-quadric cross-check as new pure functions in a new module (not `curvature.py` — see above), gate stage 1 on Spearman rank correlation against the analytic `H` of a Swiss-roll-plus-graph-of-function fixture family calibrated against a `scipy.stats.permutation_test` null, and — only on a stage-1 PASS — reuse `cae.py`'s sealed fits and `topoae.py`'s R6 verdict/handoff machinery unmodified for the stage-2 head-to-head. No new package installs are needed anywhere in this phase.

## User Constraints (from CONTEXT.md)

### Locked Decisions

- **D-00:** **The ROADMAP re-scope's framing of the binding constraint is wrong, and planning must not
  inherit it.** The re-scope records that a local quadratic fit needs `d(d+1)/2` coefficients per
  normal direction — 210 at `d=20` — against `k* = 15` neighbours, and calls this "badly
  underdetermined." That count is the cost of the **full second fundamental form**. Mean curvature is
  only its *trace*, and the classical identity `Δ_M x = H` (equivalently: the centroid of a
  neighbourhood is displaced from its centre point along the mean curvature vector, by roughly
  `r²/(2(d+2))·H`) estimates the trace as **an average over `k` vectors** — one unknown with `k`
  samples, not 210 unknowns with 15 equations. The underdetermination may therefore not bind at all.
  This reframes whether the phase is feasible and must be stated in the pre-registration. —
  **Reversibility:** costly — the entire estimator choice (D-05) and the phase's feasibility case rest
  on it; if the identity were misapplied, stage 1's design would need rebuilding from scratch.

**Feasibility criterion (stage 1)**

- **D-01:** Spearman rank correlation between estimated and true `|H|` is the gating statistic; median
  relative error on `|H|` is computed and reported as non-gating evidence. Rationale: Phase 4
  partitions by `|H|` quantiles, so it consumes ordering, not magnitude. — **Reversibility:** one-way.
- **D-02:** The Spearman threshold is calibrated against a permutation null (shuffle true curvature
  values, recompute Spearman a few hundred times, set the bar above the chance distribution). Still
  pre-registered and ratified before the probe runs. — **Reversibility:** one-way.
- **D-03:** Fixtures: the Swiss roll as the mandatory `d=2` anchor, plus a graph-of-function family
  `M = {(x, f(x))}` for `x ∈ ℝᵈ` embedded in `ℝᴰ`, where `H` follows analytically from `f`'s Hessian. A
  Swiss roll cannot reach `d = 18–25`; a `d`-sphere has constant `H` so Spearman is undefined on it.
  CLAUDE.md's "always use the Swiss roll" is honoured — the Swiss roll remains the mandatory
  sanity-check fixture and `d=2` anchor; the family extends rather than substitutes.
- **D-04:** Stage 1 emits a feasibility boundary, not a binary verdict: sweep `(d, D, n, k)`, locate
  where Spearman crosses the null-calibrated threshold, report where the PU regime sits relative to
  that frontier. On the wrong side: halt for user decision, no auto-fallback (02.2's D-02 pattern), and
  name Ollivier-Ricci / intrinsic curvature as the live remaining option. Do **not** emit a
  "recommended `k`."

**Estimator**

- **D-05:** The centroid / Laplace–Beltrami estimator **gates**; the local quadric ("bowl") fit is run
  alongside and its agreement reported as **non-gating** evidence. Rejected: quadric-only with
  ridge/low-rank regularization (the regularization strength would become a blind pre-registered
  dial). — **Reversibility:** one-way. Known caveats to state in the pre-registration: bias grows like
  `r²` at finite radius; sensitivity to non-uniform sampling density (D-06); yields `H` and `|H|` but
  not the full `II` (costs nothing here — Phase 4 consumes only `|H|` quantiles).
- **D-06:** Density correction is pre-registered up front AND proven on deliberately non-uniform
  fixtures. The centroid estimator assumes neighbours are spread evenly; where points bunch on one
  side, the centroid drifts that way and the drift is indistinguishable from curvature. **A Swiss roll
  is sampled evenly by construction and would NOT catch this** — fixtures must be non-uniformly
  sampled on purpose.
- **D-07:** Working dimension: primary `d = 20` as the gating rung, with a sensitivity ladder
  (02.4-style, e.g. `{8,16,20,24,32,40}`) reported as non-gating. `D_FROZEN = 5` is barred from
  inheritance. 02.2's D-04 already resolved this exact question (`d=20` from the local
  intrinsic-dimension cluster, explicitly refusing the global elbow) and that reasoning transfers
  directly. Rejected: per-point `d` (breaks cross-point `|H|` comparability, which Phase 4 needs).
- **D-08:** The estimator pre-registers its own neighbourhood rule with an explicit bias–variance
  justification, rather than silently inheriting `k* = 15` (frozen for Isomap graph connectivity/
  stability, a different objective). Sweep `k` in the probe, report sensitivity as non-gating; the
  gating `k` is fixed in advance.

**Local CAE gate design (stage 2)**

- **D-09:** Stage 2 gates on a **head-to-head against known `H`: CAE charts versus raw points** — this
  *supersedes* the ROADMAP re-scope's framing of stage 2 as "a locally-scoped gate on the CAE." If the
  centroid estimator works on raw 768-d points, no learned model is needed at all. The CAE's genuine
  value is noise-averaging (curvature is second-order: signal grows like `r²`, noise falls only like
  `σ/√k`) and exact differentiation of its chart decoder via `torch.func`. Counter-risk: a neural
  network's second derivative can wiggle where the true manifold does not. Only fixtures with analytic
  `H` can distinguish these. "The CAE is not needed" is a legitimate, reportable outcome. —
  **Reversibility:** one-way.
- **D-10:** Re-measure 02.2's three sealed cached fits (`cae_fit_43cf438bc944c509_seed20260803`, `…04`,
  `…05`) rather than training new ones — they were built with C²-smooth (SiLU) activations precisely
  for downstream curvature work, costs minutes, introduces no new tunable training hyperparameters.
- **D-11:** A retrain fallback exists but is fenced: the firing trigger is pre-registered before
  anything runs; if it fires, the retrain's hyperparameters are ratified at a blocking human-verify
  checkpoint before the retrain executes (02.4's D-19 convergence-contingency pattern). Residual risk
  to state plainly: the checkpoint is where post-hoc pressure would enter; it must record what was
  known at the time it was made. — **Reversibility:** costly.
- **D-12:** Decision rule: charts must beat raw points' Spearman by a pre-registered margin AND agree
  across 02.2's three sealed seeds within a stated tolerance (02.4's `THRESH_T1` baseline-relative
  shape). Outcome routing: **charts win** → Phase 3 uses CAE charts. **Raw points win, or tie inside
  the margin** → open the Ollivier-Ricci phase (not "CAE unnecessary, move on" — a fork). **Neither
  clears the null** → **NOT decided in this discussion** — defaults to 02.2's D-02 (halt, no
  auto-fallback), **flagged for resolution at pre-registration ratification**; planning must surface
  this, not silently pick.

### Pattern 1: Centroid / Laplace–Beltrami mean-curvature estimator

**What:** For a point `p` with `k`-nearest-neighbour set `{q_1,...,q_k}`, estimate the tangent space
`T_p` via local PCA (top-`d` eigenvectors of the neighbourhood covariance), project the centroid gap
`c - p` (where `c = mean(q_i)`) onto the **normal** complement of `T_p`, and rescale by the known ball
geometry to recover the mean curvature vector.

**Derivation (self-derived and numerically verified this session — see Sources).** Parametrize the
neighbourhood in local tangent coordinates `u ∈ ℝ^d` so that, to second order, a nearby manifold point
is `p + u + (1/2) II(u,u) + O(|u|³)`, where `II` is the (vector-valued) second fundamental form. For
`u` drawn uniformly from a `d`-ball of radius `r`, `E[u]=0` (by symmetry) and `E[u_i u_j] = (r²/(d+2))
δ_ij` (a standard uniform-ball second moment). Taking the expectation of the second-order term:

```
E[(1/2) II(u,u)] = (1/2) Σ_ij II_ij E[u_i u_j] = (r²/(2(d+2))) Σ_i II(e_i,e_i) = (r²/(2(d+2))) · H
```

where `H = tr(II)` is exactly the (unnormalized) mean curvature vector this phase gates on. This
**exactly matches** the constant D-00 already states, `c - p ≈ (r²/(2(d+2)))·H`. Odd-order terms
vanish under the ball's central symmetry, so the next correction is `O(r⁴)`, meaning the *relative*
bias in the recovered `H` is `O(r²)` — matching D-05's own stated caveat that "bias grows like `r²` at
finite radius."

**When to use:** As the gating estimator (D-05). Requires only a kNN query and one local
eigendecomposition per point — no per-normal-direction quadratic system to solve, which is exactly why
D-00's `d(d+1)/2`-coefficient count does not bind here.

**Example:**
```python
# Source: self-derived this session, cross-checked numerically (see Sources); the
# Delta_M x = H identity itself is classical (Meyer, Desbrun, Schroder, Barr,
# "Discrete Differential-Geometry Operators for Triangulated 2-Manifolds", 2003).
import numpy as np
from sklearn.neighbors import NearestNeighbors

def centroid_mean_curvature(X: np.ndarray, k: int, d: int) -> np.ndarray:
    """X: (n, D) point cloud. Returns (n, D) mean curvature vector estimates.

    d is the estimator's own working (tangent) dimension -- NOT read from D_FROZEN
    (D-07 bars that inheritance). Bias grows like r^2 (radius set implicitly by k);
    contaminated by non-uniform density (D-06) unless corrected upstream.
    """
    n = X.shape[0]
    nbrs = NearestNeighbors(n_neighbors=k + 1).fit(X)
    _, idx = nbrs.kneighbors(X)  # idx[:, 0] is the point itself
    H_est = np.zeros_like(X)
    for i in range(n):
        neigh = X[idx[i, 1:]]          # (k, D), excludes self
        p = X[i]
        centered = neigh - p
        cov = centered.T @ centered / k       # (D, D)
        eigvals, eigvecs = np.linalg.eigh(cov)  # ascending
        tangent_basis = eigvecs[:, -d:]         # top-d directions
        gap = centered.mean(axis=0)             # (D,) -- the centroid displacement
        tangent_component = tangent_basis @ (tangent_basis.T @ gap)
        normal_component = gap - tangent_component   # project OUT the tangent part
        r2 = np.mean(np.sum(centered**2, axis=1))     # empirical local scale
        H_est[i] = normal_component * (2 * (d + 2) / r2)
    return H_est
```

**Critical pitfall this pattern must avoid (see Common Pitfalls):** using the raw, unprojected
`gap = centroid - p` as the curvature signal. Any tangential asymmetry in the neighbourhood (from
non-uniform density, or simply from `k` being small) leaks a first-order, non-curvature term into
`gap` that the normal projection is specifically there to remove.

### Pattern 2: Local quadric ("bowl") fit — non-gating cross-check

**What:** Fit `z = q(u)` where `z` is the (D-d)-dimensional normal-space coordinate and `u` the
`d`-dimensional tangent coordinate, `q` a quadratic form, by ordinary least squares. `II` (and hence
`H = tr(II)`) is read off `q`'s Hessian. This is the estimator the ROADMAP re-scope's `d(d+1)/2` count
correctly describes — `d(d+1)/2` coefficients per normal direction — but D-05 demotes it to a
non-gating agreement check specifically because that count is real for this estimator, even though it
does not bind for Pattern 1.

**When to use:** Only as a cross-check against Pattern 1's gating result, never alone at the PU
regime's `d=18–25` (per D-05's rejection of "quadric-only with regularization" — the regularization
strength would be an unratified dial).

**Example:**
```python
# Source: standard local-quadric/jet-fitting formulation (Cazals & Pouget,
# "Estimating Differential Quantities Using Polynomial Fitting of Osculating
# Jets", 2005) -- osculating-jet degree-2 case, hand-implemented rather than via
# a dedicated package (see Alternatives Considered).
import numpy as np

def quadric_fit_curvature(u: np.ndarray, z: np.ndarray, d: int) -> np.ndarray:
    """u: (k, d) tangent coords (already centered at the query point).
    z: (k, m) normal coords (m = D - d).
    Returns the (m,) mean curvature vector: trace of the quadratic form's Hessian.
    Underdetermined once d(d+1)/2 > k -- this is why D-05 keeps this non-gating.
    """
    k = u.shape[0]
    n_coef = d * (d + 1) // 2
    # design matrix columns: 1, u_1..u_d, u_i*u_j for i<=j
    cols = [np.ones(k)] + [u[:, i] for i in range(d)]
    quad_idx = []
    for i in range(d):
        for j in range(i, d):
            cols.append(u[:, i] * u[:, j])
            quad_idx.append((i, j))
    A = np.stack(cols, axis=1)  # (k, 1+d+n_coef)
    coef, *_ = np.linalg.lstsq(A, z, rcond=None)  # (1+d+n_coef, m)
    quad_coef = coef[1 + d:]  # (n_coef, m)
    H = np.zeros(z.shape[1])
    for (i, j), c in zip(quad_idx, quad_coef):
        factor = 2.0 if i == j else 1.0  # Hessian_ij = factor * fitted coefficient
        if i == j:
            H += factor * c
    return H
```

### Pattern 3: Graph-of-function fixture with a spatially varying analytic Hessian (D-03)

**What:** `M = {(x, f(x), 0, ..., 0) : x ∈ ℝ^d} ⊂ ℝ^D`, `f: ℝ^d → ℝ^m` chosen so `H` is spatially
varying (unlike a sphere's constant `H`, which the discussion already ruled out because Spearman is
undefined against a constant). Padding with `D-d-m` exact zeros keeps ambient dimension controllable
up to `D=768` without introducing any curvature in the padded directions (they are totally geodesic).

**Recommended `f` (Claude's Discretion, per CONTEXT.md):** a Gaussian bump, `f(x) = A·exp(-‖x‖²/(2σ²))`
(`m=1`), whose Hessian is closed-form and whose curvature ranges smoothly from near-zero (far from the
origin) to a controllable peak (near the origin) — giving a genuine rank ordering to test Spearman
against, at any `d`.

```python
# Source: self-derived — a standard closed-form bump function, not drawn from a
# specific paper. Ambient padding pattern (flat extra dimensions carry no
# curvature) follows directly from the second-fundamental-form definition.
import numpy as np

def gaussian_bump_curvature(x: np.ndarray, A: float, sigma: float) -> tuple[np.ndarray, np.ndarray]:
    """x: (n, d). Returns (H_vector estimate target's analytic scalar trace,
    f(x) values) for embedding as (x, f(x), 0, ..., 0) in R^D.
    grad f = -(x/sigma^2) * f(x)
    Hess f = f(x) * ((outer(x,x)/sigma^4) - I/sigma^2)
    Codim-1 graph mean curvature (unnormalized trace convention matching H=tr(II)):
    H = trace(Hess f) / (1 + |grad f|^2)^{1/2}   [to leading order; exact graph
        mean-curvature formula divides by (1+|grad f|^2)^{3/2} and includes a
        grad f^T Hess f grad f correction term -- use the exact form, this is
        illustrative].
    """
    d = x.shape[1]
    f = A * np.exp(-np.sum(x**2, axis=1) / (2 * sigma**2))
    grad = -(x / sigma**2) * f[:, None]
    hess_trace = f * (np.sum(x**2, axis=1) / sigma**4 - d / sigma**2)
    return hess_trace, f  # caller applies the exact graph-curvature normalization
```

**Non-uniform density variant (D-06):** sample `x` via rejection sampling against a deliberately
skewed density `w(x)` (e.g., higher density on one side of the domain) rather than uniformly — the
Swiss roll's even-by-construction sampling cannot exercise D-06's density-correction requirement at
all, so this fixture family must carry the non-uniform burden.

### Pattern 4: Exact decoder-curvature differentiation for the CAE arm (D-09)

**What:** Stage 2's Arm B needs `H` computed through a CAE chart, not estimated statistically. The
two-hop map is **already implemented**: `cae._decode_through_chart(model, z, chart_idx)` takes an
initial-encoder embedding `z` and returns the ambient reconstruction through one named chart. This is
exactly the function whose Jacobian and Hessian (with respect to the *chart coordinate*, not `z`) give
the pullback metric and second fundamental form.

**When to use:** Only after stage 1 clears (D-09's whole point is that this arm is compared against
raw-point Pattern 1, not assumed superior).

**Example:**
```python
# Source: composes cae.py's existing (sealed, unedited) helper with torch.func's
# documented jacrev/hessian/vmap composition (docs.pytorch.org/docs/stable/
# generated/torch.func.jacrev.html); the g/II/H formulas match
# notebooks/pu_manifold/curvature.py's own stub docstrings (first_fundamental_form,
# second_fundamental_form, mean_curvature_vector) -- same math, computed here in a
# phase-scoped module rather than by editing those Phase-3-labelled stubs.
import torch
from torch.func import jacrev, hessian, vmap
from pu_manifold import cae as cae_mod

def chart_curvature(model: cae_mod.ChartAutoEncoder, z_chart: torch.Tensor, chart_idx: int):
    """z_chart: (batch, chart_dim) -- coordinates WITHIN one chart's own
    (0,1)^chart_dim space (NOT the initial-encoder embedding z). Returns per-row
    mean curvature vector (batch, out_dim)."""

    def decode_one(zc: torch.Tensor) -> torch.Tensor:
        w = model.chart_decoders[chart_idx](zc.unsqueeze(0))
        return model.embedding_decoder(w).squeeze(0)  # (out_dim,)

    J = vmap(jacrev(decode_one))(z_chart)          # (batch, out_dim, chart_dim)
    Hess = vmap(hessian(decode_one))(z_chart)       # (batch, out_dim, chart_dim, chart_dim)

    g = torch.einsum("boi,boj->bij", J, J)          # (batch, chart_dim, chart_dim) pullback metric
    g_inv = torch.linalg.inv(g)
    # normal projection per output dim: (I - J g^-1 J^T) applied to each Hess[:, o, :, :]
    proj = torch.eye(J.shape[1], device=J.device)[None] - torch.einsum(
        "boi,bij,bpj->bop", J, g_inv, J
    )
    II = torch.einsum("bop,bpjk->bojk", proj, Hess)  # (batch, out_dim, chart_dim, chart_dim)
    H = torch.einsum("bij,boij->bo", g_inv, II)      # g-trace -> (batch, out_dim)
    return H
```

**Note on `_decode_through_chart` vs. this pattern:** `cae._decode_through_chart` differentiates
*through the chart-coordinate-producing encoder too* (it takes `z`, the initial-encoder output). For
curvature, differentiate only the **decoder** half (chart coordinate → ambient), as above — the chart
coordinate is the local parameterization whose second fundamental form is being measured, matching how
`curvature.py`'s stubs are documented (`jacobian` in, not encoder-composed).

### Anti-Patterns to Avoid

- **Using the raw centroid gap without normal projection.** Pattern 1's whole point is that the
  tangential component of the gap is noise (or, under non-uniform density, a first-order bias term)
  that must be projected out — reporting the raw, unprojected displacement as "curvature" conflates
  sampling asymmetry with geometry, which is precisely D-06's concern.
- **Fitting the full quadric at `d=18–25` and gating on it.** This is the estimator the ROADMAP
  re-scope's `d(d+1)/2` count correctly warns about; D-05 already resolved this by demoting it to
  non-gating. Do not re-promote it to gating status without a fresh pre-registration.
- **Editing `notebooks/pu_manifold/cae.py` or `curvature.py`'s existing stubs to "just add" the new
  logic.** `cae.py` is sealed (import-only, per CONTEXT.md and CLAUDE.md). `curvature.py`'s stubs are
  explicitly labelled as Phase 3's — see Open Questions for why editing them here is a live risk, not
  a convenience.
- **Reporting a scalar "signed" curvature in high codimension without stating the projection basis.**
  The mean curvature *vector* `H` and its norm `‖H‖` have no sign ambiguity; any reduction to a single
  signed scalar along one chosen normal direction does, and the codebase's own convention (`curvature.py`
  docstrings, CURV-03) is to report the vector norm, never a signed scalar, for exactly this reason.

## Common Pitfalls

### Pitfall 1: Conflating "full `II` underdetermined" with "trace `H` underdetermined"
**What goes wrong:** Treating the `d(d+1)/2`-vs-`k` coefficient count (real for Pattern 2, the quadric
fit) as if it also applied to Pattern 1 (the gating centroid estimator), and concluding the phase is
infeasible before running anything.
**Why it happens:** The ROADMAP re-scope's own language ("badly underdetermined") describes the full
second fundamental form; mean curvature's status as its *trace* is easy to lose track of once the
coefficient-counting framing takes hold.
**How to avoid:** Keep the two estimators' sample-complexity stories explicitly separate in the
pre-registration (D-05 already does this by making the quadric fit non-gating) and cite the derivation
in Pattern 1 above whenever the coefficient count is mentioned.
**Warning signs:** Any planning document that states "`d(d+1)/2` coefficients against `k` samples" as
a reason stage 1 might fail, without immediately noting that the *gating* estimator sidesteps this
entirely.

### Pitfall 2: Non-uniform density masquerading as curvature
**What goes wrong:** The centroid estimator's normal-space displacement is contaminated by sampling
asymmetry — if points bunch on one side of a neighbourhood (for reasons having nothing to do with
manifold curvature, e.g. embedding clustering), the centroid drifts that way, and an uncorrected
estimator reports that drift as `H`.
**Why it happens:** The uniform-ball second-moment derivation in Pattern 1 assumes `E[u]=0`; real
neighbourhoods, especially from foundation-model embeddings (D-06 explicitly names this as a live
risk, not theoretical), violate that assumption.
**How to avoid:** D-06's own prescription — pre-register a density correction and prove it on
deliberately non-uniform fixtures (Pattern 3's rejection-sampling variant). A Swiss roll, sampled
evenly by construction, will never surface this bug even if it is present.
**Warning signs:** The estimator passes on the (uniform) Swiss roll but disagrees with the quadric
cross-check specifically on the non-uniform fixture family.

### Pitfall 3: Reporting the unprojected centroid gap
**What goes wrong:** Using `centroid - p` directly as a proxy for `H`, without projecting onto the
estimated normal space.
**Why it happens:** It looks like the same quantity, and for a manifold with no tangential asymmetry
the tangential component is genuinely near zero — so the bug is invisible on well-behaved fixtures and
only surfaces once real, asymmetric, high-dimensional data is used.
**How to avoid:** Pattern 1's code explicitly splits `gap` into tangential and normal components via
the local-PCA basis and discards the tangential part before rescaling.
**Warning signs:** Estimated `H` correlates with local point density or local sample count rather than
with the fixture's known curvature field.

### Pitfall 4: ReLU (or any activation with a zero second derivative) anywhere in the decoder used for curvature
**What goes wrong:** If stage 2's CAE arm somehow used, or was later extended to compare against, a
ReLU-activated decoder, its Hessian would be identically zero almost everywhere — silently zeroing the
entire second fundamental form rather than raising an error.
**Why it happens:** ReLU is piecewise-linear; its second derivative is a sum of Dirac deltas at the
kinks, numerically zero everywhere autodiff evaluates it.
**How to avoid:** Already enforced upstream — the sealed CAE fits (D-10 reuses them) were built with
SiLU specifically for this reason (CAE-06). Confirm this at load time (assert `model.activation !=
"relu"` before differentiating) rather than trusting the cache stem name.
**Warning signs:** `curvature_vector` evaluates to exactly `0.0` (not merely small) across most points.

### Pitfall 5: `torch.func` composition order for Hessians
**What goes wrong:** `jacrev(jacrev(f))` and `hessian(f)` (which is `jacfwd(jacrev(f))` under the
hood) are not drop-in interchangeable in every autodiff edge case, and getting the composition order
backwards silently returns a Jacobian-shaped, not Hessian-shaped, tensor for functions with unusual
input/output structure.
**Why it happens:** `torch.func`'s transform composition is powerful but the shape bookkeeping through
two nested transforms plus an outer `vmap` is easy to get wrong on the first attempt.
**How to avoid:** Test the composition on a function with a hand-known Hessian (e.g. a fixed quadratic
form) before trusting it on the actual chart decoder — this is exactly what Pattern 3's analytic
Gaussian-bump fixture is for.
**Warning signs:** `Hess.shape` does not match `(batch, out_dim, chart_dim, chart_dim)`.

### Pitfall 6: sklearn's `trustworthiness` sample-size guard, if reused for an auxiliary local check
**What goes wrong:** `sklearn.manifold.trustworthiness` raises when `n_neighbors >= n_samples / 2`.
**Why it happens:** Well-documented in `topoae.rank_structure`'s own docstring already in this
codebase — noted here only because a small-holdout stage-2 arm could hit this differently than
`topoae.py`'s `~2,000`-row holdout did.
**How to avoid:** Size any holdout/fixture set used with `trustworthiness` so the `k` sweep stays well
under `n_samples / 2`; let the exception surface rather than silently truncating `k`.
**Warning signs:** An unexplained `ValueError` from deep inside `sklearn.manifold`.

### Analytic mean curvature of the Swiss roll (self-derived, numerically verified)

```python
# Source: self-derived and numerically cross-checked this session against central
# finite differences of the exact parametric surface (max relative error ~1e-5
# across t in [1.5*pi, 4.5*pi]). Not found in the searched literature in this
# closed form -- sklearn's own docs give only the parametrization, not its
# curvature.
#
# sklearn.datasets.make_swiss_roll (hole=False) parametrizes the surface as
#   X(t, y) = (t*cos(t), y, t*sin(t)),  t in [1.5*pi, 4.5*pi],  y in [0, 21]
# This is a generalized cylinder (ruled surface, straight lines along y), so one
# principal curvature is exactly 0 and mean curvature is half the planar spiral's
# curvature kappa(t) = (t^2 + 2) / (1 + t^2)^{3/2}  [verified independently via
# the standard polar-curve curvature formula kappa = (r^2+2r'^2-r*r'')/(r^2+r'^2)^1.5
# with r(t)=t, r'=1, r''=0].
import numpy as np

def swiss_roll_analytic_H(t: np.ndarray) -> np.ndarray:
    """Mean curvature H(t) of the RAW (unscaled) sklearn Swiss roll surface."""
    return (t**2 + 2) / (2 * (1 + t**2) ** 1.5)

# CLAUDE.md's mandatory preprocessing -- centre and divide by ONE GLOBAL scalar
# std -- is an isotropic scaling X' = X / s with s = X_raw.std() (numpy .std()
# with no axis argument is a single scalar over all elements, matching CLAUDE.md's
# "one scalar, so the shape is preserved" instruction). Curvature has units of
# inverse length: under X' = X/s, distances shrink by 1/s, so curvature grows by
# s: H_scaled(t) = H_raw(t) * s. This factor must be applied before comparing
# H_est (computed in the scaled/preprocessed coordinates the estimator actually
# sees) against the analytic ground truth.
def swiss_roll_analytic_H_scaled(t: np.ndarray, global_std: float) -> np.ndarray:
    return swiss_roll_analytic_H(t) * global_std
```

### Permutation-null-calibrated Spearman threshold (D-01, D-02)

```python
# Source: scipy.stats.permutation_test, scipy 1.18.0 (already pinned) --
# docs.scipy.org/doc/scipy/tutorial/stats/hypothesis_spearmanr.html confirms
# permutation-based inference is the documented recommended approach for small
# samples / non-asymptotic settings, which a synthetic-fixture sweep at varying
# (d, D, n, k) genuinely is.
import numpy as np
from scipy.stats import spearmanr, permutation_test

def spearman_stat(x, y):
    return spearmanr(x, y).statistic

def calibrated_threshold(H_true: np.ndarray, H_est: np.ndarray, n_resamples: int, seed: int):
    """Returns (observed_rho, null_threshold). Pre-register n_resamples and the
    null quantile (e.g. 95th/99th percentile) BEFORE running on real fixtures."""
    rng = np.random.default_rng(seed)
    result = permutation_test(
        (H_true, H_est),
        spearman_stat,
        permutation_type="pairings",
        n_resamples=n_resamples,
        alternative="greater",
        rng=rng,
    )
    return result.statistic, result.null_distribution
```
