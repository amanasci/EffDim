<objective>
Build stage 2's Arm B: exact mean curvature through a CAE chart decoder via `torch.func`.

Purpose: D-09's whole case for the CAE rests on two properties a raw-point estimator does not
have — a model fitted to all 10,000 points averages noise away, and its chart decoder can be
differentiated *exactly* rather than estimated statistically. The counter-risk is equally
specific: a neural network's second derivative can wiggle where the true manifold does not, so a
smooth-looking reconstruction guarantees nothing about its Hessian. This plan builds the machinery
and verifies it against a decoder whose curvature is known in closed form, before it is pointed at
anything trained.

Output: `notebooks/pu_manifold/chart_curvature.py` (new, torch-importing, phase-scoped) and its
tests.
</objective>

Implement:

`assert_c2_activation(model)` — reads `model.activation` and raises `ValueError` naming the
activation string if it is in a module-level `ZERO_SECOND_DERIVATIVE_ACTIVATIONS` frozenset
containing at minimum `"relu"`, `"leaky_relu"`, `"elu"` is C1-but-not-C2 at 0 so include it,
and `"hardtanh"`. The error message must state why: a piecewise-linear activation's second
derivative is a sum of Dirac deltas at the kinks, numerically zero everywhere autodiff evaluates
it, so the entire second fundamental form would come back as exactly zero rather than raising.
RESEARCH.md Pitfall 4's stated mitigation is to confirm this at load time rather than trusting the
cache stem name — implement exactly that: check the attribute, not the filename. Raise rather than
warn; a warning in a batch runner is a silent failure.

`chart_decoder_map(model, chart_idx)` — returns a closure `decode_one(zc)` taking a single
`(chart_dim,)` tensor and returning a `(out_dim,)` tensor, computed as
`model.embedding_decoder(model.chart_decoders[chart_idx](zc.unsqueeze(0))).squeeze(0)`. The
docstring must record the deviation `02.5-PATTERNS.md` flags: `cae._decode_through_chart` takes
`z`, the *initial encoder's* output, and therefore differentiates through the chart-coordinate-
producing encoder as well. For curvature the chart coordinate **is** the local parameterization
whose second fundamental form is being measured, so only the decoder half is differentiated.
`cae._decode_through_chart` is read for its composition but is not itself wrapped under `jacrev`.

`chart_mean_curvature(model, z_chart, chart_idx)` — `z_chart` is `(batch, chart_dim)`, coordinates
**within one chart's own coordinate space**, not the initial-encoder embedding. Calls
`assert_c2_activation(model)` first. Then, following RESEARCH.md Pattern 4:
`J = vmap(jacrev(decode_one))(z_chart)` giving `(batch, out_dim, chart_dim)`;
`Hess = vmap(hessian(decode_one))(z_chart)` giving `(batch, out_dim, chart_dim, chart_dim)`;
`g = einsum("boi,boj->bij", J, J)`; `g_inv = torch.linalg.inv(g)`;
`proj = eye(out_dim) - einsum("boi,bij,bpj->bop", J, g_inv, J)`;
`II = einsum("bop,bpjk->bojk", proj, Hess)`; `H = einsum("bij,boij->bo", g_inv, II)`.
Immediately after each of `J` and `Hess`, assert the expected shape and raise `ValueError` naming
both the expected and actual shape — RESEARCH.md Pitfall 5 records that `torch.func`'s transform
composition through two nested transforms plus an outer `vmap` is easy to get wrong on the first
attempt and can silently return a Jacobian-shaped tensor. Also guard `g`'s conditioning: compute
`torch.linalg.cond(g)` and return it alongside, so a near-singular pullback metric at a
non-immersion point is visible rather than producing a large spurious curvature. Use
`torch.linalg.solve` against an identity batch in preference to `inv` if the conditioning check
shows it matters; state whichever is used and why. Run in float64 throughout — `cae.py`'s fits
persist as float64 arrays and second derivatives are the place where float32 noise shows.

`chart_mean_curvature_norm(H)` — `torch.linalg.norm(H, dim=-1)`. Docstring repeats the reason only
the vector norm is reportable: any reduction to a signed scalar along one chosen normal direction
is sign-ambiguous at high codimension, and `curvature.py`'s docstring and CURV-03 both mandate the
norm.

`chart_curvature_field(model, x, batch_size)` — the per-point field over an ambient point cloud:
encode to `z`, take `chart_coords(z)`, take `chart_probs(z).argmax(dim=1)` as the assigned chart,
then for each chart index call `chart_mean_curvature` on the rows assigned to it with that chart's
own coordinates, and reassemble in original row order. Returns a dict with `"H_vec"`, `"H_norm"`,
`"chart_assignment"`, `"metric_condition_number"`, and `"n_charts_used"`. Batch to keep peak
memory bounded — `hessian` over `out_dim = 768` and `chart_dim = 20` materializes
`batch * 768 * 20 * 20` floats, so state the chosen `batch_size` default and the resulting peak
allocation in the docstring.
