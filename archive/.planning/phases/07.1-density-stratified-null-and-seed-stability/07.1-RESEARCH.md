## Summary

This phase is entirely new-code-over-frozen-artifacts: no new packages, no network calls, no
retraining of the sealed decoder. The two deliverables split cleanly into two waves (D-12 forces
this): D7.1-01 builds and validates a within-density-stratum restricted permutation null for
`cross_split_curvature.partial_spearman`, then uses it to adjudicate the d=20/d=32 residuals;
D7.1-02 reuses the Phase 7 runner's exact fit path at three `TORCH_INIT_SEED` values and gates
each on D7.1-01's output.

The most consequential research finding this session is empirical, not documentary: **a
reproducible simulation (three seeds, a pure-null fixture with the same n=10,000 and the same
lognormal density skew Phase 7's own record shows) found that shrinking the stratum count from
S=500 down to S=10 does NOT narrow the null distribution's width — width is flat (std 0.0098-0.0117
across S=10..500) — but it DOES introduce a strong positive BIAS into the null mean (+0.033 at
S=10, decaying to +0.007-0.012 by S=100-500).** This contradicts CONTEXT.md D-02's stated
mechanism ("finer strata narrow the band, which is why finer = more sensitive"). It does not
contradict D-02's headline choice of S=20 (a middle value), but it means the artifact D-03's grid
exists to expose is better framed as a **bias/mean-shift artifact**, not a width artifact, and the
plan should report and inspect the null's mean (not only its band) at every `S` in the grid. This
is directly actionable: a coarse-S null that is biased toward positive values is *liberal* for
detecting the phase's negative-direction residuals (it makes a negative observed value look more
extreme relative to a positive-shifted null than it should), which is the opposite failure mode
from "coarse strata under-power the test" — see Common Pitfalls 1 for the full mechanism and the
concrete mitigation.

### Pattern 1: Restricted (within-stratum) permutation null

**What:** Permute `h` and `m` independently, but only within index sets defined by equal-count
quantile bins on `rankdata(density)` — never across strata. Recompute
`cross_split_curvature.partial_spearman(h_perm, m_perm, controls=density)` (the *original*,
unpermuted density) on each resample to build the null distribution.

**When to use:** Whenever a partial/residualized statistic needs a null that (a) preserves the
marginal relationship between the permuted variables and the covariate they're conditioned on,
and (b) does not require deriving the covariate's exact conditional distribution analytically.
This is the standard "restricted permutation" / "permute within blocks" technique used for nuisance
covariates in permutation ANOVA and ecological statistics (`vegan`'s `strata=` argument to
`adonis`/`mantel`, Anderson & ter Braak's blocked permutation framework) `[CITED: general
methodology, not this codebase — see Sources]`. Whether it is *exactly* correct depends on strata
being fine enough that within-stratum exchangeability approximately holds — see Common Pitfalls 1
for the measured failure mode when strata are too coarse.

**Verified equivariance the implementation should exploit:** `rankdata(x)[perm] == rankdata(x[perm])`
— confirmed directly this session (`np.allclose(...)` returned `True` on a 20-element test array).
Precompute `rankdata(h)`, `rankdata(m)`, `rankdata(density)` ONCE outside the resample loop; each
resample only needs to permute rank *values* within strata, never recompute a rank transform.

```python
# Source: derived this session from cross_split_curvature.partial_spearman's algebra
# (notebooks/pu_manifold/cross_split_curvature.py:232+) and D-05/D-06/D-08. Not yet in the
# codebase -- illustrates the precompute-ranks-once shape, verified for correctness and speed
# (n=10,000, S=20, 1000 resamples measured at ~1.5s) in this session's simulation.
import numpy as np
from scipy.stats import rankdata

def stratified_partial_null(h, m, density, n_strata, n_resamples, seed):
    n = h.shape[0]
    rh, rm, rd = rankdata(h), rankdata(m), rankdata(density)
    order = np.argsort(density)
    bin_size = n // n_strata
    strata = np.empty(n, dtype=int)
    for i in range(n_strata):
        lo = i * bin_size
        hi = (i + 1) * bin_size if i < n_strata - 1 else n
        strata[order[lo:hi]] = i
    strat_indices = [np.where(strata == s)[0] for s in range(n_strata)]

    design = np.column_stack([np.ones(n), rd])  # controls FIXED across all resamples

    def partial_from_ranks(rh_p, rm_p):
        def resid(v):
            coef, *_ = np.linalg.lstsq(design, v, rcond=None)
            return v - design @ coef
        ex, ey = resid(rh_p), resid(rm_p)
        return float(np.corrcoef(ex, ey)[0, 1])

    rng = np.random.default_rng(seed)
    null_vals = np.empty(n_resamples)
    for b in range(n_resamples):
        rh_p, rm_p = rh.copy(), rm.copy()
        for idx in strat_indices:
            rh_p[idx] = rh[rng.permutation(idx)]
            rm_p[idx] = rm[rng.permutation(idx)]
        null_vals[b] = partial_from_ranks(rh_p, rm_p)
    return null_vals
```

Report BOTH `null_vals.mean()` and the two-tailed quantile band — the mean is where the D-03
artifact actually shows up (see Common Pitfalls 1), not the band width alone.

### Anti-Patterns to Avoid

- **Reusing `curvature_probe.permutation_null` or `two_tailed_permutation_null` for the stratified
  case by passing pre-shuffled arrays in:** these delegate to `scipy.stats.permutation_test`,
  which manages its own internal resampling — you cannot inject a stratum-restricted resample
  into it from outside without reimplementing the resampling anyway. D-06 already rules this out;
  confirmed here by reading `permutation_null`'s scipy call site directly.
- **Judging stratum-count sensitivity by band width alone:** this session's simulation shows band
  width is roughly flat across `S=10..500` on a lognormal-density fixture matching PU's own
  measured spread; the artifact D-03 exists to expose shows up as a null-mean shift, not a
  band-width change. A plan that only reports `[null_low, null_high]` per `S` will not surface it.
- **Trusting `density_diagnostics` as evidence the sealed record's density partials were
  guard-checked:** the sealed runner (`run_dsweep`) never calls this function — it inlines an

## Common Pitfalls

### Pitfall 1: Coarse stratification biases the null's mean, not (only) its width

**What goes wrong:** A plan that treats `S` purely as a "how tight is the band" knob, per
CONTEXT.md D-02's stated mechanism, may under-report what actually moves when `S` changes.

**Why it happens:** Verified this session with a reproducible simulation (3 seeds, n=10,000,
lognormal density with the same order-of-magnitude spread the frozen record shows, `h`/`m`
constructed to be conditionally independent given density — i.e. a TRUE null): the null
distribution's standard deviation was flat across `S ∈ {10, 20, 50, 100, 500}` (0.0098-0.0117,
no monotonic trend), but its MEAN was strongly positive at `S=10` (+0.0334 to +0.0342 across the
three seeds) and decayed toward +0.007-0.012 by `S=100-500`. Mechanism: within-stratum
permutation only removes the *linear rank* relationship between `h`/`m` and density that the
global `partial_spearman` regression already subtracted; if a stratum is wide, points within it
still span a meaningful density range, and the residual monotonic-but-nonlinear (or simply
locally-linear-with-different-slope) confound is NOT removed by permuting within that wide bin —
it leaks into the null as a same-signed bias, because both `h` and `m` increase with density in
the same local region.

**How to avoid:** Report `null_vals.mean()` (not just the band) at every `S` in the D-03 grid.
Treat a residual whose *clearance status* changes between `S=10` and `S=50` as ambiguous
regardless of whether the band widened or narrowed — check whether the change tracks the null's
mean shift (bias artifact, this pitfall) or its width (the mechanism D-02 describes). Since the
phase's residuals of interest are NEGATIVE (-0.024, -0.022, -0.066), a positive-biased null at
small `S` makes the negative tail's threshold sit CLOSER to zero than it should, which is a
liberal (false-positive-prone) failure mode for exactly the direction this phase cares about —
worth stating explicitly in FINDINGS if the real PU data shows the same pattern this synthetic
fixture does.

**Warning signs:** A residual's `clears_either` flips between `S=10` and `S=50` in the DIRECTION
consistent with "coarse S is more permissive on the negative tail" (i.e., clears at S=10 but not
at S=50) — that is the signature this pitfall predicts, and is distinguishable from the
"clears at S=50 but not S=10" pattern CONTEXT.md's D-03 prose describes. Both are worth naming
explicitly, but they point to different mechanisms and different mitigations.

## Open Questions (RESOLVED)

Both questions were resolved at plan time (2026-08-26); each is answered
operationally by a task in the 07.1 plan set. Neither remains open at execution.

1. **Does the real PU data show the same null-mean-vs-S bias this session's synthetic fixture showed?**
   - What we know: the mechanism (linear-rank residualization leaving nonlinear residual confound inside wide strata) is general; the magnitude is fixture-specific.
   - What's unclear: whether PU's own d=20/d=25/d=32 fields and its measured 7.8-order density
     spread produce a smaller or larger bias than this session's sigma=3 lognormal fixture.
   - Recommendation: have the plan's first D7.1-01 task print `null_vals.mean()` alongside the
     band at each `S` in `{10, 20, 50}` on the REAL data, before any clearance verdict is drawn —
     this is nearly free (already computed) and directly informs whether Pitfall 1 is a real
     concern here or a synthetic-fixture artifact.
   - **RESOLVED (plan time):** adopted. `07.1-04` Task 2 makes the null-mean-vs-`S`
     diagnostic mandatory on the REAL data at `S in {10, 20, 50}`, printed BEFORE any
     clearance verdict is drawn, and `07.1-06` FINDINGS Sec 3 must state plainly whether the
     measurement contradicts D-02's stated mechanism. The question is answered by measurement
     during execution rather than assumed either way at plan time.

2. **Should the D-04 positive-control planting mechanism plant on raw `rankdata(h_real)` (current, minimal-change choice) or on the RESIDUAL rank of `h_real` after removing density?**
   - What we know: both are defensible; the minimal-change choice (plant on raw rank, evaluate
     achieved value via the partial statistic) is self-consistent because bisection always
     converges on whatever metric is measured.
   - What's unclear: whether planting on raw rank vs. residualized rank changes the *achievable
     range* of `partial_rho_density_controlled` at a fixed `slope`, which could matter for how
     many bisection iterations are needed or whether the bracket `[0.0, 2.0]` still contains the
     needed slope.
   - Recommendation: keep the minimal-change mechanism (matches D-04's "extend the bisection"
     framing most literally); if the bisection fails to bracket a target within `[0.0, 2.0]`,
     that itself is a reportable finding (mirrors `plant_positive_control`'s own "the achieved
     rho is recorded, never silently substituted" discipline), not a reason to silently widen the
     bracket.
   - **RESOLVED (plan time):** recommendation accepted. `07.1-04` Task 1 explicitly adopts
     the minimal-change mechanism — plant on raw `rankdata(h_real)`, evaluate the achieved
     value via the partial statistic — and treats a bisection that fails to bracket a target
     within `[0.0, 2.0]` as a reportable finding, never a reason to silently widen the bracket.
