# Phase 02.7 Screening Rule — Amendment 1

**Ratified 2026-08-12, at plan `02.7-09`'s Task 2 blocking `checkpoint:human-verify`, resolved
by the user after reading the committed Swiss roll notebook's Section 5 finding.**

This document is an **amendment**: it changes a rule. `02.7-SCREENING-RULE.md`'s own §13
ancestry-proof discipline (following `02.6-SCREENING-RULE-02.md`'s precedent) means a ratified
constant is not silently edited — a changed rule requires a fresh, separately-ratified
amendment document, committed alone with its own ancestry proof. That is what this is.

`7aa699de94206efe141288b2480eb1d42c045029` remains in the record, unmodified and unsuperseded.
`02.7-SCREENING-RULE.md` itself is **not edited** by this amendment.

**Unlike `02.5-PREREGISTRATION-AMENDMENT-01.md`'s precedent, this amendment requires no
re-run.** That amendment landed after a sealed sweep had already scored cells under the rule it
amended. Here, **no benchmark cloud has been scored under `02.7-SCREENING-RULE.md`, before or
after this amendment** — `02.7-09`'s Swiss roll check is a sanity notebook, explicitly outside
SC-1's own gate (`grep -cE "template_decision" notebooks/diagnostics/template_benchmark_run.py`
returns nothing because that runner does not exist yet). This amendment lands before the
benchmark grid, exactly as the original rule did.

## 1. The trigger, stated plainly, not softened

**This amendment was written after seeing an unfavourable result, and that is stated here
rather than buried.** Plan `02.7-09`'s Swiss roll notebook (`notebooks/02.7_swiss_roll_template_check.ipynb`,
commit `5d3550d`) ran the unchanged front end on the roll plus D-16's in-library `S1`/`T2`
positive controls, at `n_ph=150` (a stated reduction from the ratified 300 — see §7). All three
clouds **abstained**:

| cloud | `d_hat` | abstain condition | detail |
|---|---|---|---|
| roll | `2` | **(b)** | local dispersion range `22.201` > `dispersion_bound=3.0` |
| S1 control | `1` | **(b)** | local dispersion range `3.587` > `dispersion_bound=3.0` |
| T2 control | `None` | **(d)** | no `d_hat` consensus (vote split `{2.0: 3, 3.0: 2, 1.0: 1, 0.0: 1}`) |

Section 5 of the notebook broke condition (b)'s dispersion down per estimator and found one
estimator — `gmst` — driving it in every case, by a wide margin over the next-widest estimator:

| cloud | `gmst` range | next-widest (`two_nn`) | ratio |
|---|---|---|---|
| roll | `22.201` (min `-16.379`, max `5.822`) | `2.397` | `9.3x` |
| S1 | `3.587` (min `1.057`, max `4.644`) | `1.394` | `2.6x` |
| T2 | `26.521` (min `-5.605`, max `20.916`) | `1.892` | `14.0x` |

Every other estimator's range stayed under `2.4` at every cloud. `gmst`'s own per-anchor local
values ranged from **`-16.379` to `20.916`** across the three clouds — negative values are not
dimensions, and no other estimator in this module ever returns one.

## 2. Why this is defensible anyway: the criterion is structural, not post-hoc

The amendment does not invent a rule to explain away this result. **The exclusion criterion it
applies was already written down, before any cloud in this phase was scored**, in
`local_dimension.py`'s own module docstring (present unchanged since plan `02.7-03`, months
before plan `02.7-09` ran):

> **"GMST's separate call path (D-12)."** `gmst_dimensionality` accepts neither
> `precomputed_knn_dist_sq` nor `k` — it cannot be sliced onto the shared precomputed array like
> the other seven. `local_estimates` calls it directly on each anchor's raw local-subset
> coordinates (`provenance="recomputed"`) rather than slicing a precomputed array
> (`provenance="sliced"` for the other seven) — its local value is therefore NOT bit-identical
> in provenance to its own global call, because it rebuilds its own internal kNN structure on
> the smaller subset. This asymmetry is recorded in the data, not smoothed over.

Verified directly against `src/effdim/geometry.py:396-400` (unchanged, frozen): `gmst_dimensionality`'s
signature has no `precomputed_knn_dist_sq` and no `k` parameter at all — the only one of the
eight estimators for which this is true. `local_estimates` already tags every per-anchor,
per-estimator cell with a `"provenance"` field (`"sliced"` or `"recomputed"`), and that tag was
already correct and already tested (`test_local_estimates_smoke_one_anchor_all_eight_present`,
plan `02.7-03`) before this amendment existed.

**The rule this amendment states is: exclude, from D-12's local-dispersion vote only, any
estimator whose local call is not provenance-identical to its global call.** This is phrased as
a general, structural predicate over the `"provenance"` tag `local_estimates` already produces
— never as "exclude gmst" by name. `gmst` is the only member of `ESTIMATOR_NAMES` that
currently satisfies the predicate (every anchor's `"provenance"` for `gmst` reads
`"recomputed"`, never `"sliced"`), and that is a **consequence** of applying the general rule to
this module's current eight estimators, not the rule itself. If a ninth estimator were ever
added to `ESTIMATOR_NAMES` with the same structural limitation, the same predicate would exclude
it too, automatically, without a further amendment.

**Why this distinction matters, stated plainly**: a rule that said "exclude gmst" would be
indistinguishable, to any later reader, from a rule invented to make an unfavourable number go
away. A rule that excludes on the basis of a structural fact recorded before the measurement —
verifiable independently of what any cloud's dispersion happened to be — is not. This project's
own record already contains one criterion changed after an unfavourable result without that
distinction (`02.6-FINDINGS.md` §4) and D-01 is rated one-way partly because of it; this
amendment is written to not repeat that pattern in D-12.

## 3. What this amendment changes — exactly one thing

**D-12's local-dispersion gate, and only the gate.** The dispersion dict fed to
`template_decision.decide`'s abstain condition (b) check (`max(entry["range"] for entry in
local_dispersion.values())` against `bounds["dispersion_bound"]`) must be restricted to the
provenance-matched subset of `ESTIMATOR_NAMES` — currently `{mle, two_nn, danco, mind_mli,
mind_mlk, ess, tle}`, i.e. all eight minus `gmst`.

This is implemented as a **new** function, `local_dimension.gating_dispersion`, added in a
separate commit after this amendment (§8) — it does not modify `local_dimension.dispersion`,
whose existing contract (all eight estimators, no aggregation, pinned by
`test_dispersion_per_estimator_no_aggregate_across_estimators`) is unchanged. `dispersion`
remains the full per-estimator report D-09's "spread reported, no aggregation" discipline
requires; `gating_dispersion` is the caller-facing function that assembles
`dimension_readout["local_dispersion"]` for `decide()`. **`template_decision.decide` itself
requires no code change** — it already takes `max(...)` over whatever dict its caller supplies;
this amendment changes what a caller supplies, not how `decide` consumes it.

## 5. What this amendment does NOT rescue

**The roll's own `beta_0` never matching the `ball` row's `beta_0=1` is a separate finding, and
this amendment does not address it.** Section 5's bypass diagnostic (bypassing `decide`'s
abstain-condition precedence entirely) called `template_decision.lookup` directly on the roll's
own measured Betti vectors — `lookup((26,1,0), d_hat=2) -> None` and `lookup((29,1,1), d_hat=2)
-> None` on the Euclidean and geodesic arms respectively. Neither matches any `TEMPLATE_TABLE`
row, because every row requires `beta_0=1` and the roll measured `beta_0 in {26, 29}`. Excluding
`gmst` from the dispersion gate does not change this: had condition (b) not fired first, the
roll's own Betti vector would still fail the lookup and abstain condition (a) (off-library)
would fire instead of a `ball` label.

This inflated `beta_0` is **consistent with, and does not newly discover**,
`02.7-SCREENING-RULE.md` §11's already-named residual risk: "non-uniform sampling density...
can produce moderately-isolated points whose H0 merge-life exceeds a small-`B` bootstrap band
for reasons unrelated to genuine multi-component structure," stated there as unresolved and
carried forward, not fixed by that document. This amendment carries it forward again, unresolved,
rather than folding it into the D-12 fix it is not.

## 6. What SC-5's live prediction did and did not demonstrate

`02.6-CONTEXT.md` D-02's prediction — that the roll's *ambient* `beta_1=1` from near-touching
spiral arms makes the Euclidean arm see a spurious cycle a geodesic arm should not — **was never
tested through `decide()`'s own decision path**, because abstain condition (b) fires before
condition (c) in D-03's fixed precedence order (d, then b, then c, then a), and (b) fired first
on every run measured. This is a **gap in what SC-5 demonstrated, not a pass on it.**

What *is* known, from the notebook's own raw output rather than from `decide()`'s reported
reason: the roll's two arms' Betti vectors **did disagree** — `euclidean=(26,1,0)` vs
`geodesic=(29,1,1)` — differing in both `beta_0` (`26` vs `29`) and `beta_2` (`0` vs `1`). This
is consistent with, but does not confirm, the D-02 prediction specifically: the disagreement
could as easily be explained by the same H0 inflation named in §5 above as by a genuine
Euclidean-only spurious `beta_1` cycle — the two arms in fact agreed on `beta_1=1` at this
measurement, which is not what D-02 predicted. **This amendment does not resolve whether
condition (c) would fire on the roll under the amended gate; that remains to be observed once
`gating_dispersion` is wired into a caller and the notebook (or a future run) is re-executed
under it.** Stated here as an open question, not answered by assertion.

`H_2` bootstrap band as multi-minute per (cloud, metric) cell, incompatible with CLAUDE.md's
under-two-minutes sanity-notebook target). **The `gmst` local-dispersion finding this amendment
responds to was verified, before this amendment was committed, to reproduce unchanged at
`n_ph=150`, `n_ph=200`, and `n_ph=300`** (dispersion-only re-measurement, without the expensive
persistence/bootstrap steps, at all three sample sizes):

| `n_ph` | roll `gmst` range | S1 `gmst` range | T2 `gmst` range |
|---|---|---|---|

The instability is not an artifact of the sanity notebook's own `n_ph` reduction; it reproduces

## 8. Implementation constraint this amendment imposes

Following `02.7-SCREENING-RULE.md`'s own §1 precedent (a computation any part of a gate depends
on must be a tested module function, not runner-inline logic), `local_dimension.py` gains a new
function, `gating_dispersion(local_by_anchor) -> Dict[str, Dict[str, float]]`, in a **separate
commit from this amendment, landing after it**:

- Computes the provenance-matched estimator set **dynamically** from `local_by_anchor`'s own
  `"provenance"` tags (never a hardcoded name list) — an estimator is included iff every anchor's
  `"provenance"` for that estimator reads `"sliced"`.
- Returns the restriction of `dispersion(local_by_anchor)` to that set; raises `ValueError` if
  the matched set is empty.
- `dispersion` itself is unchanged — still all eight estimators, still no aggregation.
- `template_decision.decide` requires no code change (§3).

Its tests must pin, at minimum: that the matched set excludes exactly `{"gmst"}` on the module's
existing fixtures (a consequence, asserted, not hardcoded into the test's own selection logic);
that `gating_dispersion`'s returned values are identical to the corresponding entries in
`dispersion`'s full output; and that a hand-constructed `local_by_anchor` with no
provenance-matched estimator raises `ValueError`.

## 9. Consequence of changing this rule

Same as `02.7-SCREENING-RULE.md`'s own §13 discipline, applied to this document: once this
amendment is committed with ancestry proof, the D-12 gating-exclusion criterion, and every
constant listed unchanged in §4, may not move again without a further separately-ratified
amendment, committed alone with its own ancestry proof. Not a silent edit.
