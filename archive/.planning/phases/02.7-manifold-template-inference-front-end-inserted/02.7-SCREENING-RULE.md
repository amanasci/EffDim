# Phase 02.7 Screening Rule — the template decision (SC-1)

This document is the ratified decision rule SC-1 requires be committed **before any synthetic
benchmark cloud is scored**, following `02.6-SCREENING-RULE-02.md`'s precedent exactly: one
commit, touching no other file, its SHA recorded in `02.7-08-SUMMARY.md` and re-checked at phase
close (`02.7-12`) via `git merge-base --is-ancestor`.

**What this document does not do.** It selects **no template for PU** — SC-6's read-only probe
is a later plan, not this one. It **promotes nothing** and makes **no curvature claim** — this
whole phase trains no VAE and restricts no auto-encoder (per the phase's own scope fence). It
does not report a single accuracy number for any real cloud, because no cloud has been scored
yet: `grep -cE "template_decision" notebooks/diagnostics/ph_budget_calibration_run.py` returns
`0`, and no other runner under this phase has imported the decision layer before this commit.

**Why blind, why alone.** `02.6-FINDINGS.md` §4 records a criterion changed after an
unfavourable result, and D-01 is rated **one-way** precisely because the record cannot absorb a
second. A constant chosen after seeing a result is indistinguishable, to any later reader, from a
constant chosen *because* of it. Every constant below was fixed with zero synthetic-benchmark
numbers in existence — `02.7-BUDGET-CALIBRATION.md`, the only measured input this document reads,
is a compute-feasibility record: it scores no cell, computes no tally, and sets no decision
threshold (its own §1). Everything that is not calibration-grounded is marked as such, explicitly,
below — a later reader must be able to tell at a glance which numbers rest on measurement and
which rest on judgment.

**Checkpoint resolution (2026-08-12).** All constants below were ratified at this plan's Task 1
blocking `checkpoint:decision`. The compute-budget Option A, the consensus-rule parameters, the
two `bounds` values, and the noise-level grid were each presented with named alternatives and
their costs; the human selected explicitly, recorded per group below.

## 1. The mechanism (D-01, D-04)

The template call is a **Betti-vector lookup table**, keyed jointly on `(Betti vector, d_hat)` —
never diagram distance to a reference cloud, never a hybrid. Ratified exactly as written at plan
`02.7-01`'s own blocking checkpoint (`02.7-01-SUMMARY.md`: "Task 1 checkpoint: ratify-as-written
selected... No amendment"), and unchanged since. `TEMPLATE_TABLE`
(`notebooks/pu_manifold/template_decision.py`), verbatim:

| Template | Betti vector `(beta_0, beta_1, beta_2)` | `d` |
|---|---|---|
| `S1` | `(1, 1, 0)` (written `(1, 1)` in D-04, zero-padded here to D-11's 3-entry ceiling) | 1 |
| `S2` | `(1, 0, 1)` | 2 |
| `T2` | `(1, 2, 1)` | 2 |
| `ball` | `(1, 0, 0)` | any (`d_hat` carried into the label as `ball_d{d_hat}`) |

No diagram distance and no reference cloud is used anywhere in this phase — `template_decision.py`
imports neither `ripser` nor `persim`, verified by direct source read. **D-01 is rated one-way**:
`02.6-FINDINGS.md` §4 already records one criterion changed after an unfavourable result; a second
change to this phase's own decision mechanism would be the pattern repeating, and the record
cannot absorb it.

## 2. Significance (D-02)

A bar is significant iff it clears a **bootstrap-derived confidence band**, computed per cloud,
per metric, per degree (Fasy, Lecci, Rinaldo, Chazal, Singh, Wasserman, "Confidence sets for
persistence diagrams," Ann. Statist. 42(6):2301-2339 (2014)) — resample-with-replacement, `B`
replicates, bottleneck distance to the original diagram, `(1-alpha)` quantile as `c_alpha`,
`band = 2 * c_alpha`.

**Ratified: `B = 10`, `alpha = 0.05`.**

`B = 10` is a **stated reduction from Fasy et al.'s own documented default of `B = 30`** (cross-
checked against the R `TDA::bootstrapDiagram` package's documented defaults, `02.7-RESEARCH.md`
Q2), taken explicitly because of the measured `H_2` cost wall: `02.7-BUDGET-CALIBRATION.md` §3
measures `S2`'s own euclidean `H_2` band cost at `13.442s/call`, extrapolated linearly to
`147.86s` for the full `B=10` sequence (11 calls) — at `B=30` this would be roughly `3x` larger
again, which the calibration's own §6 options table shows is not affordable at this phase's grid
size. `alpha = 0.05` is the standard 95%-band convention, unchanged from RESEARCH's own citation
and not itself a compute-driven choice.

## 3. The abstain disjunction (D-03)

Four named conditions, evaluated in `template_decision.decide` in this fixed precedence order —
**(d) then (b) then (c) then (a)** — because the conditions most predictive of an unreliable
measurement are checked before a confident label is ever offered (verified against source,
`template_decision.py`):

| Condition | Fires when | Downstream instruction |
|---|---|---|
| **(d) measurement untrustworthy** | No `d_hat` plateau/consensus reached (§5 below fails to resolve); OR the global 7-distinct-estimator spread range exceeds `bounds["spread_bound"]`; OR the agreed Betti vector contradicts `d_hat` (matches a non-ball table row's betti pattern at a *different* `d` — D-04's stated reason for the joint key, e.g. `beta_2=1` at `d_hat=1` matches `S2`'s betti but not `S2`'s `d=2`) | Retry with more data or a better-conditioned measurement — the dimension estimate itself is not trustworthy |
| **(b) no global template applies** | More than one component survives the geodesic `k` range (`connectivity_readout["n_components"] > 1`); OR local `d_hat` dispersion exceeds `bounds["dispersion_bound"]` | Terminate the follow-on topological-VAE arm — no single global template fits |
| **(c) metric disagreement** | Euclidean and geodesic arms report different Betti vectors for the same cloud | Retry with more data or reconsider which metric is trustworthy |
| **(a) off-library** | Both arms agree and the shared Betti vector matches no `TEMPLATE_TABLE` row at the measured `d_hat` | Widen the template library (out of scope for this phase) |

`beta_0 = 1` with no persistent `beta_1` and a clean `d_hat` plateau is **not** an abstention — it
matches the `ball` row and is a positive call of the trivial template, the likely PU answer per
the ROADMAP prior. `template_decision.py`'s own `test_ball_row_is_a_positive_call_not_an_abstention`
pins this path as reachable only as a success.

## 4. The dimension protocol (D-09, D-10, D-12)

**Ratified: `k_values = [5, 10, 15, 20, 30]`, `min_run = 3`, `tolerance = 0.5`,
`count_distinct = True`, `majority = 5`.**

`k = 15` appears here only as one interior sweep point. **It is not inherited as *the* value.**
Phase 1's frozen `k* = 15` was frozen for `n = 10,000` PU points at `D = 768`; this phase's
benchmark varies `n`, `D` and density by design, so a fixed `k` would mean a different effective
neighbourhood radius in every grid cell — D-06's explicit bar. `min_run = 3` requires a stable
value over a majority of the five swept points, contiguous.

**Every one of the eight frozen estimators is run** (`mle`, `two_nn`, `danco`, `mind_mli`,
`mind_mlk`, `ess`, `tle`, `gmst`) — D-09, no aggregation, spread reported. `d_hat` is resolved
only by `plateau_consensus`'s ratified majority; **no consensus emits `d_hat = None` and abstain
(d) fires — never a fallback median.** `d_frozen = 5` is not inherited; this phase reports its own
`d_hat` against that record.

**Two verified structural facts, and the consensus rule written against them explicitly rather
than against a naive majority of eight** (both pinned as regression tests in
`notebooks/pu_manifold/tests/test_local_dimension.py`, `02.7-03-SUMMARY.md`):

1. **`tle_dimensionality` is algebraically identical to `mle_dimensionality`** — the same
   expression (`(k-1) / (sum of log-ratios + 1e-10)`), the same epsilon, the same `np.mean`
   reduction, reading the same `precomputed_knn_dist_sq` array. **This is not stated as
   "bit-identical" here, unqualified, because it is not universally true at the bit level**:
   measured this session at a 20-seed scan, `mle == tle` exactly at **15 of 20 seeds**, differing
   by **1-2 float32 ULPs** at the other 5 (`geometry.compute_knn_distances` casts through FAISS's
   float32 path, and `log(a) - log(b)` is not bit-identical to `-log(b/a)` in floating point in
   general, even though the two are the same value mathematically). The consequence for this
   phase is unaffected by which seed lands where: `tle` and `mle` are the same estimator under two
   names, so without correction one vote is doubled in any majority over the eight. `count_distinct
   = True` collapses `DUPLICATE_ESTIMATOR_PAIRS = (("mle", "tle"),)` to one vote when both members
   support the identical binned integer.
2. **`two_nn_dimensionality`, `mind_mli_dimensionality` and `gmst_dimensionality` cannot vary with
   `k`** — `two_nn` reads only columns 0-1 of the precomputed array, `mind_mli` reads only column
   0, `gmst` takes no `k` argument at all (accepts neither `precomputed_knn_dist_sq` nor `k`).
   Measured this session: `two_nn` and `mind_mli` held exactly constant across `k in {5,10,20,30}`
   while `mle` moved across every value on the same fixture. **Two of eight estimators therefore
   register a *vacuous* perfect plateau at every `k` for reasons unrelated to the data** — a
   `K_INVARIANT_ESTIMATORS` majority carried substantially by these three would be the same
   species of defect that made `d_frozen = 5` suspect (Phase 02's `02-FINDINGS.md` §6.4: a median
   across a 5/5/5/20/20/22/24/25 split reporting a plateau no estimator individually supports).
   `count_distinct = True` exempts `K_INVARIANT_ESTIMATORS = ("two_nn", "mind_mli", "gmst")` from
   the `min_run` run-length requirement (their "run" spans the whole sweep vacuously by
   construction, not because the data stabilised) — it does **not** exclude them from voting, it
   only removes the (meaningless, for them) run-length gate.

With `count_distinct = True`, the effective vote pool after collapsing `(mle, tle)` is **7
distinct estimators**. **`majority = 5` of 7** was chosen as a comfortable majority (more than
70%) rather than a bare 4/7 knife-edge, since D-10's entire purpose is to never report a number
the estimators do not clearly agree on.

**D-06's geodesic component-count stability** reuses the identical `k_values`/`min_run` — one
shared `k`-sweep-and-stability discipline across both the persistent-homology-connectivity read-out
(D-06) and the dimension consensus (D-10), per CONTEXT.md's own stated intent ("mirrors SC-2's
plateau discipline rather than inventing a second convention") — not two independently invented
conventions.

**D-12's local dispersion probe**, feeding abstain (b): `neighbourhood_size = 30`,
`anchor_indices` drawn as **40 anchors** per cloud (matching `02.7-03`'s own precedent test,
`test_local_matches_global_on_uniform_fixture`, which used 40 anchors). `neighbourhood_size = 30`
sits comfortably above `gmst_dimensionality`'s own 10-point floor and is a genuinely "local"
patch relative to `n_ph = 300` (10% of the cloud). **Neither number is calibration-grounded** —
no measurement bears on the right local-patch size for this phase's specific templates; both are
judgment calls, informed only by the prior plan's own worked example.

## 5. The bounds — `dispersion_bound`, `spread_bound` (D-03(b), D-03(d))

**Ratified: `dispersion_bound = 3.0`, `spread_bound = 3.0`.**

This is exactly `template_decision._REQUIRED_BOUNDS = ("dispersion_bound", "spread_bound")` — no
gaps, no extras, verified directly against `template_decision.py`'s source and cross-checked
against `02.7-06-SUMMARY.md`'s own stated required set (see §9 below for the explicit
side-by-side comparison).

**These two numbers are judgment calls with no calibration behind them, unlike every other
constant in this document.** `02.7-BUDGET-CALIBRATION.md` measures wall-clock and memory cost —
it does not, and structurally cannot, measure typical estimator-spread or local-dispersion
magnitudes on this phase's own templates, because doing so would require scoring a benchmark
cloud through the decision layer, which is exactly the ratify-blind ordering this document exists
to enforce. `3.0` (three integer-widths, in the same units `local_dimension.spread`/`dispersion`
report — the `"range"` key, `max - min` over the relevant set) was chosen as wide enough not to
fire on a well-conditioned in-library cloud and tight enough to still be capable of firing; no
stronger justification than that judgment exists at ratification time. **A later reader comparing
this section to §2/§4 above should see the difference plainly**: `B`, `alpha`, `n_ph` and the
compute-budget figures in §7 are calibration-grounded (traceable to a specific
`02.7-BUDGET-CALIBRATION.md` measurement); `dispersion_bound` and `spread_bound` are not.

## 6. The homology ceiling (D-11) and its amendment

**The homology degree ceiling is capped at `H_2`** — the `ripser`/`persim` library maximum this
phase's four-template library needs, not `H_dhat`. **This amends SC-3's literal text**
(`.planning/ROADMAP.md`, SC-3: "Degrees `H_0` through `H_dhat`") — stated here explicitly, not
silently applied. `{S1, S2, T2, ball}` is fully separated by `H_0, H_1, H_2`; a literal
`H_dhat` reading at the PU prior's `d_hat ~ 18-25` would be combinatorially hopeless for `ripser`
and would produce no answer for the one cloud this phase exists to probe.

**Consequence, carried as assumption A-01, stated at its correct bound.** Abstain condition (a)
can **never** fire on high-degree homology. A cloud with non-trivial `beta_3` or above reads as
`(1, 0, 0)` and is called a ball. This phase's claim is therefore bounded to **"off-library as
detectable through `H_0..H_2`"** — never "off-library, full stop," and never described as having
ruled out higher-degree structure.

## 7. The metric arms (D-05..D-08)

**Graph geodesic** (D-05): symmetric kNN graph, edges weighted by ambient Euclidean length,
symmetrized via `graph.maximum(graph.T)` (never the additive `graph + graph.T`, the verified,
measured bug in frozen `geometry.gmst_dimensionality`'s own route — `02.7-01`'s
`test_maximum_symmetrization_not_sum` pins the fix). All-pairs shortest path via
`scipy.sparse.csgraph.shortest_path`. Not diffusion distance, not Euclidean-in-a-spectral-
embedding.

**D-06's `k` sweep**: `k_values = [5, 10, 15, 20, 30]`, `min_run = 3` — identical to §4's
dimension-protocol sweep (one shared convention, not two).

**D-07's no-bridging rule**: component count at each `k` is a first-class read-out, never
repaired. Geodesic PH runs on the **largest connected component only**, with the dropped-point
fraction reported alongside; more than one surviving component fires abstain (b). **No
minimum-spanning-tree bridging, ever** — verified absent from `geodesic_graph.py` by negative
grep at plan `02.7-02`'s own acceptance criteria. **Rated costly to reverse**: this choice is
baked into what abstain (b) means and into every abstention rate this phase reports; changing it
after measurement would invalidate every measured rate, the same one-way logic as D-01.

**D-08's fixed point budget**: **`n_ph = 300`**, pinned **identically** across the Euclidean arm,
the geodesic arm, and every benchmark grid cell — the fair-comparison discipline carried forward
from `02.6-FINDINGS-02.md`'s own "assert the comparison is fair" rule, asserted in code (every
call site reads the same `n_ph` module constant) rather than left as a comment. **`draws = 3`
independent immersion draws per grid cell** — RESEARCH.md's own recommendation, preserved under
the ratified Option A budget (§8), reporting Betti-vector spread across draws (feeding assumption
A-04, PH seed/draw variance, still unmeasured in this project before this phase runs it).

**The immersion (D-14).** `warp_params = {"strength": 0.05, "freq": 1.0}` — the exact pair
`02.7-05-SUMMARY.md` measured all four templates (`S1`, `S2`, `T2`, `ball`) pass the Jacobian
rank check at, at `D = 768` (`min_rank == expected_rank` at `rank_tol = 1e-6`, wide margin, no
per-point entry observed near the boundary). **`jacobian_rank(n_check=30, rank_tol=1e-6)`** —
`n_check` and `rank_tol` are required arguments with no module default (verified,
`template_immersion.py`); `rank_tol = 1e-6` is `02.7-05`'s own measured value, flagged there as
"a starting point with wide headroom, not a tightly-calibrated bound" since no joint sweep of
`strength`/`freq`/`rank_tol` was performed — carried forward here as the best available evidence,
not re-derived. **`BALL_D = 18`** — carried forward directly from `02.7-BUDGET-CALIBRATION.md`'s
own proxy value (chosen there to sit in this project's own ~18-25 PU `d_hat` estimate range), so
the calibration's own `ball`-cost finding (§8 below) transfers directly to the actual grid rather
than needing re-measurement at a different dimension. This value is **not independently
calibration-grounded for correctness** (no accuracy number exists yet for any `ball` dimension) —
it is carried forward for **cost-transfer** reasons, stated explicitly.

**Full factorial on `(D, noise)`, 3 levels each, `D = 768` a required level:**

## 9. The compute budget, stated (never silent)

**Ratified: Option A** — `n_ph = 300`, `B = 10`, **3 draws**, the 60-combination grid above,
projected **~17.05h** (worst *measured* template, `S2`; `ball`'s true cost is unmeasured — see the

plan's checkpoint over three named alternatives:

  Betti-spread read-out, it **eliminates it entirely**: the whole instrument that would measure
  assumption A-04's unmeasured PH seed/draw variance disappears, not just its resolution. A-04 is

**~17.05h is roughly 2x RESEARCH.md's own original ~8.25h worked estimate** (Open Question 2),
now that real, degree-specific `D=768` per-call cost (§2c of the calibration: `D=768` costs
30-90% more than the flat `D=3` numbers RESEARCH's blended estimate extrapolated from) and all

explicitly, never a silent reduction.** This project has precedent for unattended multi-hour runs

different order of magnitude.

**The ratified `ball`-timeout fallback**, itself part of the ratified rule rather than a reaction

## 10. Two calibration gaps, carried forward NAMED — not resolved

Per `02.7-BUDGET-CALIBRATION.md` §4 and §5b, both real and load-bearing for how this phase's own
findings should be read:

1. **`ball`'s whole-cell cost is unmeasured.** Its euclidean `H2` bootstrap call timed out even at
   the small-`B` (`B=3`) measurement, so no real per-call number exists to compose a whole-cell
   total from. §9's ratified fallback (report `ball` as incomplete/timeout rather than blocking)
   is this document's answer to that gap — it does not resolve the underlying measurement gap.
2. **The PU-regime-shaped `H_2` power check (`S^2 x B^18`, `d=20`) timed out on both arms** at a
   doubled 180s ceiling. `H_2` power is **clean for `S^2`/`T^2`** — both intrinsically
   2-dimensional (`02.7-BUDGET-CALIBRATION.md` §5a: void arm resolved, filled control did not,
   clean separation) — but **is not established at higher effective dimensionality** within
   tractable time. This document does not assume it is. `BALL_D = 18` (§7) sits well inside the
   regime §5b could not resolve; the `ball` template's own `H_2` power at that dimension is
   therefore an **open, unmeasured question this benchmark's `ball` results should be read
   against**, not a settled fact.

**Assumption A-05 did not fire.** `02.7-BUDGET-CALIBRATION.md` §5a is the direct answer: at the
ratified `n_ph=300, B=10, D=768`, `H_2` **is** resolvable on this phase's own templates (`S^2`,
`T^2`, both 2-dimensional) — the void fixture's `H_2` bar clears the bootstrap band (1 significant
bar), the matched contractible control's does not (0 significant bars). This document ratifies
`n_ph`/`B` **without** assuming `H_2` is unresolvable on the benchmark's own templates — that
assumed risk did not materialize, on this measured evidence.

## 11. The H0 significance-band calibration — ratified here, blind

**The question, named plainly.** Plan `02.7-01`'s tracer, run at unratified placeholder settings
(`B=10`, `alpha=0.05`, no ratified bounds), produced large `beta_0` counts on both metric arms
(euclidean `251`, geodesic `189`) — far above the expected `1` for a connected, in-library cloud.
Separately, plan `02.7-04`'s own test development found that a **Gaussian-blob** fixture at
**`B=5`** produced 11 of 79 H0 bars spuriously clearing the bootstrap band, an effect the
`02.7-04-SUMMARY.md` traces to point-density variance in the blob's tail rather than genuine
multi-component structure — resolved *for that test* by switching to a near-uniformly-dense
jittered-grid fixture, not by changing the band mechanism itself.

**Ratified resolution.** `beta_0` uses the **identical** D-02 bootstrap-band mechanism as `H_1`
and `H_2` — no special-cased band, no different `B`/`alpha` for degree 0. The `+1` base-component
convention (`confidence_band.betti_vector`: significant H0 bars + 1 for the always-present base
component) is unchanged. **This document names, rather than silently fixes, the residual risk**:
non-uniform sampling density — which this phase's own D-15 grid deliberately varies via the
`density` arm (§8) and which the immersion's warp/noise (§7) can also introduce — can produce
moderately-isolated points whose H0 merge-life exceeds a small-`B` bootstrap band for reasons
unrelated to genuine multi-component structure. The tracer's own large counts were measured at
the *same* `B=10` this document ratifies, so `B=10` alone does not eliminate this risk; it was
not re-verified at the actual ratified templates and grid (only at the placeholder tracer's `S1`
cloud and plan `02.7-04`'s synthetic test fixtures).

**The mitigation already structurally present, stated explicitly here.** `template_decision.decide`
does **not** read `beta_0` off the persistence diagram as its authoritative component count for
abstain condition (b) — it reads `connectivity_readout["n_components"]` directly from
`geodesic_graph.component_readout`'s own graph-connectivity read-out (verified against source),
which is a direct combinatorial count, not a bootstrap-significance-derived one. A spuriously
large Betti-derived `beta_0` on the **Euclidean** arm (which has no analogous direct
component-count instrument) can still cause `lookup` to match no `TEMPLATE_TABLE` row (all four
rows require `beta_0 = 1`) and fire abstain (a) or, if the arms disagree, abstain (c) — **this is
a named, live risk carried into the benchmark's own abstention-rate numbers, not resolved by this
document.** Any elevated rate of abstain (a)/(c) firing specifically from an inflated Euclidean
`beta_0` should be read against this section before being read as evidence about the front end
itself.

## 12. The Swiss roll contract (D-16)
