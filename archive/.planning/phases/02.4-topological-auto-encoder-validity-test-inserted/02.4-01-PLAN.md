`pairwise_distances_f64(a)` — `torch.cdist` on `a.double()`, returning a float64 (n, n) tensor.
Every distance matrix in this phase goes through this one function so the float64 discipline
cannot be forgotten at a call site (RESEARCH.md Pitfall 10).

`persistence_pairs(D)` — the 0-dimensional persistence pairing, which for a complete graph is
exactly the minimum spanning tree edge set. Use the hand-rolled Union-Find/Kruskal routine given
verbatim in RESEARCH.md § Code Examples: `np.triu_indices(n, k=1)`, `np.argsort(weights,
kind="stable")` (row-major upper-triangular order makes a stable sort on weight alone realize
the full `(distance, row_index, col_index)` lexicographic tie-break), path-halving `find`, and
the early break once `n - 1` pairs are found. Returns an `int64` array of shape `(n-1, 2)`.
Raise `ValueError` naming the batch size when `n < 2`. Do NOT use
`scipy.sparse.csgraph.minimum_spanning_tree` — its tie-break order is not a documented,
version-stable contract, and this loss's value depends on which edges were selected
(RESEARCH.md Pitfall 1).

`topological_loss(d_x, d_z)` — the paper's `match_edges="symmetric"` branch. Select pairs from
`persistence_pairs(d_x.detach().cpu().numpy())` and `persistence_pairs(d_z.detach().cpu().numpy())`,
then index the **original, gradient-carrying** `d_x`/`d_z` tensors at those positions: gradients
flow through edge *lengths*, never through edge *selection*. Return
`{"loss_x_to_z": ..., "loss_z_to_x": ..., "total": loss_x_to_z + loss_z_to_x}` as torch scalars.
Docstring must state that the training loss uses `total` while the T1 gate evaluates the two
directional terms separately and gates on the worse one (D-04).

`latent_unit_scale(z)` — D-05's normalization, resolved here as the **global isotropic** reading:
return the single scalar `1.0 / sqrt(mean(var(z, axis=0)))`, so `z * latent_unit_scale(z)` has
mean per-dimension variance 1. Per-dimension standardization is explicitly rejected in the
docstring: dividing each axis by its own standard deviation is a non-isometric rescaling that
would change which points are nearest neighbours and corrupt the very topology T1 measures
(RESEARCH.md Pitfall 3 / assumption A1).

`lambda_schedule(epoch, cfg)` — D-15's warm-up-then-constant schedule. Reads
`cfg["lambda_topo"]`, `cfg["max_epochs"]`, `cfg["warmup_frac"]`, `cfg["ramp_frac"]`. Returns
0.0 while `epoch < floor(warmup_frac * max_epochs)`; then a linear ramp from 0 to
`lambda_topo` across the next `floor(ramp_frac * max_epochs)` epochs; then constant
`lambda_topo`. Linear is the only ramp shape implemented; the docstring says so.

`train_topoae(model, x_train, cfg)` — mirror the SHAPE of `cae._train_decoder_protocol`
(cae.py lines 630-713): same `torch.manual_seed(cfg["seed"])` + `np.random.default_rng(seed)`
seeding, same `torch.optim.AdamW(model.parameters(), lr=cfg["lr"],

three-way stopping rule (`max_epochs` cap, relative-plateau early stop on
`early_stop_min_delta`/`early_stop_patience`, `wallclock_ceiling_s` checked every epoch), and
the same returned dict keys `history`, `epochs_run`, `wallclock_s`, `wallclock_truncated`,
`early_stopped`, `cfg`. Do not import the private helper and do not reuse `cae.train_cae`'s
