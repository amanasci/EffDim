## 1. Metric definitions

Three gating metrics, exactly three, named `t1_topo_fidelity`, `t2_recon_margin`,
`t3_rank_structure`, in that order, matching `topoae.GATING_METRICS`.

**T1, topological fidelity.** The paper's own topological loss evaluated on held-out data
(D-01) — not a combinatorial matched-pair fraction and not a Wasserstein diagram distance. The
minimum spanning tree is built over the **entire** held-out set in one pass (D-03), because a
latent can preserve every 64-point neighbourhood while scrambling how regions connect; the
batch-wise average at training batch size is reported, non-gating, for consistency with how
the loss was optimised. The loss is a sum of two directional terms, computed separately, and
the **worse** one gates (D-04): input-to-latent catches destroyed structure, latent-to-input
catches invented structure, and these are different failures. The gating quantity is

```
max(loss_x_to_z_topoae / loss_x_to_z_baseline, loss_z_to_x_topoae / loss_z_to_x_baseline)
```

— the ratio is formed per direction and the max taken over directions, never over a summed
total.

**T2, reconstruction margin.** `mse_per_dim` from `cae.reconstruction_stats` on held-out data,
divided by the same quantity for the matched-capacity `cae.PlainAutoEncoder` at the same
latent dimension, under CAE-03's must-beat-not-tie rule.

**T3, rank structure.** `1 - min(trustworthiness, continuity)` at the gating neighbourhood
size (D-06, D-10), divided by the same quantity for the matched baseline (D-08). Continuity is
`sklearn.manifold.trustworthiness` with the two spaces swapped. Neighbourhood sweep
`{5, 15, 30}`, gating at `15` — the same `k*` 01-04's pre-registered plateau rule froze the
Isomap graph at, so the gating neighbourhood inherits an existing justification; the other two
rungs are reported sensitivity.

**D-09, recorded explicitly.** T1 and T3 gate independently, both are two-sided and may
correlate — T1's minimum spanning tree measures the connectivity skeleton, T3 measures local
neighbourhood ordering, and a latent can preserve one while breaking the other — so a joint
FAIL on both is **one** structural finding, not two independent ones.

**D-05's cost, recorded explicitly.** Latent coordinates are normalised by one global
isotropic scalar, `z / sqrt(mean(var(z, axis=0)))` (`topoae.latent_unit_scale`), rather than by
a scale fitted from a target as `cae.fit_global_scale` does. Per-dimension standardization is
rejected because it is a non-isometric rescaling that would change which points are nearest
neighbours. Consequently 02.4's T1 number is **not** directly comparable to 02.2's CAE
distortion figure — a different normalisation is a different statistic, and no later reader
should compare them.

**Ambient normalization resolution, its own named constant — scoped to the T1 gate only:**

```
AMBIENT_DIST_NORM = "none"
```

`AMBIENT_DIST_NORM = "none"` governs the **T1 gate's** computation on the whole held-out set:
raw float64 Euclidean distances, unnormalized, because the ambient data is already
L2-normalized onto the unit sphere and a per-batch-maximum denominator has no single
well-defined value over a ~2,000-point whole-set pass — and even if one were defined, a
per-model denominator computed at gate time would destroy the cross-model comparability the
baseline-relative margins (Section 1's `max(ratio_x_to_z, ratio_z_to_x)` form, T2, T3) all
depend on. This resolves `02.4-RESEARCH.md` Open Question 1, which no locked decision covered.

**Training uses a different, deliberately different, ambient normalization: per-batch
`d_x / d_x.max()`.** This is the paper's own convention, closed as fidelity gap #2 in plan
02.4-03's audit against the reference implementation (commit `4b9b6c9`) — before that
correction, `train_topoae` did not normalize the ambient side at all, which was a bug, not a
design choice. `topoae.py`'s training loop (`d_x_norm = d_x / d_x.max()`, paired with
`d_z_norm = d_z / latent_norm` on the latent side, where `latent_norm` is a jointly-trained
`torch.nn.Parameter`) is the faithful implementation; the gate's `AMBIENT_DIST_NORM = "none"`
is not an inconsistency with that — it is a **second, independently-justified choice at a
different evaluation point**, made for the comparability reason above. **The two are not the
same normalization and are not meant to be** — see Section 8, Limitation 3, and the Erratum
(Section 11) for the full statement of why this distinction is load-bearing for anyone reading
`loss_x_to_z`/`loss_z_to_x` off the gate.

## 2. Numeric PASS thresholds and their derivation

`THRESH_T1 = 0.90`. The worse-direction held-out topological loss must be strictly below 0.90
times the matched baseline's — a ten percent margin, the same size 02.2 used for CAE-03.
Justification: topological signature matching is this method's own central published claim, so
a margin is warranted; a threshold at 1.00 would be cleared by a numerically trivial
improvement the method achieves by construction, and would measure nothing.

`THRESH_T2 = 1.00`. Held-out `mse_per_dim` must be strictly below the matched baseline's.
Justification: CAE-03's rule is literally "must beat, not tie", and strict less-than against
1.00 encodes precisely that and no more. 02.2's additional discretionary ten percent is **not**
inherited, and the reason must be stated: the published method claims topological fidelity at
comparable reconstruction, not better reconstruction, so importing a ten percent reconstruction
margin would gate this method on a claim it never made — the same category error R4 forbids
for geodesic distortion.

`THRESH_T3 = 0.90`. `1 - min(trustworthiness, continuity)` at the gating neighbourhood size
must be strictly below 0.90 times the matched baseline's, the same margin and the same
reasoning as T1, since rank-structure preservation is also a claim the paper makes for itself.

**Verdict rule, stated verbatim.** PASS requires all three gates to hold; every comparison is
strict less-than, so a value exactly at a threshold does not clear it; there is no MARGINAL
tier, because every non-PASS outcome routes to the same halt-for-user-decision consequence. A
run in which any gating metric is absent or non-finite halts and writes no verdict at all.

Each end's justification: 8 is 02.1's coordinate-branch elbow (`classical_p`); 40 tests

```
SEEDS_PRIMARY = (20260806, 20260807, 20260808)
```

One seed (the first, `20260806`) at each other rung — eight TopoAE fits in all (D-18). The

## 5. The gate-engine key mapping

Records the decision plan 02.4-02 implemented: `cae.verdict_from_metrics` reads `cae.py`'s own
module-level gating tuple, so `topoae.py` defines its own `GATING_METRICS` and a thin wrapper
that validates its three names, remaps them positionally onto the imported module's slots,
delegates the strict-less-than comparison and the absent-or-non-finite guard to the sealed
function, and maps the returned detail keys back.

Alternatives rejected and why: reusing the borrowed names would make the artifact's gate list
print the geodesic-distortion name, reading as if the phase gated on the exact statistic R4
forbids; monkeypatching the shared module global would mutate state another module owns.

`cae.py` is not modified in any respect — verified after every task by
`git diff --quiet -- notebooks/pu_manifold/cae.py`.

## 8. Stated risks, recorded before the fact

**D-11's transfer risk.** Lambda was tuned on a 2-d sheet in 3-d and is applied to a ~20-d
manifold in 768-d; the sweep's topological-to-reconstruction term ratio (`transfer_ratio` in
`02.4-03-SUMMARY.md`'s lambda sweep table) is recorded here and the PU run reports the same
ratio, so a transfer failure is visible as an order-of-magnitude gap rather than as an
unexplained FAIL.

**D-05's non-comparability** with 02.2's distortion figure (Section 1).

**The unfaithfulness/coverage adapter's affine rescaling** from the unit box onto the latent's
bounding box, and that it is a stated difference from 02.2's measurement.

**The phase's central framing.** This method is **not** scored primarily on geodesic
distortion, because 02.1's ~0.0796 wall was measured on a distance-preservation statistic that
this method never optimises; distortion and unfaithfulness/coverage appear in the verdict
artifact only under the non-gating `context_metrics` key.

**The three named limitations carried forward from `02.4-03-SUMMARY.md`, stated plainly, as
required input to this document:**

1. **Absolute persistence correlation `r = 0.680` beat the matched baseline (`r = 0.471`, a
   45% relative win) but still misses the 0.8 bound originally set.** Both facts stand
   together — the baseline win is real, and so is the absolute miss. Neither should be read as
   cancelling the other.

2. **The `<=10% reconstruction degradation` selection rule is mis-specified for a method that
   trades reconstruction for topology by design.** It functions as "pick the smallest lambda,"
   not as a principled criterion: it bound at the grid floor on both the pre-correction
   (broken) loss and the corrected loss, across both the original and the redrawn grid. This is
   **documented, deliberately not fixed** — retuning a selection rule after seeing sweep
   results would forfeit exactly what a pre-registration exists to protect.

   **Reframing, per the coordinator's decisive context on Task 1:** the grid `(0.0, 0.1, 0.3,
   1.0, 3.0)` already spans the paper's own log-uniform-`[0.1, 3]` searched range — `0.1` and
   `3.0` are the authors' own bounds. `LAMBDA_TOPO = 0.1` is therefore not an arbitrary grid
   floor but **the smallest lambda the paper's own authors considered**; sweeping lower would
   leave the range the paper validated, and the selection rule would simply re-bind at
   whatever new floor was introduced, teaching nothing. **Both halves stand together:** the
   rule selects the paper's own minimum searched lambda, *and* the rule's own
   reconstruction-degradation criterion is mis-specified for a method that trades
   reconstruction for topology by design. The first fact does not repair the second.

3. **The T1 gate measures a different normalization than training optimizes** — raw `d_x`
   (`AMBIENT_DIST_NORM = "none"`) plus `latent_unit_scale` at the gate, versus per-batch
   `d_x / d_x.max()` plus the jointly-trained `latent_norm` in training. Consequence:
   `loss_x_to_z` / `loss_z_to_x` are scale-sensitive and are **not clean evidence on their
   own**. The scale-free correlation `r` (Swiss roll notebook) and, by the same construction,
   the ratio-based T1 gate defined in Section 1 are the trustworthy quantities. Anything in
   this document, the runner, or a later reading that reasons from the directional losses in
   isolation must restate this caveat at the point of use.

**Float64, recorded as a deliberate divergence.** `topoae.py`'s training and gate computations
retain float64 throughout, diverging from the reference implementation's float32, kept for the
tie-break determinism the `persistence_pairs`/`topological_loss` machinery depends on. This was
confirmed unchanged by both of 02.4-03's correction rounds and is a stated design choice, not a
limitation.

## 11. Erratum 1 (2026-08-07) — Section 1's ambient-normalization claim corrected

**What the original text said.** As committed at `744c1c1`, Section 1 read: *"Raw float64
Euclidean distances, identically at training time and at the T1 gate, because the ambient data
is L2-normalized onto the unit sphere and the paper's per-batch-maximum convention would
differ between the 64-point training batches and the whole-set gate."*

**Why that was wrong.** The claim that `AMBIENT_DIST_NORM = "none"` applies "identically at
training time and at the T1 gate" is factually false about `notebooks/pu_manifold/topoae.py`'s
actual training loop. `train_topoae` normalizes the ambient distance matrix by its own
per-batch maximum (`d_x_norm = d_x / d_x.max()`) and the latent distance matrix by a
jointly-trained scalar (`d_z_norm = d_z / latent_norm`) before computing the topological loss
— the paper's own convention, and precisely the fidelity gap plan 02.4-03's audit against the
reference implementation closed at commit `4b9b6c9`. Only the **T1 gate**, which evaluates
`topological_fidelity` on the whole held-out set outside training, uses `AMBIENT_DIST_NORM =
"none"` (raw, unnormalized `d_x`). Section 8's Limitation 3 already stated the correct,
different picture; Section 1 contradicted it. This is the contradiction the coordinator's
verification found and the reason this erratum exists.

**How it was found.** Orchestrator verification of `744c1c1` against `topoae.py`'s source
after this plan returned complete, cross-checking Section 1's prose claim directly against the
training loop's code (`d_x_norm = d_x / d_x.max()`, `d_z_norm = d_z / latent_norm`) rather than
trusting the document's own self-description.

**What changed and what did not.** Section 1 and Section 4 above are corrected in this same
commit to state the T1-gate-only scope of `AMBIENT_DIST_NORM = "none"` and to name the
training-side normalization (`d_x / d_x.max()` plus the jointly-trained `latent_norm`) as the
separate, deliberate thing it is, with the reason the two differ on purpose (a per-batch
maximum has no single well-defined value over a whole held-out set, and a per-model denominator
at gate time would destroy the cross-model comparability the baseline-relative margins depend
on). **No constant value and no threshold moved.** `LAMBDA_TOPO`, `THRESH_T1`/`THRESH_T2`/
`THRESH_T3`, `LADDER`, `D_PRIMARY`, the seeds, the warm-up/ramp fractions, and every other
pre-registered number are byte-identical to `744c1c1`. This erratum corrects a misstatement
about what the already-implemented, already-audited code does — it does not re-select, re-tune,
or re-derive any pre-registered quantity, and it was written without loading, inspecting, or
computing anything from the PU embedding data.

**Disposition, per the user's decision.** Additive erratum commit. `744c1c1` stays in the
commit history unmodified and unsuperseded; this correction lands as a new commit on top of it.
The frontmatter `amends:` field remains `none` because nothing pre-registered here is being
amended in the Section 8/D-xx sense — the erratum corrects a documentation defect in Section 1's
prose, not a locked decision or a threshold.
