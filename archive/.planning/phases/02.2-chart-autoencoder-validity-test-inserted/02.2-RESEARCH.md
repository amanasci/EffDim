## Summary

The Chart Auto-Encoder (CAE, Schonsheck/Chen/Lai, arXiv:1912.10094v2, Aug 2020) replaces a single
flat latent space with a **disjoint union of overlapping local charts** `Z = ⊔_α Z_α`, each
`Z_α = (0,1)^d`. Its motivating theorem (Thm 1, read directly from the paper this session) says a
plain single-chart autoencoder **cannot** ε-faithfully represent a manifold with non-contractible
topology — exactly the assumption class Phase 2's FAIL falsified was *global* Euclidean
embeddability, not *local* Euclideanness. CAE only assumes the latter, making it the correct
assumption-relief candidate under Phase 02.1's coordinate-producing fork.

The architecture is a five-part pipeline: an **initial encoder** `E: R^768 → R^40` (a
near-isometric dimension reduction per Nash–Kuiper, motivating `l ≈ 2d`), **N chart encoders**
`E_α: R^40 → (0,1)^20`, **per-chart decoders** `D_α: (0,1)^20 → R^40` (back to the *embedding*
space, not directly to ambient space — a detail easy to get wrong, see Pitfall 1), one **shared
embedding decoder** `D: R^40 → R^768`, and a **chart predictor** `P` emitting softmax-style
partition-of-unity probabilities. Training minimizes eq. 3's `L(x,W) = min_α e_α - Σ_β ℓ_β log(p_β)`
(`ℓ = softmax(-e)`) plus a Lipschitz regularizer on chart-encoder spectral norms (eq. 4) and uses
farthest-point-sampling (FPS)-seeded per-chart pre-training (eq. 5) to prevent decoder inactivity.
Chart count is obtained **a posteriori**: weight decay drives unused chart-decoder weights toward
zero, and a stated norm tolerance prunes them. The paper's own reference implementation is
TensorFlow with ReLU (page 8) — CAE-06 already anticipates the swap to a C2-smooth activation this
milestone's downstream decoder/curvature requirements need.

The single highest-leverage finding for the planner: **the pre-registered geodesic-distortion
metric (D-09 item 1) must be computed on the initial encoder's global embedding `z = E(x) ∈ R^40`,
never on chart-local coordinates `z_α ∈ (0,1)^20`.** Chart coordinates from different charts are
not comparable in one coordinate system (that is the whole point of charts), so pairwise distance
between two points assigned to different charts is meaningless. `E`'s output is the one global,
near-isometric coordinate system this phase produces — the correct analogue of 02.1's Krein/MDS
coordinates for the DISTORTION statistic. This single misunderstanding, if missed during planning,
would silently corrupt the phase's primary comparability metric with 02.1's own DISTORTION
statistic.

**Primary recommendation:** Implement CAE as pure `torch` (already pinned, no installs) inside a
new `notebooks/pu_manifold/cae.py` module following the `cache.py`/`geometry_probes.py` pattern
(pure functions/`nn.Module`s in, dicts/tensors out; no file I/O in the module itself). Train on the
`legacysurvey` array of the frozen `subsample_20260729_a79b3460b838fd0a.npz` cache (fit_key
`43cf438bc944c509`) — the same array the audited FAIL was measured on. Compute the geodesic
distortion metric on `E`'s R^40 output against the cached `geo_pairs_r2` array (note: that array
holds **unsquared** geodesic distances — square before calling `distortion_stats`). Use exact
SVD (`torch.linalg.matrix_norm(W, ord=2)`) for the Lipschitz regularizer, not
`torch.nn.utils.parametrizations.spectral_norm` (a hard constraint, not the paper's soft penalty —
see Pitfall 2). Build the plain single-chart AE control as the paper's own literal eq. 22
architecture (N=1, no cross-entropy term), not a separately invented baseline.

### Pattern 1: Two-stage decode (per-chart decoder targets the embedding space, not ambient space)

**What:** `D_α: (0,1)^d → R^l` maps chart coordinates back to the **initial-encoder embedding
space** R^40, not directly to R^768. Only the shared `D: R^l → R^m` (=R^768) is the final decoder.
**When to use:** Always — this is the paper's stated architecture (Section 4, "Chart Decoder":
"Each latent chart is equipped with a decoder D_α, which maps from the chart latent space back to
the embedding space R^l"; "Embedding Decoder... mapping from the embedding space R^l to the
original ambient space R^m").
**Example** `[CITED: arXiv:1912.10094 §4, p.5-6, read directly this session]`:
```python
# z = E(x)                      # R^768 -> R^40
# z_alpha = E_alpha(z)           # R^40 -> (0,1)^20   (chart encoder)
# w_alpha = D_alpha(z_alpha)     # (0,1)^20 -> R^40   (chart decoder -- back to embedding space!)
# y_alpha = D(w_alpha)           # R^40 -> R^768      (shared embedding decoder)
# e_alpha = ||x - y_alpha||**2
```

### Pattern 2: Loss function (eq. 3)

**What:** `L(x,W) = (min_α e_α) − Σ_{β=1}^{L} ℓ_β log(p_β)`, where `ℓ = softmax(−e)` (over the
current batch's per-chart errors) and `p` are the chart predictor's output probabilities.
**Example** `[CITED: arXiv:1912.10094 eq. 3, p.6, read directly this session]`:
```python
e = torch.stack([((x - y_alpha) ** 2).sum(-1) for y_alpha in y_list], dim=1)  # (batch, N)
recon_term = e.min(dim=1).values                                              # min_alpha e_alpha
ell = torch.softmax(-e, dim=1).detach()   # softmax(-e); treated as a fixed target distribution
p = chart_predictor(z)                    # (batch, N), already softmax-normalized
xent_term = -(ell * torch.log(p.clamp_min(1e-12))).sum(dim=1)
loss = recon_term.mean() + xent_term.mean()   # eq. 3 (batch-mean form)
```

### Pattern 3: Lipschitz regularization (eq. 4) via exact SVD, not power iteration

**What:** `R_Lip = max_α(Π_k ||W_α^k||_2) + (1/N) Σ_β(Π_k ||W_β^k||_2)` — first term stops one
chart's encoder from dominating; second promotes overall smoothness.
**Example** `[CITED: arXiv:1912.10094 eq. 4, p.6-7, read directly this session]`:
```python
def chart_encoder_spectral_product(encoder: torch.nn.Sequential) -> torch.Tensor:
    prod = torch.ones((), dtype=torch.float64)
    for layer in encoder:
        if isinstance(layer, torch.nn.Linear):
            prod = prod * torch.linalg.matrix_norm(layer.weight, ord=2)  # exact SVD, cheap at <=250x250
    return prod

products = torch.stack([chart_encoder_spectral_product(E_alpha) for E_alpha in chart_encoders])
r_lip = products.max() + products.mean()   # paper's 1e-2 weight, per-Claude's-discretion
```

### Pattern 4: FPS-seeded pre-training (eq. 5)

**What:** Select N seed points via farthest-point sampling (FPS) over the training set; pre-train
each `(E_α, D_α)` pair so `x_α` sits at the center `[.5]^d` of its chart, with a categorical
chart-prediction target. Prevents the "dead chart" failure mode the paper warns about (a chart
decoder never activated stays at initialization and never gets gradient signal).
**Example** `[CITED: arXiv:1912.10094 eq. 5, p.7, read directly this session]`:
```python
# L_init(x_alpha) = ||x_alpha - D(D_alpha(E_alpha(E(x_alpha))))||^2
#                  + ||E_alpha(E(x_alpha)) - [.5]^d||^2
#                  + sum_beta delta_{alpha,beta} log(p_beta)
```

### Pattern 5: Chart-transition cycle residual (eq. 8) — CAE-04's direct metric

**What:** Re-encode decoded data through a *second* chart and measure the round-trip error in both
directions — the direct test of whether the atlas is consistent where charts overlap.
**Example** `[CITED: arXiv:1912.10094 eq. 8, p.8, read directly this session — the exact formula]`:
```python
# R_cycle(x) = ||x - D(D_beta(E_beta(E(D(D_alpha(E_alpha(E(x)))))))||
#            + ||x - D(D_alpha(E_alpha(E(D(D_beta(E_beta(E(x)))))))||
# i.e.: encode/decode through chart alpha -> re-encode/decode through chart beta -> compare to x
#       (plus the symmetric alpha<->beta direction). Evaluate only on point pairs (x, alpha, beta)
#       where p_alpha(x) and p_beta(x) are both above some overlap threshold (else there is no
#       "transition" to measure -- the paper's own text: "Note that if x in M_alpha ∩ M_beta").
```

### Pattern 6: Unfaithfulness and coverage (eqs. 20/21) — CAE-05's reported, non-gating measures

**What:** Sample `ℓ` points uniformly in the (surviving, post-pruning) chart latent space(s);
decode each; **unfaithfulness** = mean squared distance from each decoded sample to its nearest
*training* point; **coverage** = (number of distinct training points that are some sample's
nearest neighbor) / ℓ. Paper uses `ℓ = 100` `[CITED: arXiv:1912.10094 p.19]`.
**Example** `[CITED: arXiv:1912.10094 eqs. 19-21, p.18-19, read directly this session]`:
```python
# E_recon      = (1/n) * sum_{x in D_test} ||x - y(x)||**2                          # eq. 19
# E_unfaithful = (1/l) * sum_i min_{x in D_train} ||x - D(z_i)||**2                  # eq. 20
# l_star       = |{x* : x* = argmin_{x in D_train} ||x - D(z_i)||**2, i=1..l}|       # distinct-count
# E_coverage   = l_star / l                                                          # eq. 21
```

### Pattern 7: The plain single-chart AE control (CAE-03) = the paper's own eq. 22 architecture

**What:** The paper itself reports a literal deterministic "Auto-Encoder" baseline distinct from
both its CAE and the VAE comparisons — `x → FC_250 → FC_250 → FC_250 → FC_d → z; z → FC_250 →
FC_250 → FC_250 → FC_m → y` `[CITED: arXiv:1912.10094 eq. 22, p.22, read directly this session]`.
Building CAE-03's "plain single-chart autoencoder" control as this exact architecture (matched
capacity: same total depth/width budget, N=1 chart, no cross-entropy term since there is only one
chart) is directly precedented by the paper rather than an invented control.

### Anti-Patterns to Avoid
- **Computing geodesic distortion on chart-local coordinates `z_α`** — meaningless across
  differently-charted point pairs; use `E`'s global `z` output (see Pitfall 3 below and Summary).
- **Treating `geo_pairs_r2` as already squared** — it is stored as raw geodesic distance; square it
  before calling `distortion_stats(d2_rep, d2_geo)` (see Pitfall 5).
- **Using `sklearn.manifold.Isomap.reconstruction_error()` as the CAE-03 Isomap baseline** — that
  method reports a residual-variance statistic of the *graph embedding itself*, not a held-out
  reconstruction back to the 768-d ambient space (see Pitfall 4).
- **Hard-constraining chart-encoder spectral norms via `spectral_norm` parametrization** instead of
  computing the soft eq. 4 penalty (see Pitfall 2).

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Chart-encoder Lipschitz/spectral-norm value | Power-iteration approximation from scratch | `torch.linalg.matrix_norm(W, ord=2)` (exact SVD) | Layer widths here are ≤ 250×250 (per-chart) and ≤ 768×250 (initial encoder) — exact SVD is cheap and removes the power-iteration convergence-tolerance question entirely |

## Common Pitfalls

### Pitfall 1: Per-chart decoder targets the wrong space
**What goes wrong:** Someone builds `D_α: (0,1)^d → R^768` directly, skipping the shared embedding
decoder `D`.
**Why it happens:** The 02.1/Phase-2 codebase's mental model (Isomap coordinates → decoder → R^768
directly) primes a one-hop decode; CAE's two-hop decode (`D_α` to R^l, then shared `D` to R^768) is
easy to collapse into one hop by habit.
**How to avoid:** Follow Pattern 1 exactly; the shared `D` must be a *single* module instantiated
once and called by every chart's forward pass — not per-chart.
**Warning signs:** Parameter count much higher than the paper's Table/eq. 26-28 reference sizes for
comparable `(N, d)`; embedding decoder weights not shared (gradient updates from one chart don't
visibly affect another chart's reconstruction quality).

### Pitfall 2: Hard-constraining spectral norm instead of penalizing it
**What goes wrong:** Substituting `torch.nn.utils.parametrizations.spectral_norm` (or the legacy
`torch.nn.utils.spectral_norm`) for the eq. 4 regularizer. This *reparametrizes* the weight matrix
via power iteration to force its spectral norm to ≈1 always — it is a hard constraint, not a
differentiable penalty term to add to the loss.
**Why it happens:** `spectral_norm` is the first hit for "Lipschitz + torch" and looks like exactly
what's needed.
**How to avoid:** Compute `torch.linalg.matrix_norm(W, ord=2)` per layer, take the products/max/mean
per eq. 4, and add the result (times a scalar weight, paper: 1e-2) to the loss as a term the
optimizer can trade off against reconstruction — do not reparametrize the layer itself.
**Warning signs:** Chart-encoder weights never shrink under weight decay (a hard-constrained
spectral norm resists the decay pressure the paper explicitly relies on for a-posteriori chart
pruning, CAE-05); training loss curve shows `R_Lip` pinned at a constant value rather than moving.

### Pitfall 3: Computing distortion on chart-local coordinates
**What goes wrong:** Passing `z_α` (chart-local, `(0,1)^20`) pairs into `distortion_stats` instead
of `z = E(x)` (global, R^40). Two points on different charts have chart coordinates in unrelated
coordinate systems — their "distance" in `(0,1)^20` space carries no geometric meaning.
**Why it happens:** `z_α` is the object most proximate to "the chart representation" in casual
reading of the requirement text; it takes closely reading Pattern 1's data flow to see that `E`'s
own output is the one global, comparable coordinate system CAE produces.
**How to avoid:** Compute the 200,000-pair distortion statistic on `E(x)` (R^40) exclusively — the
initial encoder's near-isometric embedding, analogous in role to 02.1's Krein/classical-MDS
coordinates.
**Warning signs:** Distortion values wildly inconsistent across pairs whose two points land on
different surviving charts vs pairs landing on the same chart (a symptom of comparing coordinates
across unrelated chart parameterizations).

### Pitfall 4: `Isomap.reconstruction_error()` is not the CAE-03 baseline
**What goes wrong:** Calling the cached `isomap_43cf438bc944c509.joblib`'s
`.reconstruction_error()` method and reporting it as "the classical-MDS/Isomap reconstruction
baseline" for CAE-03.
**Why it happens:** The method name sounds exactly right.
**How to avoid:** `sklearn.manifold.Isomap.reconstruction_error()` returns a residual-variance
statistic (1 − R²-like quantity between geodesic and embedded pairwise distances) — the same family
of quantity as Phase 2's Tenenbaum residual curve, **not** a held-out reconstruction back to the
768-d ambient space. CAE-03 needs an actual reconstruction: fit a decoder (linear least-squares, or
a shallow MLP at matched capacity) from the classical-MDS/Krein coordinates at the working dimension
back to R^768, held out, and measure squared error there — analogous to what CAE itself is being
asked to do. Classical MDS has no native inverse map to ambient space; one must be fit explicitly.
**Warning signs:** The "Isomap baseline" reconstruction number looks suspiciously good/stable across
very different working dimensions (a hallmark of measuring residual variance, which behaves
differently from an actual fit-and-evaluate reconstruction).

### Pitfall 5: `geo_pairs_r2` is unsquared
**What goes wrong:** Passing the cached `geo_pairs_r2` array directly as `d2_geo` into
`distortion_stats`, which expects **squared** distances.
**Why it happens:** The variable name pattern (`geo_pairs_r2`, "r2" referring to the `r2_pair_seed`
draw, not "squared") invites the assumption it is already squared, especially given classical MDS's
usual squared-distance convention.
**How to avoid:** `notebooks/diagnostics/geometry_probes_run.py` line 285 shows the correct usage:
`d2_geo = geo_pairs_r2.astype(np.float64) ** 2` — square it first, every time it is loaded.
**Warning signs:** Distortion values off by a large, suspiciously round-looking factor from expected
magnitudes (squaring vs not squaring a O(1) distance produces a very different relative-error
statistic).

### Pitfall 6: Compactness/reach assumption is silently treated as verified
**What goes wrong:** Citing Theorem 2's guarantee ("a CAE with L>d charts ε-faithfully represents
M") as though it applies to this point cloud without noting that the theorem requires **M compact
with positive reach τ**, and its sample-complexity bound (eq. 2, read directly this session:
`n > β₁(log β₂ + log(1/ν))`, with `β₁, β₂` depending on `ε`, `τ`, and `C = vol(M)/vol(B₁^d)`) is
never checked against `n=10,000` because `τ` and `C` are unknown for this point cloud.
**Why it happens:** The theorem is stated unconditionally in the paper's abstract/intro; the reach
and sample-size caveats are buried in Theorem 2's hypothesis and proof.
**How to avoid:** CAE-06 already requires recording this as an assumption, not a verified fact —
make sure the pre-registration and findings documents state explicitly that `τ` (reach) and `C`
(the density ratio) were never estimated for the PU point cloud, so Theorem 2's guarantee is cited
as *motivation*, not as *evidence this fit will succeed*.
**Warning signs:** Any writeup phrasing like "the theorem guarantees CAE will work here" without
the compactness/reach caveat attached.

### FPS (farthest point sampling), vectorized `[ASSUMED — standard algorithm, not paper code (no maintained reference implementation exists)]`
```python
import torch

def farthest_point_sample(x: torch.Tensor, n_seeds: int, seed: int) -> torch.Tensor:
    """Greedy FPS over x (n, l). Returns n_seeds row indices. O(n_seeds * n) via a running
    min-distance array -- no O(n^2) all-pairs matrix needed."""
    g = torch.Generator().manual_seed(seed)
    n = x.shape[0]
    chosen = torch.empty(n_seeds, dtype=torch.long)
    chosen[0] = torch.randint(0, n, (1,), generator=g)
    min_dist = torch.full((n,), float("inf"))
    for i in range(n_seeds):
        d = torch.cdist(x, x[chosen[i]].unsqueeze(0)).squeeze(1)  # (n,)
        min_dist = torch.minimum(min_dist, d)
        if i + 1 < n_seeds:
            chosen[i + 1] = torch.argmax(min_dist)
    return chosen
```

## Open Questions

1. **What numeric gate thresholds should be pre-registered (CAE-01/D-10)?**
   - What we know: three metric families are fixed (D-09); the geodesic-distortion metric can be
     benchmarked against 02.1's own measured numbers at comparable dimension (classical q=0 at
     p=40: `median_abs_rel = 0.179641`; at the elbow p=8: `0.121024` — both `[VERIFIED:
     02.1-RECOMMENDATION.md, this session's Read]`). No baseline exists yet for R_cycle or for a
     matched-capacity plain-AE/Isomap-decoder reconstruction error on this specific dataset.
   - What's unclear: the exact PASS/MARGINAL/FAIL cut points; whether R_cycle should be judged in
     absolute terms or relative to the model's own single-pass reconstruction error.
   - Recommendation (draft, for D-10 ratification — not locked):
     - **Geodesic distortion** (on `E(x)`, R^40, vs cached `geo_pairs_r2`): propose PASS if
       `median_abs_rel < 0.15` (materially below the classical `l=40` baseline of 0.179641), FAIL
       otherwise. A CAE `l=40` global embedding beating the equivalent-dimension linear classical
       baseline is a defensible bar since CAE's local-chart machinery should, if it is buying
       anything, outperform a global linear projection at the same dimension.
     - **R_cycle** (eq. 8, mean over held-out overlap-region pairs): propose PASS if the mean
       `R_cycle` is `≤ 2×` the model's own mean single-chart reconstruction error `E_recon` (a
       relative bound rather than an absolute one, since no absolute reference number exists in the
       paper or this codebase) — i.e., chart-transition round-tripping should not meaningfully worse
       than double the base reconstruction noise.
     - **Reconstruction vs baselines** (CAE-03): propose PASS if CAE's held-out aggregate MSE is
       strictly below both the matched-capacity plain single-chart AE control AND the fitted
       classical-MDS/Krein-coordinate decoder baseline, by at least a 10% relative margin over each.
   - These three numbers should be written into the pre-registration doc verbatim (or revised by
     the planner with its own reasoning) and committed *before* any training cell runs, per D-10.

2. **Should the R_cycle overlap-region selection threshold (which pairs count as "in both charts α
   and β") itself be pre-registered?**
   - What we know: the paper's own text (page 8) frames the metric as applying "if x ∈ M_α ∩ M_β" —
     it does not give a numeric threshold on `p_α(x)` for deciding overlap membership.
   - What's unclear: a reasonable operational cutoff (e.g., both `p_α(x) > 0.1` and `p_β(x) > 0.1`?)
   - Recommendation: pre-register a concrete `p`-threshold (e.g., 0.05) alongside the other D-09
     metrics, since without one, R_cycle's evaluation set is ill-defined and could be gamed by
     including only high-confidence single-chart points (trivially near-zero R_cycle).

3. **Does `arXiv:2208.10570` ("Semi-Supervised Manifold Learning with Complexity Decoupled Chart
   Autoencoders") change anything relevant?**
   - What we know: it exists (surfaced in WebSearch), is a 2022 follow-up to this same author group's
     line of work.
   - What's unclear: whether it addresses any of this phase's open numerical questions (e.g., a
     principled R_cycle threshold, or a better a-posteriori chart-pruning rule) — **not read this
     session**.
   - Recommendation: out of scope for this phase per D-01 (testing the original 1912.10094 method,
     not a later variant) — flagged only so a future amendment has a lead if this phase's chosen
     thresholds prove hard to defend.
