<objective>
Expand the proven tracer path into the full pre-registered training protocol: the paper's
Lipschitz regulariser, FPS-seeded per-chart pre-training, the three-way stopping rule, and the
matched-capacity baseline trainers the CAE-03 gate compares against.

Purpose: two of the three gating metrics depend on machinery that does not exist after the tracer.
CAE-05's a-posteriori chart pruning only works if the regulariser is the paper's *soft* penalty, so
weight decay can still shrink an unused chart — a hard constraint would resist exactly the decay
pressure the pruning mechanism relies on. CAE-03's gate is meaningless unless the controls are
genuinely matched, so the controls are built here alongside the model rather than improvised at
evaluation time.

Output: `notebooks/pu_manifold/cae.py` carrying every training-side function the runner needs, and
`notebooks/pu_manifold/tests/test_cae.py` carrying known-answer tests for each of them.

  <action>
Extend `notebooks/pu_manifold/cae.py` with three functions, keeping the existing
function-per-equation layout and the dict-of-named-floats return convention.

`lipschitz_penalty(chart_encoders, weight)` implements eq. 4. For each chart encoder, take the
product over its `nn.Linear` layers of that layer's largest singular value, obtained with
`torch.linalg.matrix_norm(layer.weight, ord=2)` — exact SVD, which is cheap at these layer widths
(at most 250 by 250 per chart, 768 by 250 for the initial encoder) and removes the
power-iteration convergence-tolerance question entirely. The penalty is the maximum of those
per-chart products plus their mean: the first term stops one chart's encoder from dominating, the
second promotes overall smoothness. Return `weight` times that quantity as a differentiable scalar
tensor the optimizer can trade off against reconstruction.

This must remain a **soft additive penalty term on the loss**. Do not reach for the
power-iteration spectral-norm reparametrisation helper bundled with `torch.nn.utils`: that helper
rewrites the weight matrix itself to force its largest singular value to approximately one at all
times, which is a hard constraint rather than a penalty, and it would resist exactly the weight-decay
pressure that CAE-05's a-posteriori chart pruning depends on. The warning sign, if this is ever
confused, is a chart-encoder weight set that never shrinks under weight decay and a penalty value
pinned to a constant across training rather than moving.

`farthest_point_sample(x, n_seeds, seed)` implements greedy farthest-point sampling over a
`(n, features)` tensor, returning `n_seeds` row indices as a `torch.long` tensor. Seed the first
pick from a `torch.Generator` set to `seed`, then maintain a running per-row minimum-distance array
and pick the argmax each round — order `n_seeds * n`, with no all-pairs matrix materialised. No new
package may be installed for this, and at sixteen seeds over ten thousand rows the hand-rolled
greedy routine is trivially fast.

`fps_pretrain_loss(model, x_seeds, seed_chart_index)` implements eq. 5: for each FPS-selected seed
point paired with the chart index it seeds, the sum of the squared ambient reconstruction error of
that point through its own chart, the squared distance between that point's chart coordinate and
the centre of the chart space (the all-one-half point in the chart's dimension), and the
categorical chart-prediction term pushing the predictor toward that chart for that point. Returning
a dict with the three named components plus their total keeps it inspectable. This stage exists to
prevent the dead-chart failure mode the paper warns about, where a chart decoder is never activated,
receives no gradient signal, and stays at its initialisation forever.

Stage one, pre-training: select `cfg["n_charts"]` seed rows with `farthest_point_sample` over the
initial encoder's current embedding of the training set, then run `cfg["fps_pretrain_epochs"]`
epochs minimising `fps_pretrain_loss` over those seed points paired with their chart indices.

Stage two, the main loop: AdamW at `cfg["lr"]` with `cfg["weight_decay"]`, shuffled minibatches of

`cfg["lip_weight"]`. The penalty is applied on steps where the step counter is a multiple of
`cfg["lip_every_n_steps"]`, un-rescaled — a pre-registered compute contingency, not a tuning knob,
so the value comes from the config and is recorded in the returned artifact.

The stopping rule is three-way and whichever fires first wins. The epoch cap is
`cfg["max_epochs"]`. The plateau rule fires when the epoch-mean total loss has failed to improve on
its best value by more than a relative `cfg["early_stop_min_delta"]` for `cfg["early_stop_patience"]`
consecutive epochs. The wall-clock ceiling is checked at every epoch boundary against
`cfg["wallclock_ceiling_s"]` measured from the start of stage one. Set exactly one of
`early_stopped` and `wallclock_truncated` True according to which fired, leave both False when the
cap was reached, and always record `epochs_run` and the measured `wallclock_s`.

Add the CAE-03 controls to `notebooks/pu_manifold/cae.py`.

`PlainAutoEncoder(in_dim, latent_dim, hidden, activation)` is the paper's own deterministic
autoencoder reference architecture, eq. 22: ambient input through three hidden layers of the
pre-registered `HIDDEN_WIDTH` to the bottleneck, then three hidden layers of the same width back to
the ambient dimension. This is a single chart with no chart predictor and no cross-entropy term,
which is precisely what makes it the right control for the question CAE-03 asks — whether the
atlas bought anything over one chart at matched capacity. Building it as the paper's own stated
architecture rather than an invented control is what keeps the comparison defensible.

`train_plain_ae(model, x_train, cfg)` reuses the identical protocol as `train_cae`: same optimizer,
same learning rate, same weight decay, same batch size, same three-way stopping rule, same seeding
discipline, same returned fit-artifact shape. The only differences are that there is no
pre-training stage, no chart predictor, no cross-entropy term, and no Lipschitz penalty, because a
single-chart model has no chart-encoder family for the penalty to range over. Record that
difference in the returned cfg rather than leaving it implicit.

`MlpDecoder(latent_dim, out_dim, hidden, activation)` and
`train_mlp_decoder(model, z_train, x_train, cfg)` fit a decoder from a fixed coordinate array back
to the ambient space, under the same protocol. This is the CAE-03 classical-MDS baseline: the
cached `mds_coords` array holds the classical-MDS embedding at 40 dimensions, the baseline slices
its first `p` columns, and the decoder is fitted on the training rows and evaluated on the holdout
rows. Classical MDS has no native inverse map to the ambient space, so one must be fitted
explicitly — and the `sklearn.manifold.Isomap` estimator's own residual-variance method is
emphatically not this quantity: it reports a residual-variance statistic of the graph embedding, in
the same family as Phase 2's Tenenbaum residual curve, rather than a held-out reconstruction back
to the 768-dimensional ambient space. The decoder's hidden layers match the plain-AE decoder half,
so the comparison is at matched capacity.

`fit_linear_decoder(z_train, x_train)` returns the least-squares linear map from coordinates to
ambient space, reported as a floor beneath the fitted MLP decoder so a reader can see how much of
the baseline's performance is linear.
