## Open decisions adopted as this plan's stated assumptions

No CONTEXT.md exists for Phase 02.6 (it was inserted and scoped directly in ROADMAP.md;
`/gsd-discuss-phase` was never run). 02.6-RESEARCH.md flags several of its own proposals as
pending ratification. The decisions below do **not** change what gets built, so they are adopted
here as stated assumptions rather than pushed to a checkpoint. The decisions that *would* make
already-written work wrong if reversed — the numeric admission floor and the promotion bars — are
gated by a `checkpoint:decision` in plan 02.6-02 instead.

- **A-01. Import the sealed private helpers; do not duplicate them.** `VMAP_CHUNK`,
  `_pad_to_chunk`, `_assert_float64` and `ZERO_SECOND_DERIVATIVE_ACTIVATIONS` are imported from
  `chart_curvature` unchanged. **Alternative not chosen:** duplicate ~15 lines into the new module
  (02.6-RESEARCH.md Open Question 1's own recommendation, on the grounds that this codebase
  duplicates rather than shares across sealed phase boundaries). Rejected because importing *reads*
  the sealed module and never edits it — the coupling that Open Question 1 actually warns against is
  editing `chart_curvature.py` to add a `chart_idx=None` branch, which this plan does not do — and
  because a second copy of `VMAP_CHUNK`/`_pad_to_chunk` is a second copy of the exact constant whose
  drift silently destroys bit-reproducibility. Reversible.
- **A-02. A new sibling module, never an edit to `chart_curvature.py`.** Adopted from
  02.6-RESEARCH.md's Anti-Patterns section and this codebase's own insertion pattern
  (`curvature_probe.py` beside `curvature.py`, `topoae.py` beside `cae.py`). **Alternative not
  chosen:** generalize `chart_curvature.chart_decoder_map` in place. Reversible as chosen; the
  rejected alternative would have been costly (it edits a sealed Phase 02.5 artifact).
- **A-03. Mirror the sealed `chart_mean_curvature`'s trace-first-then-project form, not
  02.6-RESEARCH.md Pattern 1's illustrative explicit-projector form.** PATTERNS.md line 74 records
  this as a genuine open decision. Adopted: the `d x d` solve. Reasons: it is the form the sealed
  module already proves correct; at the Swiss roll's `out_dim = 3` the two forms cost the same; and
  at the PU regime's `out_dim = 768` the explicit form materialises 151 MB of float64 projector per
  chunk, so a follow-on gate phase reusing this module would have to rewrite it. **Alternative not
  chosen:** the explicit `(out_dim, out_dim)` projector. Their equality is proved by test in Task 3
  rather than asserted. Reversible.
- **A-04. `swiss_roll_analytic_H_vector` is hosted in this new module.** The analytic mean curvature
  *vector* (needed for the direction axis) exists nowhere in the repo — `curvature_probe` supplies
  only its norm, and 02.5-09 derived the direction inline in its notebook. Two admission notebooks,
  one diagnostics runner and one test file all need it. **Alternative not chosen:** re-derive it in
  each of the four (02.5-09's own precedent), which would put four copies of a six-line differential
  geometry derivation in the repo and no single place to pin them. Hosting it once and pinning its
  norms against the sealed `curvature_probe.swiss_roll_analytic_H_scaled` keeps the sealed module as
  the magnitude ground truth and makes the direction the only new information. Reversible.
</assumptions>

<critical_finding_from_planning>
**`chart_curvature.assert_c2_activation` cannot be called on a `PlainAutoEncoder`.** Both
02.6-RESEARCH.md (Pattern 1, line 239) and 02.6-PATTERNS.md (Shared Patterns, "C2-activation guard")
instruct the new module to call `assert_c2_activation(model)` unchanged, and PATTERNS.md states
"Both `PlainAutoEncoder` default constructions use `activation="silu"` by default so this passes."
**That is false and was verified false during planning.** `cae.ChartAutoEncoder.__init__` sets
`self.activation = activation` at `cae.py:170`; `cae.PlainAutoEncoder.__init__` (`cae.py:584-594`)
does **not**. `assert_c2_activation` opens with `if not hasattr(model, "activation"): raise
ValueError(...)`, so it hard-raises on *every* `PlainAutoEncoder`, silu or otherwise. Measured:

    has .activation: False
    guard RAISED: assert_c2_activation: model has no 'activation' attribute, ...

`cae.py` is sealed and must not be edited to add the attribute. Task 1 therefore introduces
`assert_c2_decoder`, which reuses the sealed `ZERO_SECOND_DERIVATIVE_ACTIVATIONS` frozenset
unchanged and reaches it by **inspecting the decoder's own activation submodules** instead of a
recorded attribute. That is strictly stronger than trusting an attribute, and it is what makes the
ReLU-decoder guard test in Task 2 meaningful rather than vacuous. Also verified during planning:
`type(m).__name__.lower()` over `model.decoder.modules()` yields exactly `silu` for a default
`PlainAutoEncoder` and exactly `relu` for `activation="relu"`, and both strings key directly into
the sealed frozenset.
</critical_finding_from_planning>

<assumption_delta_decision>
The `assumption-delta` detector fired (`kind: pluralization`, on the weak lexical term
"alongside"). The signal is a weak lexical hit, but a genuine assumption delta does exist in this
phase and is worth recording: Phase 02.5 was built around **the** decoder substrate (the chart
auto-encoder); Phase 02.6 opens that to **many** candidate substrates.

- **Noun now primary:** *decoder substrate* — any smooth map `decode: R^d -> R^D` whose second
  fundamental form is taken by exact autodiff. The chart-routed CAE is one variant of it, not the
  general case.
- **Decision:** `add-alongside`, deliberately. The correct promote would be to generalize
  `chart_curvature.py` so the chart-routed decoder becomes one branch of a general decoder-curvature
  module. That is blocked by a hard project constraint, not by preference: `chart_curvature.py` is
  Phase 02.5's sealed artifact and this milestone does not edit sealed modules.
- **Accepted debt, and what would force the promote:** two modules now carry the same
  differentiation mathematics with different front doors. If a third substrate family arrives (a
  decoder that is neither one MLP nor a chart atlas — e.g. GRAE's kernel-regularized bottleneck), a
  third copy would be one too many and the shared core should be lifted into a common helper at that
  point, ideally when Phase 02.5's artifacts are no longer live. Recorded, not scheduled.
- **Companion invariant test (suggested, and implemented here):** Task 3's
  `test_decoder_curvature_convention_matches_chart_curvature` goes red the instant the two modules'
  curvature conventions diverge — the one way the duplication can silently produce two different
  answers to the same question.
</assumption_delta_decision>
