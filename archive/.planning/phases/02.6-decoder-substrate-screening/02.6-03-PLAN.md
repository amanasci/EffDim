<objective>
Deliver CLAUDE.md's mandatory Swiss roll sanity notebook for the **plain auto-encoder** decoder as a
curvature substrate: `notebooks/02.6_swiss_roll_plainae_curvature_check.ipynb`.

Purpose: `cae.PlainAutoEncoder` has a Swiss roll notebook already (`02.2_swiss_roll_cae_check.ipynb`
uses it as the matched baseline) and it passes — but that notebook tests **reconstruction**, and
nothing in this repo has ever tested this decoder's **curvature**. Reading the existing notebook's
pass as admission evidence is 02.6-RESEARCH.md's Pitfall 1 exactly, and
`02.5-NOTE-substrate-selection.md` Section 4 states flatly that reconstruction quality validates
nothing about curvature. This plan closes that gap for one candidate.
Output: a 15-cell notebook, executed end to end with outputs committed, and a human judgement on its
read-out.
</objective>

<assumptions>
## Open decisions adopted as this plan's stated assumptions

- **A-05. Fixture: `curvature_probe.make_swiss_roll_fixture(n=3000, seed=20260807)`.** Both 02.6
  notebooks and the plan 02.6-05 runner use this identical fixture. **Alternative not chosen:** the
  02.4 notebook's own `make_swiss_roll(n_samples=3000, random_state=20260806)` call. Rejected because
  the raw-point comparator's `0.6712` and the CAE negative control's whole four-seed table were
  measured on `20260807`; using a different draw would make this phase's numbers non-comparable to
  the one negative control it has. Reversible.
- **A-06. Architecture and training cfg reused verbatim from `02.4_swiss_roll_topoae_check.ipynb`:**
  `cae.PlainAutoEncoder(3, 2, hidden=(64, 64, 64), activation="silu")`, cfg
  `dict(seed=SEED, lr=3e-4, weight_decay=1e-4, batch=64, max_epochs=150)`, 80/20 train/holdout split
  from `np.random.default_rng(SEED).permutation(3000)`. **Alternative not chosen:**
  02.5-09's own `hidden=[64,64]`, `lr=1e-3`, `max_epochs=300`, `early_stop_patience=25`. Rejected
  because plan 02.6-04 screens the *same* `PlainAutoEncoder` class trained under
  `topoae.train_topoae`, and the two candidates must differ only in the topological loss term for the
  comparison to mean anything — so both must use the cfg that `train_topoae` was itself last
  exercised under. A second reason: with `early_stop_patience` left unset, `_train_decoder_protocol`
  defaults it to `max_epochs + 1`, so neither arm early-stops and both run the identical 150-epoch
  budget. Phase 02.4-05's reopened defect was precisely an early-stop asymmetry between a TopoAE arm
  and its matched baseline; this choice makes that failure mode unreachable. Reversible.
- **A-07. Notebook sanity bars are comparative against the raw-point arm computed in the same cell;
  the notebook introduces no numeric constant of its own.** 02.5-09's precedent is that a sanity
  notebook introduces no new tunable. The phase's *screening* bars live in
  `02.6-SCREENING-RULE.md` (plan 02.6-02) and are applied in `02.6-FINDINGS.md` (plan 02.6-06), never
  inside the notebook — CLAUDE.md bars threshold tables from a sanity notebook. **Alternative not
  chosen:** print the ratified screening bars inside the notebook. Reversible.
- **A-08. The matched-baseline step is degenerate for this candidate and is handled by substitution,
  stated, not by omission.** CLAUDE.md step 6 requires a matched baseline and names
  `cae.PlainAutoEncoder` as the one to use for reconstruction models — but here the model under test
  *is* `cae.PlainAutoEncoder`, so a reconstruction baseline against itself is vacuous. Substitution:
  the curvature comparator is `curvature_probe.centroid_mean_curvature` at `k=30, d=2` on the
  identical fixture — a baseline that works (Spearman `0.6712`) and the same reference 02.5-09 used.
  This follows CLAUDE.md's own instruction for the case where the standard baseline does not apply
  ("replace steps 5-6 with the ... analogue"), and it is stated in the notebook's markdown rather
  than silently omitted. **Alternative not chosen:** dropping the baseline step. Reversible.
</assumptions>
