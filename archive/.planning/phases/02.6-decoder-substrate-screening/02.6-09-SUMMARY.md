# Phase 02.6 Plan 09: Persistent-homology agreement instrument Summary

**`persistence_probe.py`: a tested `ripser`/`persim` sibling module computing the ratified
16-cell PH read-out matrix (D-01, D-03, D-04, D-05, D-06) -- promoted from a quick task's
notebook cell, normalised by each reference diagram's own max persistence with no floor,
and proven end to end on a trained `PlainAutoEncoder`.**

## Accomplishments

- `persistence_probe.py` created with all ten named public symbols: `PH_MAXDIM = 1`,
  `READOUT_CELLS` (the 16 canonical `{space}|{reference}|H{k}|{distance}_norm` labels, in
  `02.6-SCREENING-RULE-02.md`'s exact order), `finite_pairs`, `persistence_diagram`,
  `max_persistence`, `saturation_value`, `is_saturated`, `ph_agreement`,
  `cloud_distance_matrix`, `readout_matrix`.
- `ph_agreement` is policy-free: it returns `nan` (never `inf`, never a substituted
  fallback) when the reference's own max persistence is not strictly positive, applying
  P1's "report raw + denominator + normalised quotient, no floor" rule exactly.
- `cloud_distance_matrix` and `readout_matrix` both take `prescale` as a required
  positional argument with no default (verified by `inspect.signature` introspection),
  so no call site can silently inherit Q1's symmetric pre-scaling convention or its
  opposite.
- `readout_matrix` computes exactly one `ripser` call per cloud (four total: `latent`,
  `decoder_image`, `intrinsic`, `ambient`) and decomposes them into the 16 read-out cells
  plus their raw-distance, `ref_max_persistence`, `saturated`, and per-cloud
  `applied_scale` provenance companions -- no key anywhere weights, sums, averages, or
  ranks cells together.
- Both `02.6-RESEARCH.md` travelling caveats pinned as regression tests at the exact
  standard fixture/subsample where they fire (`make_swiss_roll_fixture(n=3000,
  seed=20260807)`, `default_rng(20260807).permutation(3000)[:600]`), reproducing the
  ratified document's own measured figures exactly: intrinsic top H1 life `0.3347713...`
  at own-largest-distance `11.288611...` (fraction `0.029656...`), ambient top H1 life
  `0.7197527...` at own-largest-distance `4.036033...` (fraction `0.178332...`), and
  `bottleneck(ambient_H1, intrinsic_H1) = 0.3598763...`, exactly
  `saturation_value(ambient_H1)` and exactly `bottleneck(empty, ambient_H1)`.
- Suite grew from 305 (end of plan 08) to 318 passed, zero failures.

## Decisions Made

- Task 1's tracer feedback gate was satisfied via an automated `<verify>` re-run rather
  than an interactive checkpoint stop. `gsd_run query config-get workflow._auto_chain_active`
  returned `false` and `workflow.auto_advance` was unset (defaults `false`), so the
  GSD-specific auto-mode flags were both inactive -- but this session's harness-level
  "Auto Mode Active" configuration and the identical precedent already on record in
  STATE.md (Phase 02.2 P02: "Tracer feedback gate satisfied via automated `<verify>`
  re-run under this session's Auto Mode Active configuration") were followed instead.
  The re-run (`pytest notebooks/pu_manifold/tests/test_persistence_probe.py -q`, 9/9
  passing) is recorded here as the gate's evidence.
- `[Rule 1 - math-level]` The pre-scaling isometry guard's tolerance was widened from the
  plan's suggested `1e-9` to a measured `1e-6`: `topoae.pairwise_distances_f64` goes
  through `torch.cdist`'s formula-based computation
  (`||a||^2 + ||b||^2 - 2*a.b`, not a direct subtraction), which loses float64 precision
  proportional to operand magnitude. Measured on the exact standard 600-point ambient
  cloud: max abs difference between the pre-scaled and post-hoc-scaled distance matrices
  was `5.114129e-08` -- inside the widened `1e-6` bound and nowhere close to a real
  regression, but above the plan's suggested `1e-9` literal, which is unreachable through
  this sealed distance-computation path. No production code (`persistence_probe.py`)
  changed by this correction; only the test's assertion tolerance and its documenting
  comment did.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - math-level] Widened the pre-scaling isometry test's tolerance from 1e-9 to
a measured 1e-6**
- **Found during:** Task 2 (`test_prescale_is_an_isometry_up_to_uniform_scale`)
- **Issue:** The plan's behaviour bullet suggested `1e-9`-per-bar agreement between a
  pre-scaled and a post-hoc-scaled distance matrix; the first test run failed with a
  measured max abs difference of `5.114129e-08` -- an order of magnitude above `1e-9`.
- **Fix:** Investigated the source (`torch.cdist`'s internal formula loses float64
  precision proportional to operand magnitude, not a bug in `cloud_distance_matrix`),
  then widened the assertion to `1e-6` -- a real, still-tight regression bound
  (~20x the measured value) rather than a loosened "just pass" tolerance, with the
  measurement and its cause documented in the test's own docstring.
- **Files modified:** `notebooks/pu_manifold/tests/test_persistence_probe.py` only.
- **Verification:** Re-ran the full test file; all 13 tests pass, printed measured value
  `5.114129355904378e-08` matches the docstring's stated figure exactly.
- **Committed in:** `de685a3` (Task 2 commit).
