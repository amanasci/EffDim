## Tracer-first vs. freeze-before-any-number — resolved, not left implicit

D8-22 requires every Phase 8 constant to land in one freeze commit that is git-ancestry-proved to
precede **every measured value on PU**. A tracer that measured a PU number first would break the
phase's central discipline — the failure mode `02.2`'s sealed FAIL and
`06-PREREGISTRATION-AMENDMENT-01` both record.

**Resolution adopted:** the tracer runs entirely on **synthetic pairs whose CKA answer is known in
closed form** (D8-16's invariance ladder — orthogonal rotation and isotropic scaling give exactly
1.0 for linear CKA; independent columns give ≈0). It touches every layer this phase will ever touch
(estimator module → runner → record writer → printed pass/fail), so it is a genuine end-to-end
slice, and it opens no PU file, so no PU number exists before the freeze.

**Mechanism that keeps it honest:** every gating constant in `cka.py` is declared UNSET in this plan
(`None` for scalars, `()` for tuples, `""` for rule strings), exactly as Phase 5's tracer left
`linear_probe.py`'s constants UNSET across its pre-freeze interface restructure. `assert_preregistered()`
raises on every one of them here, and the commit that fills them (08-04) is the freeze commit. Every
pure function in `cka.py` therefore takes its parameters as explicit arguments — `sigma` is passed in,
never read from a module constant at a call site that only sees a subset (D8-03's named confound,
restated as an interface property).

Estimator functions, all pure, all taking their parameters explicitly:
- `_zero_diag(K)` returns a copy with the diagonal set to 0.0.
- `unbiased_hsic(K, L) -> float` — the Song et al. (2012) estimator exactly as written in
  RESEARCH.md §Pattern 1: on zero-diagonal copies of the RAW Gram matrices, `1/(n(n-3))` times
  `trace(K̃ L̃)` plus `(1ᵀK̃1)(1ᵀL̃1)/((n-1)(n-2))` minus `(2/(n-2)) 1ᵀK̃L̃1`. Raise `ValueError` when
  `n <= 3`, and raise `ValueError` on non-square, shape-mismatched, or non-finite input before doing
  any arithmetic — matching `mknn.py`/`density_stratified_null.py`'s validate-then-compute
  convention. **The inputs are raw Gram matrices with only the diagonal zeroed; the classical
  double-centering transform must never be applied before this correction** — doing so silently
  reproduces the biased estimator under the unbiased one's name, which is the exact trap D8-02 exists
  to avoid and which Task 2 pins with a behavioral test.
- `cka(K, L) -> float` = `unbiased_hsic(K, L) / sqrt(unbiased_hsic(K, K) * unbiased_hsic(L, L))`.
- `linear_gram(X, dtype) -> np.ndarray` = `X @ X.T` cast to `dtype`.
- `median_pairwise_distance(X) -> float` — median Euclidean pairwise distance over ALL rows of `X`;
  docstring states it is D8-03's sigma, computed once over all 10,000 points before any subset
  exists.
- `rbf_gram(X, sigma, dtype) -> np.ndarray` — `sigma` is a REQUIRED positional parameter with **no
  default**, so no call site that only sees a subset can silently supply a per-subset bandwidth
  (D8-03's named confound). Raise `ValueError` when `sigma <= 0` or is non-finite.
- `cka_on_subset(K_full, L_full, idx) -> float` — `K_full[np.ix_(idx, idx)]` / `L_full[np.ix_(idx, idx)]`
  then `cka`. Docstring states this is exact, not an approximation, because a kernel value depends
  only on the pair of points and never on which other points are in the batch — the Gram-matrix-once
  architecture RESEARCH.md §Runtime establishes as this phase's cost model.
Do not use SciPy's rank-transform helper anywhere in this module: CKA's inputs are the raw feature
matrices, not ranks (RESEARCH.md Pitfall 5).
