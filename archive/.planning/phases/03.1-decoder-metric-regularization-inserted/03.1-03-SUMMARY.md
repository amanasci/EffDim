**Anchor cell reproduces the sealed `d=20` saddle row's `rank_spearman_rho` with exact `==`, and a two-sided cost probe -- after fixing a truncation defect that had produced a false linearity verdict -- ratifies an 18-cell, 20-epoch ladder configuration against the 8-hour budget.**

## Accomplishments

- **Task 1 -- the faithfulness gate.** `anchor_check` calls `synthetic_control_run.run_one_control` unchanged and measures `rank_spearman_rho == -0.015106571347065712` **exactly** -- no tolerance, no `isclose`. This proves the new runner's imported fixture, matched-architecture builder, blocked trainer and metric call sequence are a faithful copy of the sealed protocol, not a re-derivation.

  **Machine-speed corrections**, the ratio of this run's fresh wall clock to the sealed reference: train `5637.547828624025 / 6253.836718825012 = 0.901454`; curvature `2920.6222927509807 / 2993.912286339997 = 0.975520`. Both ratios are below 1.0 -- this machine measured faster than the one that produced the sealed row, in both halves, consistently. That consistency is itself weak evidence against contamination by a co-scheduled job (a contaminated run would typically show one half slower, not both faster).

  **CURV-04's absolute metric scale for the sealed `d=20` saddle fit, on record for the first time:** `lambda_min median=9.448030e-07`, `lambda_max median=1.744437e+02`, `det_g median=1.654749e-23`, `log10_det_g median=-22.781268`.

  **The anisotropy-not-collapse finding.** `lambda_max = 174` is a healthy-scale eigenvalue; `lambda_min = 9.4e-07` is not. The geometric-mean eigenvalue is `10^(-22.78/20) ~= 0.073` -- a normal-scale metric with one direction crushed to near-zero, not a uniformly collapsed one. This is **seed 20260813's own signature**, and it is a different pathology from seeds 20260814/20260815's `~1e-07`-everywhere collapse (`det(g) ~ 1e-162`, every eigenvalue small, not just one).

  **Reading rule for wave 4 (03.1-04/05):** `christoffel`'s target field is `cond(g)` with `lambda_max` not falling -- `christoffel` is the arm aimed at the pathology this fixture actually has (one crushed direction driving a large condition number). `scale`'s penalty `(log det g / d)^2` has something to bite on (`(-22.78/20)^2 ~= 1.30`, well off its zero target), but the saddle only mildly exhibits the uniform-collapse signature `scale` is designed to fix. **If the `scale` arm moves nothing in the ladder, that is a fixture-selection result -- this fixture's pathology is not `scale`'s target pathology -- not a flat null against `scale` as a mechanism.** D-02 remains locked: both arms still run regardless of this reading rule.

- **Task 2 -- the two-sided cost probe, with a defect found and fixed.**

  **The defect.** `PROBE_EVAL_SIZES` was originally declared `(1000, 2000, 4000)`. The `pu._split` holdout is only `2000` rows (`n=10000, PU_HOLDOUT_FRACTION=0.2`), so `x_eval_base64[:4000]` silently returned the same `2000` rows already measured at `eval_size=2000` -- an identical-cost measurement recorded under two different labels. That produced a fake `curv_s_per_row = 0.148627` at the mislabeled `eval_size=4000` and a false `EVAL COST IS NOT LINEAR IN ROW COUNT` verdict (a spurious `2.06x` span).

  **The fix.** `probe()` now raises `ValueError` naming the requested size and the actual holdout size rather than silently truncating, and `PROBE_EVAL_SIZES` is corrected to `(500, 1000, 2000)`, all of which fit inside the 2000-row holdout.

  **The corrected re-run** (`--probe-skip-train`, reusing Half A's costly `scale`/`christoffel` training from the first run and re-training only `weight=0` fresh, since the defect was Half-B-only):
  ```
  Half B: pu._split holdout = 2000 rows (PU_HOLDOUT_FRACTION=0.2, n=10000)
    eval_size=500   per_row=0.317721   n_charts_used=3
    eval_size=1000  per_row=0.311734   n_charts_used=3
    eval_size=2000  per_row=0.306350   n_charts_used=3
  EVAL COST IS APPROXIMATELY LINEAR IN ROW COUNT (A2 CONFIRMED) -- varies only 1.04x
  ```
  **A2 (evaluation cost is approximately linear in row count) is CONFIRMED, not refuted** -- the original "NOT LINEAR" verdict was an artifact of the truncation defect, not a real measurement, and is superseded rather than quietly overwritten.

  **The mixed-source multiplier caveat.** This corrected run's fresh `weight=0` measured `18.5946` s/epoch, against the first run's `17.4357` s/epoch -- a `6.6%` run-to-run variance on the same cell type at the same architecture. Meanwhile the `scale` (`29.8536` s/epoch) and `christoffel` (`82.4458` s/epoch) numerators were **reused from the first run**, not re-measured here. The projection uses each mode's own absolute s/epoch rate directly (not a multiplier relative to a shared baseline), so **sizing itself is unaffected** by this mix. But any *multiplier* quoted from this run (e.g. "scale costs Nx weight=0") mixes a fresh denominator against reused numerators from a different run -- stated here so it is not read as a single coherent measurement.

  **The `n_charts_used` 3-vs-4 caveat.** Every probe model is a 3-epoch fit and populates `n_charts_used=3`, versus the anchor's full 300-epoch fit at `n_charts_used=4`. If curvature-evaluation cost tracks chart count, real ladder cells cost roughly `1.3333x` more per row than the probe measured. This is **not folded into the base projection** -- it is carried as an explicit, separately-computed **caveat-adjusted** figure: extrapolated `n=10000` from the largest measured per-row cost is `3177.2s` (vs sealed `2993.9s`, `6.1%` off; vs the fresh anchor `2920.6s`, `8.8%` off), and at `max_epochs=20` the caveat-adjusted total is **`27839.2s` (`7.73h`)** against `LADDER_BUDGET_S=28800` (`8.00h`).

  **The projection and relief cascade.** `apply_relief_ladder` walked F1 (rungs 3->2) then F2 (`LADDER_EVAL_N` 2000->1000), and the resulting configuration fit the budget without needing F3 or F4:
  ```
  chosen_max_epochs = 20  relief_applied=['F1','F2']  projected_total_s=25932.9
  ```

- **Task 3 -- the sizing checkpoint, resolved.** Ratified: `chosen_max_epochs = 20`, `relief_applied = ['F1', 'F2']`, 18 cells, `~7.2h` projected / `~7.73h` caveat-adjusted. **F4 was never reached -- D-07's fence held, no override was granted.**

  **The 20-vs-300 epoch limitation, stated plainly.** `chosen_max_epochs = 20` against the anchor's sealed `300`-epoch protocol is a `15x` protocol gap. Phase 3 established that this architecture never plateaus even at 300 epochs (best epoch was the last epoch trained), so every ladder cell in 03.1-04 measures decoder priors on a deliberately undertrained fit. This is the **initial** epoch-count choice -- ordinary Claude's-Discretion under `03.1-01`'s own framing, **not** F4's forbidden overrun-response cut -- so it violates no locked decision, but it is carried forward as a stated limitation into `03.1-05`'s findings, not silently absorbed.

## Decisions Made

- Anchor comparison is raw `!=` against the module constant `ANCHOR_RHO_SPEARMAN`, never `isclose`/`allclose`/a tolerance parameter -- a drifted fixture, protocol or metric call sequence must fail loudly rather than pass approximately.
- The probe's evaluation-size defect (silent truncation past the holdout) is fixed by raising rather than clamping -- a probe that silently produces a shorter, duplicate measurement is worse than one that crashes, because the crash is visible and the duplicate measurement looked like real evidence.
- F4 is gated behind `confirm_f4_override` defaulting to `False` and reachable only via the explicit `--confirm-f4-override` flag; this plan's ratified run never sets it, so no cell in `03.1-04` will carry the F4 override label.
- `christoffel` is read as the arm aimed at this fixture's actual pathology (anisotropic collapse); `scale`'s null result, if it occurs, is pre-declared to be read as a fixture-selection finding rather than a flat null against the mechanism -- stated here, before any ladder cell has run, so it cannot be read as a post-hoc rationalization later.
