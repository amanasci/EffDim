Add three functions to `notebooks/pu_manifold/curvature_probe.py`.

`quadric_fit_curvature(u, z, d)` — RESEARCH.md Pattern 2's function, with one correction. Pattern 2's
example builds the design matrix with a constant column, `d` linear columns, and `d(d+1)/2`
quadratic columns `u_i*u_j` for `i <= j`, solves by `np.linalg.lstsq`, and then reads the trace
off the diagonal terms with `factor = 2.0` when `i == j`. That factor is correct — for a fitted
term `c_ii * u_i^2` the Hessian entry is `2*c_ii` — but Pattern 2's snippet applies the factor
inside a branch that also guards `if i == j`, making the off-diagonal `factor = 1.0` assignment
dead code. Write it without the dead branch: accumulate `H += 2.0 * c` over the `i == j` columns
only, and state in the docstring that off-diagonal coefficients contribute nothing to the trace by
construction. Returns the `(m,)` mean curvature vector in normal coordinates, under this module's
trace convention.

Never add `rcond` tuning, a ridge term, or a low-rank truncation. Call `np.linalg.lstsq(A, z,
rcond=None)` exactly. D-05 rejected quadric-with-regularization precisely because the
regularization strength would become a blind pre-registered dial; the docstring must say so.

`quadric_mean_curvature(X, k, d)` — the per-point wrapper, returning a dict with `"H_vec"`
`(n, D)`, `"H_norm"` `(n,)`, `"underdetermined"` `(bool)`, `"n_coefficients"` `(int)`, and
`"coefficient_deficit"` `(int)`. Per point: k-NN, `local_tangent_basis` for the `(d, D)` tangent
frame, project the centered neighbours onto tangent coordinates `u = centered @ Vt.T` `(k, d)` and
normal coordinates `z = centered - u @ Vt` expressed in a normal frame, then call
`quadric_fit_curvature`. Set `n_coefficients = d*(d+1)//2`, `coefficient_deficit = max(0,
n_coefficients - k)`, `underdetermined = n_coefficients > k`. Its docstring's first line must
state that this estimator is **non-gating** under D-05 and must name the reason: the
`d(d+1)/2`-vs-`k` count the ROADMAP re-scope describes is real *for this estimator* and does not
transfer to `centroid_mean_curvature`, which estimates one unknown averaged over `k` vectors. Do
not raise when underdetermined — return the value with the flag set, because the *contrast*
between a determined and an underdetermined quadric across the `d` ladder is exactly the evidence
D-00's reframing needs to be reported alongside.

For the normal-frame construction, avoid materializing a `(D, D-d)` basis at `D = 768`: keep the
normal residual as the ambient `(k, D)` vector `centered - u @ Vt` and fit the quadric with `z`
being that full ambient residual. The fitted mean curvature vector then lives in ambient
coordinates directly and needs no back-transformation. Note this deviation from Pattern 2's
`(k, m)` normal-coordinate formulation in the docstring — it is an efficiency choice, not a
mathematical one, and the two are equivalent because the tangential part of the residual is
identically zero by construction.

`estimator_agreement(h_centroid_norm, h_quadric_norm)` — returns a dict with
`"agreement_spearman"` (rank agreement between the two estimators' `||H||` fields) and
`"agreement_median_rel_diff"` (`median(|a - b| / max(|a|, |b|, floor))`). CONTEXT.md leaves the
quantification and the block-or-report question to Claude's discretion: **resolve it as report,
never block.** Rationale, to be stated in the docstring: the two estimators have different bias
mechanisms, so at the underdetermined end of the `d` ladder they are *expected* to diverge, and a
blocking rule would convert an expected, informative divergence into a spurious failure. The
divergence is reported in the stage-1 verdict artifact's non-gating `context_metrics` block
(plan 02.5-04) and discussed in `02.5-FINDINGS.md`.

Add `test_quadric_cross_check_and_underdetermination`: (a) on a `d=2` sphere of radius 1.5 with
`k=30`, assert `quadric_mean_curvature`'s median `||H||` is within 15% of `d/R`, that
`underdetermined` is False, and that `estimator_agreement` against the centroid estimator gives
`agreement_median_rel_diff < 0.25`; (b) at `d=20, k=15` on a graph-of-function fixture, assert
`underdetermined` is True, `n_coefficients == 210`, and `coefficient_deficit == 195`. Comment on
(b) that this is the count the ROADMAP re-scope calls "badly underdetermined" and that it is a
property of *this* estimator, which is why D-05 keeps it non-gating.
