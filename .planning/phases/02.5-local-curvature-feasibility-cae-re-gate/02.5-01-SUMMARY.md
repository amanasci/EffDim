## Decisions Made

- **Trace convention (`H = tr(II)`) used everywhere**, per the plan's own OQ-CONV resolution — matches `curvature.py`'s stub docstring and RESEARCH.md's Pattern 1/4 derivations, not RESEARCH.md's `swiss_roll_analytic_H` code sample (which was the averaged form, /2 too small, and is deliberately NOT what got implemented)
- **Rule 1 auto-fix of the estimator's scale constant.** `02.5-RESEARCH.md`'s Pattern 1 example and this plan's Task 1 action text both specify `H[i] = gap_normal * (2*(d+2)/r2)`, treating `r2 = mean(||centered||^2)` as if it were already the tangent ball's outer radius squared. It is not: for `u` uniform in a `d`-ball of radius `r`, `E[|u|^2] = d*r^2/(d+2)`, so `r2` (the code's actual quantity) equals `d*r^2/(d+2)`, not `r^2`. Substituting and solving for `H` gives `H = (2*d/r2)*gap`, not `2*(d+2)/r2`. Confirmed by an exact (noise-free) symmetric-neighbourhood construction on a unit `d`-sphere at `d` in `{2,3,5,8}`: the uncorrected constant returns `H=d+2` in every case; the fix returns exactly `H=d`. Task 1's tracer test could not have caught this — Spearman rank correlation is invariant to any positive monotonic rescaling of the estimator's output; only Task 2's absolute-magnitude known-answer fixture (`test_centroid_estimator_known_curvature`) surfaced it.
- **Interactive tracer-feedback checkpoint.** Auto mode was not active (`workflow._auto_chain_active=false`, `workflow.auto_advance` unset). Per the tracer execution protocol, execution stopped immediately after committing Task 1 and returned a `checkpoint:human-verify` presenting the tracer's result (Spearman rho=0.5806, all Task 1 acceptance criteria independently re-checked). User replied "approved"; execution resumed at Task 2.
- **Sphere-scaling test's per-dimension sample size.** `test_curvature_convention_is_trace_not_averaged`'s `d=5` sphere check needed more points (`n=15000` vs `d=2`'s `n=3000`) at the same `k=30` to keep finite-radius bias from eating the required `d=5 median >= 2 * d=2 median` margin — not specified by the plan, chosen empirically to make the test robust rather than flaky.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Corrected `centroid_mean_curvature`'s scale constant**
- **Found during:** Task 2 (`test_centroid_estimator_known_curvature`, the sphere fixture)
- **Issue:** The estimator, implemented per the plan's own Task 1 action text (itself copying `02.5-RESEARCH.md`'s Pattern 1 example verbatim), used `H[i] = gap_normal * (2*(d+2)/r2)`. This conflates the empirical local second moment `r2 = mean(||centered||^2)` with the tangent ball's outer radius squared `r^2` from the derivation `E[c-p] = (r^2/(2(d+2)))*H` — but `r2` actually equals `d*r^2/(d+2)` for points uniform in a `d`-ball, not `r^2` itself. The uncorrected estimator recovered `H=d+2` instead of `H=d` on a unit sphere (e.g. 4 instead of 2 at `d=2`, an 100% relative error at `d=2` and growing worse as `d` shrinks relative to the fixed `+2`).
- **Fix:** Changed the constant to `2*d/r2`. Confirmed exact (zero numerical noise) on a symmetric-neighbourhood unit-sphere construction for `d` in `{2,3,5,8}`.
- **Files modified:** `notebooks/pu_manifold/curvature_probe.py`
- **Verification:** `test_centroid_estimator_known_curvature` (flat plane and sphere), `test_curvature_convention_is_trace_not_averaged` (sphere `d`-scaling check), and the standalone exact-construction check documented in the function's docstring all pass with the fix; `test_tracer_swiss_roll_end_to_end` (Task 1, rank-only) is unaffected either way, as expected for a scalar rescaling.
