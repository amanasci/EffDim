## Accomplishments

- `STAGE1_GATING_METRICS = ("spearman_rho",)`, `STAGE2_GATING_METRICS = ("chart_vs_raw_margin", "seed_spread")`, `GATE_DIRECTIONS` mapping each gate name to `"greater"` or `"less"`, and `STAGE1_VERDICT_RULE`/`STAGE2_VERDICT_RULE` prose strings stating each stage's exact PASS condition and D-12's PASS/FAIL routing
- `_apply_gates(metrics, thresholds, gate_names, rule_name)`: one guard-first, direction-aware comparison function. Guards (in order): gate absent from `metrics`, gate value non-finite (`math.isfinite`), gate absent from `thresholds`, gate absent from `GATE_DIRECTIONS` -- each raises `ValueError` naming the gate (and, for non-finite, its value) before any comparison runs. Then compares per-gate direction (`greater`: `value > threshold`; `less`: `value < threshold`), both strict
- `verdict_from_stage1_metrics` / `verdict_from_stage2_metrics`: thin wrappers over `_apply_gates` with each stage's own gate tuple; the strict comparison lives only inside `_apply_gates`, never re-implemented at either call site
- `write_curvature_verdict(key, stage, metrics, thresholds, verdict, extra=None)`: recomputes `(computed_verdict, gate_detail)` internally via the stage's own verdict function and raises `ValueError` if it disagrees with the caller's `verdict` argument; thresholds live inside the `json_cache` cfg dict so an edited threshold raises `cache._manifest_matches`'s mismatch error on re-call; payload includes `gating_metrics`, `gate_directions`, `metrics`, `thresholds`, `gate_detail`, `verdict_rule`, `curvature_convention`, an additive `gate_scope: {"value": "local", ...}` annotation (following 02.4-07's precedent), and `context_metrics` when `extra` is supplied; every value passes through `cae.to_native` (the module's only dependency on `cae.py`, imported lazily inside the function)
- `write_curvature_handoff(key, verdict, payload)`: raises `ValueError` unless `verdict == "PASS"`; raises `ValueError` naming any of 12 required full-estimator-contract keys (`substrate`, `working_dimension`, `neighbourhood_rule`, `density_correction`, `estimator_variant`, `cache_stems`, `fit_key`, `gate_values`, `thresholds`, `evidence_criteria`, `preregistration_sha`, `activation`) absent from `payload`; reads `torch_version` via a function-local lazy `import torch`, falling back to `"not-installed"` on `ImportError`, so the module's numpy-only posture is preserved
- `clear_stale_curvature_handoff(key)`: unlinks both `curvature_handoff_{key}.json` and its `.meta.json` sidecar when present, returns `True` if anything was removed and `False` otherwise, never raises when nothing is there

## Decisions Made

- **OQ-4 (mirror, not import).** `write_topoae_verdict` hard-codes the stem `topoae_verdict_{fit_key}` and `cfg["phase"] = "02.4"`; `write_topoae_handoff` hard-codes `representation_id = "topoae"` and a coordinate-producing payload schema. Neither is parameterized by phase or stem, so importing them would either write 02.5 results under 02.4-tagged stems or require editing a sealed phase's artifact. `curvature_probe.py`'s three writers reimplement the same PASS-always/handoff-PASS-only/stale-actively-deleted contract at 02.5-scoped stems (`curvature_verdict_stage{stage}_{key}`, `curvature_handoff_{key}`); `topoae.py` is never edited, never generalized, never called (`grep -c 'write_topoae_verdict\|write_topoae_handoff\|clear_stale_handoff' curvature_probe.py` returns 0).
- **OQ-5 (no delegation into `cae.verdict_from_metrics`).** `topoae.py`'s `CAE_SLOT_ALIASES` positional remap requires both tuples to have exactly three entries; stage 1 has one gating metric, stage 2 has two -- no such remap exists at either count. `cae.verdict_from_metrics` also applies strict less-than uniformly to every gate, while `spearman_rho` and `chart_vs_raw_margin` are greater-than gates; delegating would require sign-flipping the metric before handoff, inserting an opaque transform between measurement and the tested comparison. `_apply_gates` implements its own guard-then-compare discipline instead, with an explicit `GATE_DIRECTIONS` map. `cae.GATING_METRICS` is never monkeypatched (`grep -c 'cae_mod.GATING_METRICS\|cae.GATING_METRICS' curvature_probe.py` returns 0).
- **Thresholds inside the cache cfg dict.** `write_curvature_verdict`'s `cfg = {"key": key, "phase": "02.5", "stage": stage, "thresholds": thresholds}` puts thresholds inside the manifest cache key, so `test_threshold_edit_raises_manifest_mismatch` confirms editing a threshold after the fact raises `cache._manifest_matches`'s mismatch `ValueError` on the next call with the same `key`/`stage`, rather than silently re-verdicting.
- **`torch_version` read lazily inside `write_curvature_handoff` only**, never at module level, so `curvature_probe.py` keeps its numpy-only import posture even though the handoff payload (which names a Phase 3-facing estimator contract, potentially trained via torch) needs to record which torch version produced the fit it's handing off. Falls back to `"not-installed"` on `ImportError` rather than raising.
- **`gate_scope` additive annotation** (`{"value": "local", "reason": "..."}`) included in every `write_curvature_verdict` payload, following the precedent plan 02.4-07 set by adding the same annotation to its own sealed verdict artifact after the fact -- here it is included from the start, since every gate in this phase is local-scoped by design (there is no global-scoped gate in 02.5 to distinguish it from).
