## Decisions Made

- **`global_std` computed on the unpadded local embedding, before padding/rotation.** A literal reading of the plan's action text (embed -> pad -> rotate -> centre/scale) would compute the CLAUDE.md global scalar `std()` on the full padded `(n, D)` array, whose flattened-array `.std()` depends on how many exact-zero columns were added -- this would make padding change the reported (rescaled) `H_norm`, directly breaking the plan's own required bit-identical-padding test. Computing `global_std` on the intrinsic `(n, d+n_bumps)` embedding first makes padding a true no-op on every returned quantity, including scale.
- **`apply_rotation` (internal, undocumented-in-plan-signature) parameter added to `make_graph_of_function_fixture`.** Required to obtain bit-identical `H_norm` between the `D=3` and `D=768` configurations in `test_graph_fixture_padding_and_codimension` -- with rotation enabled, the rotation matrix is drawn at size `(D, D)` and differs between configurations, reintroducing floating-point noise unrelated to the padding property under test. Defaults to `True` so normal fixture usage is unaffected.
- **Error message field order for `D < d + n_bumps`** reordered to `d=..., n_bumps=..., D=...` (rather than a more natural English "D is too small for d + n_bumps") specifically so the acceptance criterion's regex (`d=.*n_bumps=.*D=`) matches.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - math-level bug in the plan text, discovered and resolved during Task 2] D-06's flat-fixture test premise is mathematically impossible for the shipped estimator**

- **Found during:** Task 2, while writing `test_density_correction_removes_bias` as literally specified (`make_flat_fixture(density_skew=3.0)`, expect uncorrected `median(||H||)` "well above numerical noise" and corrected at least 5x smaller).

- **Issue:** Empirically, `centroid_mean_curvature` on this exact fixture at the plan's own worked-example parameters (`density_skew=3.0`) reported `median(||H||) ~ 4.7e-14` for BOTH the corrected and uncorrected estimator -- floating-point noise, not "well above numerical noise" as the plan required. This was reproduced at multiple skew levels and multiple `k`/`n` configurations; the ratio between skewed and noise-floor stayed pinned at the float64 precision level throughout.

  Confirmed analytically, in two independent ways:
  1. **Exact-rank-`d` degeneracy.** `make_flat_fixture`'s point cloud is an EXACTLY linear embedding (all bump amplitudes zero): every neighbour of every point lies, to floating-point precision, exactly on a single `d`-dimensional affine subspace. `local_tangent_basis`'s SVD of such a matrix has its remaining singular values at the float64 noise floor (~1e-16 relative), REGARDLESS of how the rows (neighbour points) are distributed or weighted within that subspace (confirmed directly: `np.linalg.svd` on a synthetic exactly-rank-2 matrix in `R^10` gives singular values `[8.96, 4.46, 6.6e-16, ...]`). Since the recovered tangent basis is therefore EXACT, any centroid displacement -- weighted or unweighted -- computed from points confined to that exact subspace ALSO lies exactly in that subspace, so `centroid_mean_curvature`'s normal projection (`gap - Vt.T @ (Vt @ gap)`) removes it completely. This generalizes plan 02.5-01's own Pitfall-3 regression guard (`test_tangential_perturbation_does_not_leak_into_H`) to this density model: it is not merely a property of that plan's specific reparametrized-axis construction, it is a general property of any exactly-flat linear embedding.
  2. **Log-linear density model.** The plan's specified density tilt, `w(x) = exp(density_skew * <x,u> / domain_radius)`, has `log(w(x))` EXACTLY LINEAR in `x`. A first-moment (Taylor-expansion) derivation for a `d`-ball with a linear density perturbation shows the perturbation shifts the tangential first moment `E[x]` but leaves the SECOND moment `E[x^2]` (the quantity `r2`, and hence the curvature-detection channel) UNCHANGED to leading order -- an odd density correction integrates to zero against the even `x^2` kernel over a symmetric domain. This holds for this specific density model at ANY skew magnitude, not just to leading order, since `log(w)` is EXACTLY linear (not merely approximately so for small skew).

  Both findings were cross-checked against extreme parameter regimes (`density_skew` up to 8.0, `realized_skew` up to ~1200) to rule out the possibility that a stronger skew would eventually surface the plan's expected effect; at that extreme, floating-point conditioning artifacts from severe point clustering did produce large spurious `||H||` values (`~7.8`), but these were confirmed to be numerical-conditioning noise (present identically in the corrected estimator, `~8.2`, i.e. NOT something the correction addresses), not the geometric mechanism the plan described.

- **Fix:** `test_density_correction_removes_bias` was redesigned in two parts. Part A proves the finding directly: on the flat, strongly-skewed fixture, BOTH corrected and uncorrected `median(||H||) < 1e-8` (float64 noise floor) -- a positive, provable robustness result, not a failure to demonstrate D-06. Part B demonstrates the correction's REAL mechanism and effect size: density bias can only leak past an exact normal projection when the tangent basis is itself imperfectly estimated, which requires genuine curvature to exist at all. On a curved, strongly-skewed fixture (`amplitude=3.0, sigma=0.4, density_skew=5.0`), the corrected estimator's median relative error against the known analytic `H` is consistently and measurably ~8-10% lower than the uncorrected estimator's (`err_corrected < 0.95 * err_uncorrected`, comfortably inside the observed ~0.90-0.92 ratio across several parameter regimes tested). `local_density_weights` itself was independently sanity-checked (weights correlate strongly, `r=0.69`, with the actual PCA-recovered skew-axis position, confirming the density estimator is measuring what it claims to).

- **Files modified:** `notebooks/pu_manifold/curvature_probe.py` (`make_graph_of_function_fixture`/`make_flat_fixture` docstrings document the finding; no change to the density-correction formula itself, which is implemented exactly as the plan specifies -- weight centroid and `r2`, leave the tangent basis and `2*d/r2` scale constant unchanged), `notebooks/pu_manifold/tests/test_curvature_probe.py` (`test_density_correction_removes_bias` rewritten around the proven mechanism).
