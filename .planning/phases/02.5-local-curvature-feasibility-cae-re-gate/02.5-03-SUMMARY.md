## Decisions Made

- **`quadric_fit_curvature`'s trace accumulation rewritten without Pattern 2's dead branch.** RESEARCH.md's own example applies a `factor = 2.0 if i == j else 1.0` assignment inside a branch that already guards `if i == j`, making the `factor = 1.0` (off-diagonal) assignment unreachable dead code. Implemented instead as `H += 2.0 * c` accumulated only over the `i == j` columns, with no branch that ever touches an off-diagonal coefficient, and the docstring states off-diagonal coefficients contribute nothing to the trace by construction.
- **No shrinkage/tuning dial anywhere near the quadric fit.** `np.linalg.lstsq(A, z, rcond=None)` is called exactly as specified; the file-wide negative grep for `ridge|alpha_reg|lambda_reg|regulariz|rcond=[0-9]` returns 0, confirmed after every task.
- **`estimator_agreement`'s floor** (`1e-3 * median(max(|a|,|b|))` elementwise) mirrors `median_relative_error`'s own near-zero-denominator guard, so a point where either estimator reports near-zero `||H||` cannot blow the agreement ratio to `inf`.
- **`permutation_null`'s statistic** is a plain `(x, y) -> spearmanr(x, y).statistic` closure (no `axis` parameter), matching RESEARCH.md's own Code Example and letting `scipy.stats.permutation_test` auto-detect non-vectorized mode without any extra `vectorized=` argument.
- **`measure_cell`'s `null_` key-prefixing** only prefixes keys that do not already start with `null_` (`null_quantile`/`null_threshold`/`null_mean`/`null_std` pass through unchanged; `observed_rho`/`n_resamples`/`seed`/`clears_null` from `permutation_null`'s own return dict become `null_observed_rho`/`null_n_resamples`/`null_seed`/`null_clears_null`), exactly as the plan's action text specifies -- note `measure_cell`'s top-level `"seed"` key is the same numeric value as `"null_seed"` but is a separate, intentional echo of the caller's argument, not a duplicate bug.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `quadric_mean_curvature` needed its own tangent-basis extraction, not `local_tangent_basis`**

- **Found during:** Task 1, while writing `test_quadric_cross_check_and_underdetermination` case (b) (`d=20, k=15`, exactly as the plan's own acceptance criteria specify).
- **Issue:** The plan's action text says to build the tangent frame "via `local_tangent_basis`" for `quadric_mean_curvature`, the same helper `centroid_mean_curvature` uses. `local_tangent_basis` deliberately hard-raises whenever `d > min(k, D)` (a guard from plan 02.5-01, itself correct and tested for the gating estimator's use). But `d=20, k=15` is exactly `d > k`, so calling `local_tangent_basis(centered, d=20)` on a `(15, D)` neighbourhood always raises `ValueError` -- which would make it impossible for `quadric_mean_curvature(X, k=15, d=20)` to ever return the required dict (`underdetermined=True, n_coefficients=210, coefficient_deficit=195`), directly contradicting Task 1's own stated acceptance criterion ("`quadric_mean_curvature(X, k=15, d=20)` on any fixture returns a dict...").
- **Fix:** Added `_quadric_tangent_basis(centered, d)`, using `np.linalg.svd(centered, full_matrices=True)` instead of `local_tangent_basis`'s `full_matrices=False`. This always returns exactly `d` rows for any `d <= D`: when `d <= k` the top-`d` singular vectors are numerically identical to `local_tangent_basis`'s output (confirmed to float64-epsilon agreement via a direct interpreter check); when `d > k`, the extra rows are an arbitrary orthonormal completion of the neighbourhood's null space, along which every neighbour's centered coordinate is exactly zero -- `quadric_fit_curvature`'s least-squares fit then handles those all-zero design-matrix columns as ordinary rank deficiency (a minimum-norm solution), not a special case. `local_tangent_basis` itself, and its use inside `centroid_mean_curvature`, is completely untouched.
- **Files modified:** `notebooks/pu_manifold/curvature_probe.py` (new private helper only; no existing function's signature or behavior changed).
- **Verification:** `test_quadric_cross_check_and_underdetermination` case (a), which exercises the well-determined `d=2, k=30` path, still passes unchanged (proving the `d <= k` route is unaffected); case (b) (`d=20, k=15`) now completes and returns `underdetermined=True, n_coefficients=210, coefficient_deficit=195` as required; the full package suite (129 tests, including every `local_tangent_basis`/`centroid_mean_curvature` test from plans 02.5-01/02) remains green.
- **Committed in:** `0a061e2` (Task 1 commit)
