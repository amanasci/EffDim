# Note — persistent homology as a CAE faithfulness measure on the PU embeddings

**Status:** proposal, recorded for plan 02.5-10 (the stage-2 pre-registration) to accept,
reshape, or decline. **Gates nothing as written.** Raised by the user 2026-08-09, during
02.5-09's execution. Timing matters: 02.5-10 is the LAST point this can enter stage 2, because
02.5-11 measures under whatever 02.5-10 seals and D-10/D-11 bar adding a statistic afterwards.

## 1. The proposal

Estimate persistent homology of the ORIGINAL PU embedding point cloud, then ask how well the
CAE preserves it. This measures whether the CAE is a faithful model of the manifold at all — a
question orthogonal to everything stage 2 currently gates on.

It is a genuine gap. Stage 2's gating metrics are `chart_vs_raw_margin` and `seed_spread`, both
curvature-comparison quantities. **Nothing in the current stage-2 design checks topological
faithfulness.** A 16-chart decoder can tear the manifold or merge distant regions while local
curvature still looks reasonable at every individual point.

It is also the right fixture for it. `02.5-09`'s Swiss roll is contractible (`H0 = 1`,
`H1 = 0`) — persistence has nothing to detect there, which is why it is not part of that
notebook. The PU embeddings have unknown topology, so there is something to measure.

## 2. Two hard constraints found on inspection, both load-bearing

### 2a. The repo's existing persistence machinery is H0 ONLY

`topoae.py:persistence_pairs(D)` computes the minimum spanning tree edge set — 0-dimensional
persistence, the Moor et al. TopoAE formulation. It captures connected-component merge
structure. **It cannot see loops or voids.**

For "does the CAE preserve the topology of the embedding cloud", `H1` is usually where the
interesting answer is: a decoder that fills in a hole, or opens one, is exactly the failure this
check exists to catch, and `H0` is blind to it. An `H0`-only faithfulness result would be worth
reporting but must not be described as a topology check without that qualifier stated.

### 2b. No persistence library is installed, and adding one is BARRED this milestone

Checked in the project venv: `ripser`, `gudhi`, `persim`, `giotto-tda` all **absent**. Only
`scipy.sparse.csgraph` is available, which gives MST (`H0`) and nothing higher.

`CLAUDE.md` bars modifying `pyproject.toml` during the v1.1 milestone, so adding a persistence
library as a project dependency is not available. Three honest options, none free:

1. **`H0` only, using the existing tested `persistence_pairs`.** Available today, zero new
   dependencies, zero new untested code. Weakest of the three, and its limitation must be
   stated in the read-out rather than buried.
2. **Install a library into the venv without touching `pyproject.toml`.** Gets `H1`, but the
   result is then not reproducible from the repo alone — which is the property every gated
   artifact in this milestone has been built to have. Would need explicit user sign-off, and
   the reproducibility gap named in the pre-registration.
3. **Implement `H1` Vietoris-Rips persistence in-repo.** New, untested, non-trivial numerical
   code that would itself need a known-answer fixture (a torus and an annulus, whose diagrams
   are known in closed form) before any result from it could be trusted. That is a plan-sized
   piece of work, not a task-sized one.

**Recommendation: option 1 for stage 2, with the `H0`-only limitation disclosed**, and option 3
scoped as its own plan if `H1` turns out to matter. Do not quietly do option 2.

## 3. Design, if it is adopted

### 3a. What to compare

Three diagrams, not two:

    D_orig    persistence of the original PU embedding cloud       (n=10_000, D=768)
    D_recon   persistence of the CAE reconstruction, ambient space (same n, same D)
    D_latent  persistence of the chart/latent coordinates          (chart_dim=20)

`D_orig` vs `D_recon` asks whether the decoder distorts the manifold. `D_orig` vs `D_latent`
asks whether the CHART COORDINATES preserve structure — a different and arguably more
interesting question, since that is the representation Phase 3/4 would consume.

### 3b. The calibration problem, which is the whole design

**A bottleneck or Wasserstein distance between two diagrams is meaningless without a scale.**
This is the same lesson stage 1 already paid for: `quantile_bin_concordance = 0.4444` only
became interpretable once it had a null and a floor derived from something external.

The natural null here is the data's own resampling spread. Subsample the ORIGINAL cloud twice
independently and compute the bottleneck distance between those two diagrams. That distance is
what "same topology, different sample" looks like. Then:

    faithful  iff  d_bottleneck(D_orig, D_recon)  <=  the null spread of
                   d_bottleneck(D_orig_subsample_A, D_orig_subsample_B)

If the CAE's distortion is inside the noise the original data shows against itself, it is
faithful at the resolution available. If it is outside, it is not. This is a real threshold
derived from measurement rather than a number chosen because it sounded strict.

`subsample.py` already exists and is read-only-safe to use for the draws.

### 3c. Baselines, mirroring the phase's own discipline

- `cae.PlainAutoEncoder` at the same bottleneck — the matched control.
- The 02.4 TopoAE — it optimizes 0-dimensional topological preservation DIRECTLY, so it should
  win on `H0`. **If it does not, something is wrong with the measurement, not with the TopoAE.**
  That makes it a known-answer check on the metric itself, which is worth more than its value
  as a competitor.

### 3d. Scale

Full Vietoris-Rips at `n = 10_000` is not feasible. Subsample to ~1000-2000 points and repeat
over independent draws — which produces 3b's resampling null as a by-product rather than as
extra work. Report across draws, never from one.

## 4. What this does NOT do

It does not substitute for the amplitude checks in `02.5-NOTE-randomized-trace.md` Addendum C,
and the two must not be conflated. **Persistent homology is invariant to exactly the deformation
those checks exist to catch.** A decoder learning `y = 0.7 a x^2` where the truth is
`y = a x^2` has an IDENTICAL persistence diagram — same components, no holes created or
destroyed, a smooth isotopy — while attenuating curvature by 30%. Its stability under small
metric perturbation is the theorem that makes persistence useful, and it is precisely why it
cannot see amplitude.

The two measure different things and both are needed:

| check | catches | blind to |
|---|---|---|
| persistence agreement | tearing, merging, holes created or filled | curvature amplitude, smooth distortion |
| amplitude / calibration slope | attenuated or inflated curvature | topology violations |
| rank statistics (Spearman, qbc) | ordering failures | BOTH of the above |

## 5. Open question this raises, not resolved here

Phase 02.4 built and evaluated a **TopoAE** — a model whose entire purpose is topological
faithfulness — and stage 2's Arm B uses the plain **CAE** instead. Whether that choice was made
on measured evidence or inherited by default is not established in this note, and it should be
checked before 02.5-10 seals, because "use the model that already optimizes the property we are
about to start measuring" is a live alternative that the stage-2 design does not currently
consider.
