<objective>
Build the whole Phase 5 machine, wired end to end and proven on a synthetic case with a known
answer, while it is still structurally impossible for it to produce a PU probe number.

Purpose: this phase's entire evidential value rests on one ordering property — the rule was frozen
before the numbers existed (D5-09). The cheapest way to guarantee that is to make the bucketed path
*dead* until the freeze: the constants ship unset, `assert_preregistered()` raises on them, and the
runner's `--mode bucketed` branch calls it before touching anything. That guard is not documentation
here, it is the live state of the repository at the end of this plan.

`notebooks/pu_manifold/tests/test_linear_probe.py` (the Wave 0 test gaps from `05-VALIDATION.md`),
`notebooks/diagnostics/curvature_probe_decodability_run.py` (`--selfcheck`, `--mode field`,
`--mode pool`, `--mode bucketed` guard, `--smoke`), and one verdict row in
`notebooks/.cache/05_probe_selfcheck.jsonl` from planted synthetic data.

**Why the tracer runs on synthetic data and not on PU.** The orchestrator's natural tracer would
resolve the subsample, extract a small curvature field, fit the probe, bucket, and emit a verdict
row. Steps 1 and 2 are safe and this plan does them for real (Task 3 runs
`chart_curvature_field` on 64 genuine PU rows through a genuine sealed CAE checkpoint). Steps 3-5
are not: D5-09 freezes the protocol "before any PU probe number exists", which is stricter than
Phase 4's own wording ("before any *regional* MKNN number existed") and forbids even a global,
bucket-blind PU fit. So the tracer's probe/bucket/verdict legs run on a synthetic fixture that is
dimensionally identical to PU (768 in, 768 out) with a planted linear map and a planted
curvature-to-residual ordering. This is not a weaker tracer — it is the same production code on the
same code path, and it is the only tracer shape that does not spend the phase's one non-renewable
resource.

**No new Swiss roll notebook is required for this phase, and this plan states why rather than
skipping it silently.** `CLAUDE.md`'s standing rule targets a new manifold-learning or
representation-learning model that maps data to a lower-dimensional representation and back, or
claims to recover manifold structure. A linear map `W : R^768 -> R^768` fit by ridge regression has
no bottleneck, no latent space, no decoder, no reconstruction, and makes no manifold-recovery claim
— it is a regression, not a model of the manifold. The thing in this phase that *does* claim
manifold structure is the curvature estimator, and Phase 5 writes no estimator: it imports
`chart_curvature.chart_curvature_field` unchanged, which is already covered by
`notebooks/03_swiss_roll_chart_curvature_field_check.ipynb`. The rule is not being waived; it does
not apply. D5-11's declined low-`d` anchor is a separate, already-settled question and is not
re-litigated here.

is a non-empty string; `VERDICT_RULE` contains the literal `N_BUCKETS`; `N_BUCKETS` is a positive
int; `TRAIN_FRACTION` is a float strictly inside `(0, 1)`; `SPLIT_SEED` is a positive int;
`RIDGE_ALPHA_GRID` is a non-empty tuple of positive floats; `POOLING_METHOD` is a non-empty
string; `BUCKET_EDGES` is a tuple of `N_BUCKETS - 1` finite floats in strictly ascending order;
`SEED_STEMS` is a tuple of three positive ints; `CURVATURE_CONVENTION` equals `"trace"`;
`CURVATURE_SOURCE_FUNCTION` is a non-empty string. With the constants unset it therefore raises
today, which is the point.

Functions, all pure, no file I/O, every pre-registered value passed in by the caller with **no
default** (`region_partition`'s stated convention — a default is how a pre-registered value gets
inherited by accident instead of by an explicit call-site choice):

`train_test_split_indices(n, train_fraction, split_seed)` — one permutation of `np.arange(n)` under
`np.random.default_rng(split_seed)`; the first `int(round(n * train_fraction))` indices are train,
the rest test; returns both index arrays sorted ascending so downstream row alignment is readable.

`fit_probe(X_train, Y_train, alpha_grid, alpha_per_target, fit_intercept)` — wraps
`sklearn.linear_model.RidgeCV(alphas=alpha_grid, alpha_per_target=alpha_per_target,
fit_intercept=fit_intercept)`; returns a flat dict with `estimator`, `coef_` shape, `intercept_`
shape, `alpha_` (the selected value, as float or array), `alpha_grid`, `n_train`, `n_features`,
`n_targets`. Do not hand-roll a CV loop and do not hand-roll a least-squares solver.

`predict_probe(fit, X)` — `fit["estimator"].predict(X)`.

`per_point_residuals(Y_true, Y_pred)` — returns the length-`n` array
`np.sum((Y_true - Y_pred) ** 2, axis=1)`, the per-point squared L2 residual.

`aggregate_r2(Y_true, Y_pred, multioutput)` — `sklearn.metrics.r2_score(Y_true, Y_pred,
multioutput=multioutput)`. The pairing of this with `per_point_residuals` is what satisfies
05-CONTEXT.md's "R-squared and per-point residual derivable from one underlying quantity"
constraint; Task 2 pins the equivalence numerically rather than trusting RESEARCH A3's citation.

`pool_seed_fields(fields, method)` — `fields` is a dict mapping seed int to a length-`n` float64
array. `method` is required, no default. Support exactly two methods and raise `ValueError` naming
the offending value on anything else: `"per_seed_median_divide"` (divide each seed's field by its
own median before averaging across seeds) and `"per_seed_rank_uniform"` (map each seed's field to
its own percentile rank on `[0, 1]` via a stable argsort before averaging). Return a dict with
