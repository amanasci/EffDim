<assumption_delta_decision>
**Signal:** `pluralization` — `k` loses its monopoly. Until this phase there was one `k` in the
curvature pipeline (the estimator's neighbourhood size, swept 30/60/120/231). This phase introduces
a second, semantically unrelated `k`: MKNN's neighbourhood size, fixed at {5, 10, 20, 50} by
MKNN-06. Both are integers, both are called `k`, and both flow through the same runner.

**Primary noun:** *a named neighbourhood scale*. No bare `k` is primary any more.

**Decision: `promote`.** Every call site and every CLI flag names which scale it means —
`--mknn-k` / `k_mknn` for the alignment metric, `--field-k` / `k_field` (and the already-frozen
`K_FROZEN`) for the curvature estimator, `k_density` for the density correction. `mknn.py`'s public
functions keep the bare parameter name `k` because their signatures are fixed by the existing stub
contract and their module scope is unambiguous; every *caller* in `notebooks/diagnostics/` uses the
qualified name. The bare `k` is demoted to a within-module detail of one variant, not kept as a
still-required primary alongside.

**Invariant this buys:** a JSONL row can never be ambiguous about which neighbourhood scale
produced it — every row carries both `k_mknn` and the field's `k_field`/`K_FROZEN` provenance.
</assumption_delta_decision>

`_membership_matrix(Z, k)` returns an `(n, n)` boolean array whose row `i` marks `i`'s `k` nearest
neighbours with self excluded, built as `NearestNeighbors(n_neighbors=k + 1, algorithm="brute").fit(Z)`
then `kneighbors(Z)` and dropping column 0. Never `n_neighbors=k`. Guards, raising `ValueError`
that names the offending argument and its value, in this order: `Z` non-finite; `n < 2`; `k < 1`;
`k + 1 > n` (message names both `k` and `n`).

`mknn_score(z1, z2, k)` validates that `z1` and `z2` have equal row counts (a `ValueError` naming
both lengths — the docstring is explicit that row alignment is the caller's guarantee and there is
no join key to catch a mismatch), builds both membership matrices, and returns
`float(((A & B).sum(axis=1) / k).mean())` in float64. At `k = n - 1` this is exactly `1.0`; for
`z1 is z2` (or an identical copy) it is exactly `1.0` with no tolerance.

`permutation_null(z1, z2, k, n_permutations, seed)` builds `A` and `B` ONCE, then drives
`scipy.stats.permutation_test((np.arange(n), np.arange(n)), _stat, permutation_type="pairings",
alternative="greater", n_resamples=n_permutations, rng=np.random.default_rng(seed))`.
`permutation_type="pairings"` is passed explicitly — the sealed codebase's own docstring warns that
the default silently computes a different null. `_stat(idx1, idx2)` treats BOTH arguments purely as
index arrays into the precomputed `A`/`B` and never assumes either is the caller's original
unshuffled array. No k-NN query may occur inside the resampling loop. Return a flat dict:
`observed_score`, `null_distribution`, `p_value`, `null_mean`, `null_std`, `null_threshold`
(the `NULL_QUANTILE`-th percentile, quantile passed in as a required argument), `clears_null`
(strict `>` against `null_threshold`, so an observed value exactly equal to the threshold does NOT
clear), `n_permutations`, `seed`, `n`, `k`.

`bootstrap_ci(z1, z2, k, n_resamples, seed, confidence_level)` computes the fixed `(n,)` per-point
overlap array `(A & B).sum(axis=1) / k` once, then `scipy.stats.bootstrap((per_point,), np.mean,
method="percentile", n_resamples=n_resamples, confidence_level=confidence_level,
rng=np.random.default_rng(seed))`. It resamples POINTS, never the pairing, and never re-queries
k-NN. `n_resamples` and `confidence_level` are required arguments with no default. Raise
`ValueError` when `n < 2`. Return `score`, `ci_low`, `ci_high`, `degenerate` (true when
`ci_low == ci_high`), `confidence_level`, `n_resamples`, `seed`, `n`, `k`.

`hubness_skewness(Z, k)` returns `float(scipy.stats.skew(_membership_matrix(Z, k).sum(axis=0)))` —
the column sums are the k-occurrence in-degree (Radovanovic, Nanopoulos and Ivanovic, JMLR 2010).
`chance_floor(n, k)` returns `float(k) / float(n)`.
