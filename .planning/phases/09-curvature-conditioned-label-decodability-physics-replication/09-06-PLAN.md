measured figure. `--print-cost-model` runs this and exits 0 without touching data.

non-alphanumeric characters replaced). Include the environment dict as a JSON member inside the
archive. Print the archive path, its byte size and its SHA-256, and exit 0 even when only some

- **The cost model is stated in core-hours with an implied wall-clock at a named thread count**,
  not in the minutes Phase 7 used. `07-CONTEXT.md` §7's figures were measured on the developer's
  own box at an 8-thread cap; the execution host's core count is unknown at planning time, so a
  bare minute figure would be wrong on arrival. Core-hours plus a stated thread count is the
  portable form and is what `09-CONTEXT.md`'s execution-host note asks for.
- **Training and curvature costs are stated as separate components.** Phase 7 evaluated the
  curvature field at every row; Phase 9 evaluates it at 512 anchors only (D9-04). That single
  difference removes most of Phase 7's dominant cost term, so a single scaled total would
  misrepresent the shape of the run and mislead anyone watching it for pace.
- **`--mode bundle` exits 0 on a partial set.** An interrupted eight-hour run on a remote host is
  the case where the artifacts matter most; refusing to bundle because a later file is missing
  would throw away the evidence that exists.
- **The host is recorded as capability, not as an address.** Core count, OS and library versions
  are what make a wallclock interpretable and a result reproducible; a hostname or key path is
  neither, and committing one would put infrastructure detail into a research record permanently.
- **This is a `checkpoint:human-action`, not `checkpoint:human-verify`.** The automation-first rule
  says Claude must do anything it can do via CLI or API. It cannot: the host is not chosen yet,
  Claude has no credential for it, and the transfer back is manual. This is one of the rare cases
  the human-action type exists for.
</discretion_decisions>
