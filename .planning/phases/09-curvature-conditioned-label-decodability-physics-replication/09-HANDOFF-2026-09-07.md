## 0. Non-negotiable practices established this phase

1. **The pod guide comes first, every session.** Verify its digest on the host
   (`sha256sum /root/user-guide.md`, expected `5e94dd31…3dc4053b`) and re-read it if it changed.
   The rules that bit or nearly bit us: `/root` is wiped on unannounced restarts, so everything of
   ours lives under `/mnt/ssd-cluster/effdim/`; long jobs run only inside `tmux` with a log file;
   no recursive `find`, `ls -R` or `du` on `/mnt` (a `du` on our own tree took 5 minutes); never
   write to `/mnt/datasets`; never delete anything you did not create; the pod is a shared root
   account with other people's projects and about 35 foreign tmux sessions.
2. **Use available compute only.** Before launching, run `uptime`, `nvidia-smi`, and a quick
   `ps` for live CPU users. We used `--threads 16` on a 128-core, cgroup-unlimited host and never
   more. The work is CPU-only; the eight A100s stayed idle and untouched.
3. **Every host run follows the runbook shape:** fresh `git pull --ff-only` in the clone, strict
   ancestor check against the current freeze SHA, one scripted sequence in `tmux` with a log and an
   `EXIT=` marker, then `scp` the bundle or record back and verify `sha256sum` on both sides
   before reading a single value. Runner modes never run concurrently.
4. **Runbook §7:** no hostname, IP, username, or SSH key path in any phase artifact. Capability
   only (`pod128`, core count, versions, thread count). Paths under `/mnt/ssd-cluster/effdim/`
   are fine. The address lives in `CLAUDE.md` (uncommitted, see §5) and in memory, nowhere else.
5. **Sealed modules are never edited outside a numbered amendment:** `physics_labels.py`,
   `physics_curvature_probe.py`, `decoder_curvature.py`, `cae.py`, and `src/effdim/`. Amendment
   01 shows the only sanctioned path: one constant, fresh freeze commit, SHA rewired into both
   runners and both test suites, push, fresh-clone ancestry proof, separate output root, original
   record preserved.
6. **Subagent hygiene.** A `gsd-executor` that starts a background job and ends its turn does not
   wake up when the job finishes. Watch the PID (`until ! kill -0`, or `Monitor` for runs over
   10 minutes) and `SendMessage` it the exit time, output path and remaining steps. Executors run
   sequentially on the main working tree (worktrees are auto-degraded on this branch); tell each
   one to stage only its own files, because the tree carries uncommitted files that are not theirs.
7. **Never fabricate a number.** If a host step fails, return the stdout and the partial bundle.
   Every number in a document is quoted from a JSONL or npz record whose digest is written down.
