<objective>
Compute the full classical-MDS eigenspectrum of the frozen Isomap fit by hand, and turn it into the
two pre-registered gate statistics.

Purpose: This is the phase's load-bearing claim and its one genuine architectural unknown. Everything
downstream — the residual curves, the frozen `d`, the verdict artifact, Phase 3's decision to run at
all — is arithmetic on one array: the 10,000 eigenvalues of the double-centred geodesic matrix. If the
memory-mapped load, the in-place centring, or the split eigensolve does not work at this scale, or if
the hand-rolled centring does not reproduce sklearn's own leading eigenvalues, that must be known
after one commit rather than after the whole section is written. The tracer task proves that path end
to end before any expansion touches it.

The requirement this exists to satisfy is a negative one: `Isomap.kernel_pca_.eigenvalues_` is
truncated to `n_components` by construction, so reading it and reporting "no negative eigenvalues" is
a false negative *by construction*, not a finding (PITFALLS Pitfall 3). The only defence is to compute
the whole spectrum independently and prove it is whole — which this plan does by asserting its length
is exactly 10,000.

Output: sections 6.0 through 6.4 of `notebooks/01_manifold_and_gate.ipynb`, the cached
`mds_eigenspectrum_{fit_key}.npz`, the bound statistics `R_STAT` and `M_STAT`, the classifier
`_gate_classify`, and the two figures that make the spectrum's shape visible rather than compressed
into two numbers.

Task budget: 2 tasks. The tracer (~30% context) carries sections 6.0 through 6.3; the expansion
(~15%) carries section 6.4 and the two figures. Roughly 45% total.

### Open item 1 — the d-axis sweep ceiling, which is also the K eigenvector ceiling

**Answer: `D_SWEEP_MAX = 40`.**

Kneedle's answer depends on how far the curve runs, so this number is pre-registered with the
thresholds and never adjusted afterwards. 40 is chosen because it is the smallest round value more
than twice `D_PROVISIONAL = 18`: the elbow candidate then sits near the middle of the swept range
rather than at its boundary, and a chord-distance elbow finder is least trustworthy exactly when the
answer lands at an endpoint. The cost is bounded and small — the top-40 eigenvector block is
10,000 x 40 float64, about 3.2 MiB, comfortably inside D-11's under-10-MB artifact budget, and
`scipy.linalg.eigh` with `subset_by_index` computes only that band rather than all 10,000 vectors.

### Open item 3 — the equivalence-guard tolerance and matrix size

**Answer: `EQUIV_N = 50`, `EQUIV_TOL = 1e-12` (used as both `rtol` and `atol`), on two different
50 x 50 inputs.**

Both forms are float64 sums over 50 terms; the literal `J` form additionally performs two matrix
products, so its rounding error accumulates on the order of `n * eps`, roughly `50 * 2.2e-16 = 1.1e-14`
relative. `1e-12` leaves two orders of margin above that while remaining far tighter than any genuine
algebraic discrepancy, which would be order 1 relative, not order 1e-12. Two inputs rather than one,
because the identity `B = -0.5 * J D2 J` is purely algebraic and must hold for *any* symmetric input:
a real squared-Euclidean distance matrix built from 50 random points in R^5 (the actual input class),
and a symmetrised random matrix that satisfies no triangle inequality (proving the identity does not
quietly depend on metric structure).

### Open item 4 — how SPEC-02's steep dropoff is defined, distinct from SPEC-04's elbow

**Answer: the dropoff index is `argmax` over `j` in `1 .. D_SWEEP_MAX - 1` of
`log(lambda_j) - log(lambda_{j+1})` — the largest single multiplicative gap between consecutive
leading eigenvalues — reported together with that ratio and marked on a log-scale scree plot.**

This is deliberately a different statistic answering a different question from the SPEC-04 elbow. The
dropoff reads the **raw spectrum** and finds the sharpest single step; the elbow reads a **cumulative
residual-variance curve** and finds where it stops improving. On a spectrum with one clean gap they
agree; on a smoothly decaying spectrum they can disagree by several dimensions, and that disagreement
is information about the manifold, not a discrepancy to reconcile away. The notebook must say so in
prose next to both numbers. Ties break to the lower index, consistent with Phase 1's
`PLATEAU_TIE_BREAK = "lower"`.

reads both back instead of re-running LAPACK. This is a recorded deviation rather than a silent one:
if the single-file form is required, say so and both plans change together.

<assumption_delta_decision>

The detector fired one `chosen` signal on the phase scope: *"The **chosen** embedding dimension `d` is
frozen and recorded before any decoder is trained."* A derived value is becoming a recorded, chosen
constant, so the identity question is live and is answered here once for the phase.

**Noun now primary:** the frozen embedding dimension `d`, recorded as `d_frozen` in
`gate_verdict_{fit_key}.json`.

**Decision: promote.** Phase 1's `n_components = 18` was the dimension of record — derived from the
`compute_dim` geometric median, carried in `ANALYSIS_CFG`, and baked into `fit_key`. From this phase
onward it is demoted to a **fit-capacity** detail: it bounds how wide a slice can be taken, and
nothing more. The dimension every downstream consumer means is `d_frozen`, which follows from the
SPEC-04 elbow. Phase 3's decoder input width, the coordinate space the curvature field lives on, and
CURV-08's support region are all defined on `d_frozen`; Phase 4's region partition inherits it. Adding
the new dimension alongside the old — leaving `n_components` as the thing downstream code reads — is
exactly the failure mode this checkpoint exists to catch, because the two are equal in the common case
and diverge silently in the case that matters.

**Suggested invariant, encoded in plan 02-02's section 6.6 and plan 02-03's artifact contract:**
`d_frozen <= n_components` always holds, and every downstream consumer reads `d_frozen` from the
verdict artifact rather than `n_components` from the Phase 1 handoff. The D-08 branch is what makes
this more than bookkeeping: an elbow above `n_components` cannot be satisfied by a slice at all, and
the notebook halts rather than quietly capping `d_frozen` at 18.

This checkpoint is advisory and does not block the phase.

</assumption_delta_decision>

<threat_model>
## Trust Boundaries

ASVS level 1, blocking on `high`. The attack surface is a local notebook: no network service, no
user input, no authentication, no credentials, and a public unauthenticated dataset with no labels
and no PII. The register is deliberately not padded with inapplicable web threats. The boundaries
below are the ones this plan's work actually crosses.

| Boundary | Description |
|----------|-------------|
| `notebooks/.cache/` -> notebook process | `joblib.load` is pickle deserialization, and `mmap_mode="r"` does not change that — the pickle stream is still executed to reconstruct the object graph. A substituted artifact is arbitrary code execution in the kernel. This is the ~1.55 GiB file every remaining phase loads. |
| Pre-registered constants -> gate statistics | The integrity boundary specific to this phase. `r`, `m`, and their thresholds decide whether the milestone continues, so a threshold that could be edited after the spectrum was seen would make the verdict unfalsifiable. |
| `dist_matrix_` -> `B_CENTERED` -> the spectrum | A silent numerical defect here — an asymmetric input read as symmetric, a float32 downcast, a centring that is not actually the double-centring — produces a plausible-looking spectrum and a confidently wrong verdict. Nothing downstream would catch it. |
