### Open item 2 — the D-08 statistical smoke-test margin

**Answer: a scale-free z-score against a 50-permutation null, with a strict threshold of z > 5.0.**

Compute `s_true = mean_i <hsc[i], ls[i]>` over the L2-normalized arrays. Draw
`ALIGNMENT_N_PERMUTATIONS = 50` independent seeded permutations of one array, compute the same
mean cosine for each, and take `mu_perm` and `sd_perm` (the standard deviation across the 50
permuted means). The reported statistic is `z = (s_true - mu_perm) / sd_perm` and the assertion is
**strict**: `z > ALIGNMENT_MARGIN_Z` where `ALIGNMENT_MARGIN_Z = 5.0`. A value exactly at 5.0 is
treated as insufficient and FAILS.

Justification, which must appear verbatim-in-substance in the notebook:

- **Scale-free, so it cannot false-alarm on a weak-but-correct pairing.** The origin paper
  (arXiv:2509.19453) reports Legacy Survey crossmodal MKNN at only 0.4-2%, so any margin stated as
  an absolute cosine value would risk rejecting a genuinely correct pairing. A z-score against the
  permuted null adapts to whatever the true-pair cosine actually is.
- **The null's spread is a standard error over 10,000 rows**, so `sd_perm` is roughly the per-row
  cosine SD divided by 100. A correct row alignment — even a weak one — puts `s_true` many standard
  errors above `mu_perm`, because every one of the 10,000 rows contributes a small positive
  same-object bias. Under a gross misalignment (off-by-one, independent re-sort) `s_true` is itself
  a draw from the permuted distribution, so `z` lands near 0, not near 4.9.
- **z > 5 is a ~5-sigma bar** that 50 permutations estimate the null spread well enough to support,
  and it is far above the noise floor a correct-but-weak pairing clears.
- The observed `s_true`, `mu_perm`, `sd_perm`, `z`, `margin_z`, and `n_permutations` are all printed
  and carried into the Phase 1 -> Phase 2 handoff artifact, so a reader can re-judge the margin
  rather than trust it.

<threat_model>
## Trust Boundaries

ASVS level 1, blocking on `high`. This phase's attack surface is genuinely narrow: a local
notebook with no network service, no user input, no authentication, no credentials, and a public
unauthenticated dataset. The register below is deliberately not padded with inapplicable web
threats. The three L1-relevant items are untrusted-pickle risk on `joblib.load`, HuggingFace
download integrity, and cache-key under-specification letting a stale or incompatible artifact be
silently reused.

| Boundary | Description |
|----------|-------------|
| `notebooks/.cache/` -> notebook process | Untrusted-if-substituted bytes cross here. `joblib.load` is pickle deserialization, so a substituted `.joblib` is arbitrary code execution in the notebook kernel. |
| `huggingface.co` -> notebook process | A ~553 MiB third-party parquet crosses here over the network on first run. |
| PyPI / `download.pytorch.org` -> notebook environment | Package installs cross here via `%pip install -r requirements-notebooks.txt`. |
| notebook process -> `src/effdim` | Read-only in-process call to `compute_dim`. No boundary risk; listed for completeness because the milestone constraint is that this direction is never reversed. |

## STRIDE Threat Register

| T-01-02 | Tampering | HuggingFace dataset download integrity (`datasets.load_dataset`) | medium | mitigate | `datasets` and (transitively) `huggingface_hub` are version-pinned in `requirements-notebooks.txt` (D-03).
