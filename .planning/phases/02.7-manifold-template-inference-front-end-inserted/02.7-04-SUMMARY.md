## Accomplishments

- **`confidence_band.py`'s surface completed.** `bands_for_diagram(D, maxdim, B, alpha, seed)` returns one `bootstrap_band` result per degree, keyed by degree, so a caller cannot apply an `H_1` band to an `H_2` diagram. `band_spread(D, degree, B, alpha, seeds)` returns the per-seed `c_alpha` values plus `{min, max, range}` -- A-04's PH seed/draw-variance instrument, reporting spread rather than absorbing it into an average.
- **`betti_vector` widened to accept both call shapes with no breaking change.** Now takes `bands` as either a plain sequence (the pre-existing tracer's `[band_h0, band_h1, band_h2]`) or a degree-keyed mapping (`bands_for_diagram`'s own dict output, unwrapping each entry's `"band"` key). Raises `ValueError` naming the missing degree if `bands` supplies no entry for a degree present in `dgms`. Verified backward-compatible by re-running `notebooks/diagnostics/template_tracer_run.py --smoke` end to end after the change -- it still passes its original list-of-floats call unmodified.
- **The disc's `beta_1 == 0` result is now a pinned test, not prose.** `test_disc_yields_no_significant_h1` is the plan's named most-important test: D-02's rationale is that a largest-gap cut is undefined exactly when the true Betti number is 0 (no gap to find, so the rule manufactures a cycle) -- the expected PU case. The band proves it can return 0 there.
- **Six known-answer tests added, all passing in ~10s** (90s budget): determinism under seed, circle `beta_1==1`, disc `beta_1==0`, Euclidean-vs-geodesic bands differing on the same cloud, the `beta_0` `+1` base-component convention on a single blob vs. two well-separated blobs, and `band_spread`'s per-seed reporting.
- **Full `notebooks/pu_manifold/tests/` suite: 243 passed** (237 baseline + 6 new), no regression.

## Decisions Made

- **`betti_vector`'s `bands` parameter widened rather than the tracer rewritten.** The plan's `<read_first>` note says Task 1 "completes the surface, it does not rewrite the tracer's version" -- `notebooks/diagnostics/template_tracer_run.py` (out of this plan's `files_modified` scope) calls `betti_vector(dgms, bands)` with `bands` as a plain list built via `.append(band_info["band"])`. Rather than break that call site or reach outside scope to edit the tracer, `betti_vector` now resolves each degree via `bands[degree]` and unwraps a dict's `"band"` key when present -- so both the tracer's list shape and `bands_for_diagram`'s new dict shape serve unchanged. Verified by running `--smoke` after the change; unchanged output structure, no error.
- **Jittered-grid fixture instead of a Gaussian blob for the `beta_0` base-component test.** Measured first with a Gaussian blob (`n=80`, `B=5`): 11 of 79 H0 bars cleared the bootstrap band, not the expected 0 -- a Gaussian's tail reliably produces a handful of moderately-isolated points whose H0 merge-life exceeds a small-`B` band for reasons unrelated to genuine multi-component structure. Switched to a near-uniformly-dense jittered grid (`9x9`, `jitter=0.05`), which gave the expected `beta_0==1` for one blob and `beta_0==2` for two well-separated copies. This isolates the `+1` convention under test from an unrelated density-tail confound; recorded here since a future reader might otherwise assume any "single blob" fixture would do.
