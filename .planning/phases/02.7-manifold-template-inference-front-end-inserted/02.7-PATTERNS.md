**Core transform pattern**: array/dict-in, dict-out, no file I/O — same contract as
`ph_agreement` (persistence_probe.py lines 187-219) and `readout_matrix` (lines 259-323):
"Returns one flat dict carrying..." — document every output key explicitly the way
`readout_matrix`'s docstring does (lines 273-284).

**Validation pattern**: `persistence_diagram`'s explicit shape/symmetry checks (lines 135-144)
raising `ValueError` with a specific f-string message — apply the same discipline to
`template_decision.py`'s lookup-table input (e.g. reject a Betti vector of the wrong length

**D-13's three-way tally**: no existing analog in this repo counts into three disjoint buckets;
write it as a small, separately-testable function (`tally(results) -> {"correct":, "wrong":,

invariant directly, mirroring how `persistence_probe.py` keeps `finite_pairs`/`max_persistence`/

### `notebooks/pu_manifold/geodesic_graph.py` (utility, transform)

**Analog:** `src/effdim/geometry.py::gmst_dimensionality`'s `geodesic=True` branch
(lines 396-471, the relevant symmetrization at line 434-442) — **frozen code, call/reference
never edit**, and it is the closest structural analog for the geodesic route **but it carries
the bug this phase must not copy.**

**Verified bug, cite with correction, never copy verbatim** (geometry.py line 437):
```python
graph = kneighbors_graph(subsample, k_geo, mode='distance')
graph = graph + graph.T          # BUG: doubles mutual-neighbour edge weights
```
D-05/D-07's new code must instead do:
```python
graph = kneighbors_graph(data, k, mode="distance")   # real Euclidean weights, NOT squared
graph = graph.maximum(graph.T)                          # correct symmetrization
```
Verified this session (RESEARCH.md Pitfall 3): `graph + graph.T` measured a 2x inflation
(`2.914` vs true `1.457`) on a mutual-neighbour edge; `graph.maximum(graph.T)` recovers the
exact true distance to full float64 precision. Pin this as a regression test
(`test_geodesic_graph.py::test_maximum_symmetrization_not_sum`), exactly as RESEARCH.md's test
map already names it.

**Do not use `geometry.compute_knn_distances`** (geometry.py lines 8-31) for this module — it
returns squared distances with no neighbour indices, the wrong contract for a graph (Pitfall 4).
Use `sklearn.neighbors.kneighbors_graph(data, k, mode="distance")` directly, as
`gmst_dimensionality` itself does, for real distances plus index structure in one call.

**Core pattern** (component read-out + largest-component-only geodesic, D-07, no bridging) —
RESEARCH.md's Pattern 1 is the concrete code to follow, verified this session against this
exact venv:
```python
from sklearn.neighbors import kneighbors_graph
from scipy.sparse.csgraph import shortest_path, connected_components

graph = kneighbors_graph(data, k, mode="distance")
graph = graph.maximum(graph.T)

n_components, labels = connected_components(graph, directed=False)
sizes = np.bincount(labels)
largest_label = sizes.argmax()
largest_mask = labels == largest_label
dropped_fraction = 1.0 - sizes[largest_label] / len(data)

sub_graph = graph[largest_mask][:, largest_mask]
D_geo = shortest_path(sub_graph, directed=False, method="D")
assert np.allclose(D_geo, D_geo.T)
```

**Validation pattern**: mirror `persistence_probe.persistence_diagram`'s explicit
shape/symmetry assertion (lines 135-144) before handing `D_geo` off to
`persistence_probe.persistence_diagram` — the V5 input-validation note in RESEARCH.md's
Security Domain section flags this explicitly: a malformed geodesic matrix (e.g. the
un-fixed symmetrization bug) would otherwise silently produce a wrong-but-plausible result
with no exception anywhere in the pipeline.

**No `minimum_spanning_tree` bridging** — `gmst_dimensionality` imports and uses
`minimum_spanning_tree` for its own (different) length-scaling purpose; D-07 explicitly forbids
using it to repair disconnection here. Do not import it into `geodesic_graph.py`.

### `notebooks/pu_manifold/local_dimension.py` (utility, transform)

**Analog:** `src/effdim/geometry.py`, all eight estimator functions — frozen, call only.

**Core pattern** (D-12, RESEARCH.md Pattern 2), verified against source this session — seven of
eight estimators accept `precomputed_knn_dist_sq`:
```python
dist_sq_global = geometry.compute_knn_distances(data, k)   # (n, k), SQUARED distances

for anchor_idx in anchor_indices:
    local_idx = neighbourhood_of(anchor_idx, radius_or_k)
    local_d_hat = geometry.mle_dimensionality(
        data[local_idx],
        precomputed_knn_dist_sq=dist_sq_global[local_idx],   # same array, sliced
    )
```
This pattern applies identically to `mle_dimensionality` (geometry.py:34), `two_nn_dimensionality`
(89), `danco_dimensionality` (152), `mind_mli_dimensionality` (208), `mind_mlk_dimensionality`
(246), `ess_dimensionality` (293), `tle_dimensionality` (348) — all seven verified this session
to accept `precomputed_knn_dist_sq: Optional[np.ndarray] = None` as their signature's final
keyword.

**GMST is the verified exception** (geometry.py:396-471): `gmst_dimensionality(data,
geodesic=False, random_state=42)` has no `precomputed_knn_dist_sq` and no `k` parameter at all.
For D-12's local probe it must be called directly on raw local-subset coordinates —
`geometry.gmst_dimensionality(data[local_idx])` — a structurally different call path, not
bit-identical in provenance to its own global call (it recomputes its own internal kNN on the
subset). **Do not attempt to slice a precomputed array into GMST — the parameter does not
exist.** Flag this explicitly in the module docstring and in `test_local_dimension.py`.

**Global `d_hat` (D-09, D-10) plateau-and-consensus**: no existing analog in this repo computes
a cross-estimator consensus; this is new logic, but should live in `template_decision.py`
(abstain condition (d) consumes it) or as a small shared helper — the eight raw estimates
themselves are `local_dimension.py`'s output, not the consensus rule.

### `notebooks/pu_manifold/template_immersion.py` (utility, synthetic generator)

**Analog:** `notebooks/pu_manifold/decoder_curvature.py` / `chart_curvature.py` for the
float64 + `torch.func.jacrev` rank-check discipline (`_assert_float64` pattern cited in
RESEARCH.md Pattern 3) — no immersion-generator precedent exists anywhere in this repo, so this
is the closest instrument-level analog, not a structural one.

**Core pattern** (D-14, Q5) — use RESEARCH.md's verified per-template construction (not
verified against a specific citation — logged there as Assumption A1, standard differential
geometry):
- `S^1`: `p(t) = (cos t, sin t)` — analytic tangent, safe to autodiff directly, no singularity.
- `T^2`: standard torus embedding `((R + r cos v) cos u, (R + r cos v) sin u, r sin v)`,
  `R > r > 0` — Jacobian never drops rank; safe to autodiff directly.
- `S^2`: **avoid the angle parametrization for the rank check.** Sample via normalized
  Gaussian (`u = g / ||g||`), compute tangent space directly via `torch.linalg.qr` on
  `[u, e1, e2]` dropping the first column, check rank of `d(lift ∘ warp)(u) @ tangent_basis`
  (a `D x 2` matrix) — well-posed everywhere including the angle-chart's would-be poles.
- `B^d`: identity embedding, rank check is `d(lift ∘ warp)` restricted to `R^d`'s own
  coordinate directions.

**Rank tolerance**: `torch.linalg.matrix_rank` (SVD-based) at float64 — "consistent with this
project's existing float64 discipline (`_assert_float64` pattern in
`chart_curvature.py`/`decoder_curvature.py`)" per RESEARCH.md; verify `_assert_float64`'s exact
call site in one of those two modules before reusing the name (not independently re-verified
this session — cite RESEARCH.md's claim, do not assert it verbatim as source-checked).

**Negative control test**: `test_template_immersion.py::test_jacobian_rank_negative_control`
should deliberately construct a collapsing warp and assert the rank check flags it — mirrors
the "known-answer fixture" discipline in `test_persistence_probe.py` (circle → `beta_1=1`, disc
→ `beta_1=0`, lines 39-51).
