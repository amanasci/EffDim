<objective>
The CLAUDE.md-mandated Swiss roll sanity check for this phase's model — non-negotiable, and not
a follow-up task: the front end is not done until this notebook exists and passes.

Purpose, in CLAUDE.md's own words: a model that fails on real data has two possible causes — the
data has no structure to find, or the implementation is broken — and only a manifold whose
answer is known in advance separates them. Without this check, SC-6's PU result is
uninterpretable and every conclusion drawn from it is unsupported.

D-16 adds what makes the check falsifiable. The Swiss roll's correct answer **is** the trivial
template, so a front end that has silently degenerated into always emitting `ball` passes the
roll check with no controls at all. The in-library positive controls — a sampled `S^1` and `T^2`
at matched `n`/`D`/noise, whose expected labels are non-trivial — are CLAUDE.md step 6's
"baseline known to succeed", adapted for a model with no decoder to compare against a
`PlainAutoEncoder`.

There is a **live prediction** here, not a formality. `02.6-CONTEXT.md` D-02 records that the
Swiss roll's *ambient* `beta_1 = 1`, from near-touching spiral arms. The Euclidean arm is
therefore predicted to see a spurious cycle on a contractible sheet where the geodesic arm
should not — making SC-5 a live test of abstain condition (c), metric disagreement. Either
outcome is a real result; report what happens.

Output: `notebooks/02.7_swiss_roll_template_check.ipynb`, committed with outputs, executed end
to end.
