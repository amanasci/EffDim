Order of operations, and the order matters:

Call `crossmodal_curvature.assert_preregistered()` as the first statement. Then verify the freeze
ancestry before any compute: read the freeze commit SHA from a `--freeze-commit` flag (required, no
default), and assert BOTH that `git merge-base --is-ancestor <freeze> HEAD` exits 0 AND that
`git rev-list --count <freeze>..HEAD` returns an integer of at least 1. Exit non-zero naming D7-06
if either fails. The second check is not redundant: a commit is its own ancestor, so
`--is-ancestor` alone would pass for a number produced in the freeze commit itself.

Load the row-aligned pair once with `load_pu_pair(PU_COLUMN_A, PU_COLUMN_B)`.

Compute the per-point MKNN arrays ONCE, before the `d` loop — one array per `k` in `MKNN_K_GRID`,
each via `crossmodal_curvature.per_point_mknn`. MKNN depends only on the two frozen embeddings and
`k`, never on the decoder's latent dimension; recomputing it inside the `d` loop would triple the
cost for identical values. Record each array's distinct-value count, computed at relative
precision — divide by the array's own maximum absolute value and round to 12 decimals before
`np.unique` — never on raw float equality. The `05-02-SUMMARY.md` retraction on record in STATE.md
is exactly the error of counting raw float equality: it reported 5,301 and 9,852 distinct values
where the true counts were 4 and 3.

Compute the density diagnostics ONCE, before the `d` loop, on the ambient legacysurvey array at
`DENSITY_K` and `DENSITY_FIELD_D`, against the `HEADLINE_K` MKNN array. Hold that for the moment
when the `d=20` field exists — the density-versus-curvature statistic needs the field, so compute
the density array once and re-use it inside the loop for each `d`'s
`spearman_density_vs_h` and `partial_rho_density_controlled`.

Then, for each `d` in `D_SWEEP`, in tuple order, sequentially: print a banner naming the `d` and the
projected field time from the cost model; call `fit_and_field` at `MAX_EPOCHS`; run
