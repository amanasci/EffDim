# Phase 02.4: Topological Auto-Encoder Validity Test — Specification

**Created:** 2026-08-06
**Ambiguity score:** 0.108 (gate: ≤ 0.20)
**Requirements:** 8 locked

## Goal

A Topological Auto-Encoder (Moor, Horn, Rieck, Borgwardt — ICML 2020, arXiv:1906.00722) is
implemented in `notebooks/pu_manifold/topoae.py`, trained on the frozen Phase 1 10,000-row PU
subsample at a pre-registered latent-dimension ladder, and put through a three-gate validity test
whose machine-readable PASS/FAIL verdict decides whether Phase 3 may decode a curvature field from a
TopoAE representation.

## Background

**What exists.** `notebooks/pu_manifold/cae.py` (1,187 LOC) already carries generic machinery this
phase reuses rather than rebuilds: `verdict_from_metrics` is a threshold-agnostic gate engine
reading a `GATING_METRICS` list; `PlainAutoEncoder` + `train_plain_ae` + `_train_decoder_protocol`
supply the matched-capacity baseline; `reconstruction_stats` reports aggregate plus per-dimension
error; `unfaithfulness_coverage` implements the paper's topology measures; `embedding_distortion`
takes a generic latent array and delegates to `geometry_probes.distortion_stats`;
`activation_module` handles C2-smooth activation selection; `write_cae_verdict` / `write_cae_handoff`
/ `to_native` are the artifact writers. Test coverage: `test_cae.py` (944 LOC),
`test_geometry_probes.py` (272 LOC). The frozen Phase 1/2 caches (subsample, Isomap joblib,
200,000-pair geodesic sample, `gate_verdict`) are on disk and gitignored.

**What does not exist.** Any persistence computation, any topological loss, `topoae.py`, TOPO
requirement IDs in `REQUIREMENTS.md`, and `notebooks/02.4_swiss_roll_topoae_check.ipynb`.

**What triggers this work.** Phase 2 gated the Isomap geodesic metric FAIL (`m = 0.412071`, 41% of
eigenvalue mass negative). Phase 02.2 tested the Chart Auto-Encoder's local-charts assumption relief
and returned `CAE_VERDICT = FAIL`. Phase 02.1 sealed with its falsifier fired, recommending
graph-native Ollivier-Ricci and concluding that the ~0.0796 distortion wall reflects flatness of the
*target space* — four structurally unrelated algorithm families hit it, including metric SMACOF with
no eigendecomposition and no PSD constraint.

**Why TopoAE is not simply a rerun of a settled question.** 02.1's wall was measured on
`DISTORTION`, a **distance-preservation** statistic, and every arm that hit it was optimising
distance preservation in some form. TopoAE optimises **topological signature matching** — agreement
between 0-dimensional persistence pairings of input and latent space — and does not claim distance
preservation. A method with a different objective is not obviously bound by a wall measured on the
objective it declines to pursue. That is the hypothesis this phase tests, and it is why R4 forbids
gating on distortion.

## Requirements

1. **Persistence and topological loss**: 0-dimensional persistence pairings computed from the
   minimum spanning tree of each batch's pairwise distance matrix, in both input and latent space,
   combined into the paper's topological loss.
   - Current: no persistence computation exists anywhere in the repo
   - Target: `topoae.persistence_pairs(D)` returns the MST edge set as persistence pairings, with
     ties broken lexicographically on `(distance, row_index, col_index)`; `topoae.topological_loss`
     combines input-space and latent-space pairings per Moor et al.
   - Acceptance: on a hand-built distance matrix containing exact ties, `persistence_pairs` returns
     an identical pairing on repeated calls and across process restarts; a batch smaller than 2
     raises a named error rather than returning zero loss

2. **Model and training**: a TopoAE trained on the frozen subsample, reproducible, C2-smooth,
   across a pre-registered latent-dimension ladder.
   - Current: no TopoAE implementation; `cae.py` is 02.2's sealed artifact and must not be edited
   - Target: `notebooks/pu_manifold/topoae.py` defines the model and `train_topoae`, importing
     `verdict_from_metrics`, `PlainAutoEncoder`, `train_plain_ae`, `reconstruction_stats`,
     `activation_module`, `to_native`, and `embedding_distortion` from `cae` rather than copying
     them; trained on `subsample_20260729_a79b3460b838fd0a.npz` (`legacysurvey`, L2-normalized) at
     each rung of a pre-registered ladder, from recorded seeds, with no ReLU-family activation
     anywhere in encoder or decoder
   - Acceptance: two runs at the same seed and rung produce bit-identical held-out metrics; a grep
     for ReLU-family activations across `topoae.py` returns nothing; `git diff --quiet -- notebooks/pu_manifold/cae.py` is clean

3. **Pre-registration before any fit**: gate metric definitions and numeric thresholds committed
   ahead of the first fit, with ordering proved mechanically.
   - Current: no pre-registration exists for this phase
   - Target: `02.4-PREREGISTRATION.md` fixes the three metric definitions, their numeric PASS
     thresholds, the latent-dimension ladder, the primary `d`, all architecture and compute
     constants, and the prohibited moves — committed before any TopoAE fit commit
   - Acceptance: `git merge-base --is-ancestor <preregistration-commit> <first-fit-commit>` succeeds;
     the verdict artifact's `json_cache` cfg carries the thresholds, so editing one afterwards raises
     a manifest mismatch instead of silently re-verdicting

4. **Three gating metrics, measured on held-out data**: topological fidelity, reconstruction margin,
   rank structure — and explicitly not geodesic distortion.
   - Current: no gate exists; 02.2's T1 gated on geodesic distortion, which is the wrong axis here
   - Target: **T1** topological fidelity — agreement between input-space and latent-space 0-dim
     persistence pairings on held-out batches. **T2** held-out reconstruction margin against a
     matched-capacity `PlainAutoEncoder`, under CAE-03's "must beat, not tie" rule. **T3** a
     rank-based structure-preservation measure (trustworthiness / continuity or MRRE). Geodesic
     distortion and `unfaithfulness_coverage` are computed and reported for comparability with 02.1
     and 02.2, and never enter the verdict
   - Acceptance: the verdict artifact's gating-metric list contains exactly T1, T2, T3; distortion
     and unfaithfulness/coverage appear in the artifact under a non-gating key; every comparison is
     strict less-than, so a value exactly at a threshold does not clear it

5. **Verdict artifact, always written**: machine-readable, self-contained, on every run.
   - Current: no verdict artifact for this phase
   - Target: `topoae_verdict_{fit_key}.json` written on PASS and on FAIL alike, carrying every
     measured metric, every threshold, the primary `d`, the per-rung sensitivity results, the
     non-gating context metrics, seeds, and versions
   - Acceptance: the artifact is parseable and its stored verdict is reproducible from its own
     recorded metrics and thresholds without the notebook; a run in which any gating metric is
     absent or non-finite halts and writes no verdict at all

6. **Handoff on PASS only**: written when the gate passes, actively prevented from going stale when
   it does not.
   - Current: no handoff; `cae.write_cae_handoff` exists but 02.2 never exercised it (it FAILed)
   - Target: on PASS, `topoae_handoff_{fit_key}.json` carrying representation id, primary `d`, fit
     artifact and encoder-weight paths, the three gate values with thresholds, the evidence criteria
     Phase 3 should judge it by, and the DEC/CURV requirement buckets a coordinate-producing win
     reinstates. On FAIL, no handoff is written **and** any existing handoff at that `fit_key` is
     deleted
   - Acceptance: after a FAIL run, no `topoae_handoff_{fit_key}.json` exists on disk even when one
     was present beforehand; after a PASS run the handoff parses and carries all named fields

7. **Reconciliation on PASS**: the requirement register and 02.1's falsifier reading updated, once,
   additively.
   - Current: 02.1's graph-native answer drops 9 of 13 DEC/CURV requirements, rewrites 3, amends 1;
     `REQUIREMENTS.md` has no TOPO family
   - Target: on PASS the runner writes a **new dated** `02.1-AMENDMENT-03.md` revisiting the
     falsifier *reading* only, and applies a marker-guarded `REQUIREMENTS.md` traceability update for
     the reinstated DEC/CURV requirements. Both steps are guarded by an existence check so a second
     run is a reported no-op. No sealed 02.1 measurement, artifact, or prior amendment is edited or
     overwritten
   - Acceptance: running the reconciliation step twice produces one amendment file and one
     `REQUIREMENTS.md` change, with the second run reporting "already written";
     `git diff --quiet` on 02.1's sealed artifacts is clean afterwards

8. **Swiss roll sanity check**: the mandatory known-answer test for the new model.
   - Current: `notebooks/02.2_swiss_roll_cae_check.ipynb` and
     `notebooks/02.1_swiss_roll_geometry_probes_check.ipynb` exist as references; none for TopoAE
   - Target: `notebooks/02.4_swiss_roll_topoae_check.ipynb` imports `topoae` unchanged, generates
     ~3,000 noiseless Swiss roll points in-notebook with a fixed `random_state`, centres and divides
     by one global standard deviation, trains from scratch at latent dimension 2, plots the latent
     against the arc-length parameter `t`, compares against a matched-capacity `cae.PlainAutoEncoder`,
     and ends with three or four printed pass/fail lines and a one-sentence read-out
   - Acceptance: the notebook runs end to end on CPU in under two minutes with zero error cells; a
     grep of its source for `.cache` returns nothing; it is committed with outputs

## Boundaries

**In scope:**
- `notebooks/pu_manifold/topoae.py` — persistence, topological loss, model, training, rank-structure
  measure
- Tests for the new module, following `test_cae.py` / `test_geometry_probes.py`
- `02.4-PREREGISTRATION.md` — metrics, thresholds, ladder, primary `d`, constants, prohibited moves
- A runner under `notebooks/diagnostics/` following the existing convention
- `topoae_verdict_{fit_key}.json` (always) and `topoae_handoff_{fit_key}.json` (PASS only)
- On PASS: `02.1-AMENDMENT-03.md` and the `REQUIREMENTS.md` traceability update
- `notebooks/02.4_swiss_roll_topoae_check.ipynb`
- TOPO-xx requirement IDs added to `REQUIREMENTS.md`

**Out of scope:**
- **Curvature of any kind** — no mean-curvature field, no Jacobian/Hessian work, no Ricci. This
  phase validates a representation; Phase 3 decodes curvature from whatever passes. Mirrors 02.2's
  boundary.
- **CAE iteration** — no re-tuning, re-fitting, or re-pre-registering the Chart Auto-Encoder.
  02.2's FAIL is sealed history and Phase 02.3 owns any iteration on it.
- **The graph-native branch** — no Ollivier-Ricci implementation, no `GraphRicciCurvature` / `POT`
  installs, no head-to-head against 02.1's recommendation. 02.1's recommendation stands untouched
  unless this phase PASSes, which triggers R7's amendment.
- **Higher-dimensional persistence** — dimension 0 only, which is what the paper's loss uses and
  what scipy's MST provides without a new dependency.
- **The seed-sensitivity study** named in `02.1-AMENDMENT-02.md` §6.5 — a separate dated
  pre-registration, not this phase.
- **Editing `cae.py`** — 02.2's sealed artifact. Reuse by import only.

## Constraints

- **No new packages.** 0-dim persistence pairings are exactly the MST edge set, so
  `scipy.sparse.csgraph.minimum_spanning_tree` suffices — already a dependency and already used in
  `geometry_probes_run.py`. `torch==2.13.0+cpu` is vetted and pinned. If a later check genuinely
  demands higher-dimensional persistence, a library install goes through its own blocking
  `checkpoint:human-verify` gate as a dated amendment, never assumed here.
- **C2-smooth activations throughout** encoder and decoder — DEC-02 and CURV-01..03 need a non-zero
  second derivative, and ReLU's is identically zero. Same substitution obligation as CAE-06.
- **Compute envelope**: laptop, no GPU, n = 10,000. The ladder multiplies fit cost by its rung count,
  so the ladder and the per-fit budget must be costed together in the pre-registration.
- **Working dimension is not inherited.** `D_FROZEN = 5` is flagged suspect and was discarded as
  inapplicable by 02.1; intrinsic-dimension estimates cluster at 18–25. Every rung and the primary
  `d` must be justified from that evidence.
- **Cache posture**: the gitignored Phase 1/2 caches are not reproducible here. A runner that cannot
  find them halts rather than regenerating, because regenerating changes provenance.
- **Additive only** — no existing notebook, runner, or module is deleted or rewritten.
- **Batching**: `drop_last=True`, and the persistence function asserts batch size ≥ 2.
- **Determinism**: distance matrices in float64; MST ties broken lexicographically on
  `(distance, row_index, col_index)` rather than relying on scipy's internal ordering, so a scipy
  version bump cannot silently move the loss.
