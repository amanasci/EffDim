# Phase 02.4 Plan 02: Gate Layer Summary

**The T1/T2/T3 gate engine in `topoae.py`: two new baseline-relative statistics (`topological_fidelity`, `rank_structure`), a positional-slot-remap verdict wrapper that delegates the strict-less-than comparison to `cae.py`'s sealed engine without ever leaking its borrowed names into an artifact, and the always-written verdict artifact plus PASS-only handoff with active stale-handoff deletion on FAIL.**

## Accomplishments

- Implemented T1's raw statistic `topological_fidelity` (whole held-out set, no ambient normalization, `worse = max(loss_x_to_z, loss_z_to_x)`) and T3's raw statistic `rank_structure` (two `sklearn.manifold.trustworthiness` calls, continuity as the swapped-argument identity, `gate_value = 1 - min(trustworthiness, continuity)`)
- Implemented `t1_gate_value`/`t2_gate_value`/`t3_gate_value`, each a baseline-relative ratio through a shared zero/non-finite guard that raises `ValueError` naming the exact metric
- Implemented `unfaithfulness_adapter`, a duck-typed `SimpleNamespace` shim (via `chart_dim`, `out_dim`, `chart_decoders`, `embedding_decoder`) so `cae.unfaithfulness_coverage` runs unmodified against a TopoAE's single unbounded latent, rescaled through an affine `[0,1]^d -> latent-box` map
- Resolved the key-mapping question `02.4-PATTERNS.md` flagged for the planner: `GATING_METRICS = ("t1_topo_fidelity", "t2_recon_margin", "t3_rank_structure")`, `CAE_SLOT_ALIASES` built by zipping onto `cae.GATING_METRICS` (never hard-coded, never monkeypatched)
- Implemented `verdict_from_topoae_metrics`, which raises first on any absent/non-finite topoae-named metric, then delegates the strict-less-than comparison to `cae.verdict_from_metrics` through the slot remap, then maps `gate_detail` back to topoae names
- Implemented `write_topoae_verdict` (thresholds inside the `json_cache` cfg for manifest-mismatch protection; recomputes `gate_detail` and refuses to write on a verdict/gate disagreement) and `write_topoae_handoff`/`clear_stale_handoff` (PASS-only write; active deletion of both the handoff JSON and its `.meta.json` sidecar on FAIL, proved with planted files)

## Decisions Made

- The binding key-mapping resolution for threat T-02.4-11: `cae.py`'s borrowed slot names never appear in any artifact this phase writes; the positional remap (`CAE_SLOT_ALIASES = dict(zip(GATING_METRICS, cae_mod.GATING_METRICS))`) is the only place they are referenced, and only internally
- `write_topoae_verdict` recomputes `gate_detail` from `metrics`/`thresholds` rather than trusting a caller-supplied value, and raises if the caller's `verdict` argument disagrees with the recomputed one -- a small extra safety margin beyond what the plan's literal signature required, justified as Rule 2 (data-integrity: a verdict artifact whose stored outcome disagrees with its own gates is worse than useless)
- `topological_fidelity` rescales only the latent side (`z * latent_unit_scale(z)`), never the ambient side, matching D-05/RESEARCH.md Open Question 1's resolution
- `unfaithfulness_adapter` derives `out_dim` from `model.decoder[-1].out_features` rather than requiring a new attribute on `PlainAutoEncoder`, since `mlp_stack`'s default construction always ends in a bare `nn.Linear`

None. The `topological_fidelity` zero-loss test (`test_topological_fidelity_zero_on_identical_spaces`) required a specific ±1-valued fixture (mean-zero, unit-variance-by-construction columns) rather than arbitrary random data, so that `latent_unit_scale` returns exactly `1.0` and `x * 1.0` is bit-identical to `x` -- otherwise the internal rescale of the latent side alone would introduce a tiny nonzero loss even for "identical" inputs. This was anticipated during design, not discovered as a bug; no code change resulted.
