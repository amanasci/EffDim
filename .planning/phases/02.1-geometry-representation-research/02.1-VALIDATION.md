# Phase 02.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.

**Phase character (governs everything below).** This is a literature-review-and-decision phase.
ROADMAP.md states no production pipeline code is expected. Four of five requirements
(GEOM-01, 02, 03, 05) are "a reader can see X" — narrative deliverables verified by human
reading, not by assertion. Applying an implementation phase's automated-coverage expectations
here would manufacture tests that assert nothing real. The honest position is that this phase's
core output is argued prose, and its validation is human review.

What *is* automatable: any illustrative computation the phase chooses to run. Those get sanity
checks, because an illustrative number that is silently wrong is worse than no number.

## Manual-Only Verifications

| Behavior | Requirement | Why Manual | Test Instructions |
|----------|-------------|------------|-------------------|
| Flat-target class membership is correct | GEOM-01 | Claim about the literature and about solver construction; no code can assert it | Check each listed method against its defining objective/solver. The sharp claim to verify: PSD-constrained methods (LLE, Hessian-LLE, LTSA, Laplacian eigenmaps, MVU) and probability-based ones (t-SNE, UMAP) *cannot expose* a negative-eigenvalue statistic even when the same non-Euclidean geometry is present — so a clean plot from them is not evidence of anything |
| Candidate survey is complete and fairly costed | GEOM-02 | Judgment about coverage and about implementation maturity | Confirm each branch carries assumptions, cost at n=10,000, implementation state, and what it demands of Phase 3. Confirm the coordinate-producing vs graph-native fork is stated, since it decides whether Phase 3 is re-specified or re-scoped |
| Correction-vs-retention judgment is argued, not asserted | GEOM-03 | Contested methodological question | Verify the document states that Cailliez/Lingoes/eigenvalue-clipping are diagnostic-blind by construction — they force a passing gate on any input, curved or not — and therefore self-defeating for a project measuring curvature. Verify the recommendation is consistent with GEOM-04's choice |
| Recommendation is decision-grade | GEOM-04 | Requires judging whether Phase 3 could actually be re-specified from it without re-opening this question | Read as if you were the Phase 3 planner. Can you write PLAN.md from it? If the extrinsic/intrinsic curvature consequence of the chosen branch is not explicit, it is not decision-grade |
| Dimension treatment is representation-specific | GEOM-05 | Requires reasoning about entanglement | Verify the document does not simply declare `D_FROZEN=5` wrong. Curved targets can represent structure in fewer dimensions than flat ones need, so 5 is not refuted by the 18–25 local estimates — the working dimension must be re-derived from the chosen representation's own diagnostic |
