# Phase 02.1: Geometry Representation Research - Research

**Researched:** 2026-07-31
**Domain:** Non-Euclidean manifold representation and curvature estimation for a validated
~20-25 dimensional manifold whose geodesic metric is strongly non-Euclidean (41% negative
classical-MDS eigenvalue mass)
**Confidence:** MEDIUM

## Summary

Phase 2 established, across four experiments, that classical MDS cannot describe the geodesic
geometry of this Isomap fit: `m = 0.412071` (41% of absolute eigenvalue mass negative), robust
to `k`, survey column, resample, and normalization. This is not exploratory territory — it is a
well-studied failure mode with a real (if fragmented) literature, decades old in the
correction-methods branch (Cailliez 1983, Lingoes 1971) and very active in the
representation-learning branch (hyperbolic embeddings 2017-2019, mixed-curvature 2019, indefinite
MDS via bilinear forms NeurIPS 2024).

The terrain splits along one axis that matters more than any individual method choice:
**does the candidate produce continuous coordinates Phase 3 can decode from, or does it compute
curvature directly on the graph with no embedding step at all?** Coordinate-producing candidates
(hyperbolic/Lorentz, mixed-curvature/product-manifold, pseudo-Euclidean/Krein, diffusion maps)
are compatible with the existing DEC/CURV requirement shape — a C2-smooth decoder differentiated
via `torch.func` to get a mean-curvature *vector* field — with "Isomap coordinates" read as
"this phase's chosen coordinates." Graph-native candidates (Ollivier-Ricci, Forman-Ricci) need
no embedding, sidestep the flat-target problem entirely, and are argued in the literature to
converge to genuine Ricci curvature under conditions — but Ricci curvature is an *intrinsic*
scalar/tensor quantity, not the *extrinsic* mean-curvature vector CURV-01..03 specifically ask
for, and it gives Phase 3 nothing to differentiate. Choosing a graph-native representation is not
a smaller version of this phase's decision — it is a decision to re-open Phase 3's requirements,
not merely re-specify their input. This is the single highest-leverage finding for planning
(§ Entanglement).

A second load-bearing finding: methods that share Isomap's flat-target assumption do **not** all
share its diagnostic. LLE, Hessian LLE, LTSA, Laplacian eigenmaps, MVU, t-SNE, and UMAP all
target flat Euclidean output space, but their solvers are either PSD-constrained by construction
(MVU's SDP, Laplacian eigenmaps' graph Laplacian) or probability-based (t-SNE/UMAP) — none of
them can produce a computable negative-eigenvalue statistic the way classical MDS/Isomap can.
A clean-looking UMAP or t-SNE plot of this data would not be evidence the flat-target problem is
resolved; it would only mean the same failure has become invisible rather than absent.

A third finding bears directly on GEOM-05: the corrections that make classical MDS "pass"
(constant-shift/Cailliez, constant-additive/Lingoes, eigenvalue clipping) are mathematically
guaranteed to succeed on *any* input, including genuinely curved data — they are diagnostic-blind
by construction, not evidence of flatness. The 2024 Neuc-MDS line of work is the literature's own
articulated alternative: keep both eigenvalue signs and work in a pseudo-Euclidean/Krein
bilinear-form space rather than discarding the negative part.

**Primary recommendation (for how the planner should scope the phase, not a foreclosure of
GEOM-04 itself):** structure the phase around a small, apples-to-apples comparison of at most
three candidates — one coordinate-producing curved-target embedding (mixed-curvature/product
manifold, because a single constant-curvature hyperbolic space is a strong and likely-wrong
assumption for heterogeneous astronomical morphology data), one non-flattening
alternative (pseudo-Euclidean/Krein retention of the existing spectrum, since the split is
already computed), and one graph-native cross-check (Ollivier-Ricci on the existing k*=15 graph,
computed via the Sinkhorn-approximate solver so it is laptop-tractable) — evaluated against one
pre-registered criterion before comparison happens, not chosen after seeing which method looks
best.

### Pattern 1: Diagnostic-blind corrections vs. signal-retaining representations

**What:** Constant-shift (Cailliez), constant-additive (Lingoes), and eigenvalue clipping all
force a PSD Gram matrix and therefore a "passing" gate — on *any* input, curved or not.
Eigenvalue flipping and pseudo-Euclidean/Krein retention keep the negative eigenvalues as
information rather than discarding them.
**When to use:** Corrections are appropriate only as a documented *contrast* baseline ("here is
what forcing flatness would look like, and here is why it is not what we did") — never as the
project's actual representation, given the project's own stated goal of *measuring* curvature.
**Example:**
```python
# Source: general MDS-correction literature (Cailliez 1983, Lingoes 1971), synthesized —
# [ASSUMED] no single canonical Python reference implementation found; R's ape::pcoa and
# vegan::wcmdscale implement this (confirmed via WebSearch), not a Python package.
import numpy as np

def cailliez_correction(D):
    """Add a constant c to all off-diagonal distances so the resulting Gram matrix is PSD.
    WARNING: succeeds on any input, curved or not -- diagnostic-blind by construction."""
    n = D.shape[0]
    J = np.eye(n) - np.ones((n, n)) / n
    B_upper = -0.5 * J @ (D ** 2) @ J
    B_lower = -0.5 * J @ np.block([[np.zeros((n, n)), 2 * D], [2 * D, np.zeros((n, n))]]) @ J
    # c = largest eigenvalue of the special 2n x 2n matrix; see Cailliez (1983) for the exact form
    ...  # full derivation needed if this baseline is actually implemented
```

### Anti-Patterns to Avoid

- **Treating a clean UMAP/t-SNE plot as evidence the flat-target problem is resolved:** their
  solvers cannot expose the negative-eigenvalue diagnostic even when the same underlying
  non-Euclidean geometry is present (§Summary, GEOM-01).
- **Re-deriving "the" working dimension once, globally, before picking a representation:** the
  right dimension is representation-specific (a curved target space can need fewer or more
  dimensions than a flat one for the same manifold) — re-derive per candidate (GEOM-05).
- **Computing graph-native curvature on a freshly-built graph instead of the existing, validated
  k*=15 graph:** Phase 2 spent real effort validating k*=15's connectivity and stability; reusing
  it keeps the comparison apples-to-apples and avoids re-litigating the k-sensitivity question.
- **Choosing the evaluation criterion after seeing which candidate looks best on an ad hoc
  metric:** this project has an established pre-registration discipline (Phase 2's
  `02-REFIT-PREREGISTRATION.md`, committed before any re-fit ran) — apply the same discipline
  here, fixing the criterion before the comparison.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Ollivier-Ricci / Forman-Ricci curvature at n=10,000 | A custom optimal-transport-per-edge loop | `GraphRicciCurvature` (Sinkhorn-regularized OT) | Exact OT is an LP with `d_x * d_y` variables per edge; at 150,000 edges (k*=15) this is intractable without entropic regularization, which is easy to get numerically wrong (temperature/epsilon tuning) if hand-rolled |
| Riemannian optimization for hyperbolic/mixed-curvature embedding | Custom Poincare-ball exponential/logarithmic maps and Riemannian SGD | `geoopt` | Numerically delicate near the ball boundary (norm approaching 1); a well-documented source of silent NaN/instability bugs in from-scratch implementations |
| Diffusion-map kernel bandwidth selection and symmetric-conjugate stabilization | Naive Gaussian kernel + row-normalize + `eigh` | `datafold` | Getting the bandwidth wrong silently changes what "diffusion distance" means; the symmetric-conjugate trick for numerical stability is non-obvious and easy to omit |
| Gromov delta-hyperbolicity at scale | Exhaustive quadruple enumeration (`C(10000,4)` is intractable) | Hand-rolled **sampled**-quadruple estimator (no maintained Python package found for this specifically) | This is the one item in this table where hand-rolling is actually the right call — but the *sampling* strategy is the part with a documented right/wrong way (literature reports as few as 200 sampled 4-tuples used in practice); don't naively brute-force |

**Key insight:** every "don't hand-roll" item above is a numerically delicate primitive
(optimal transport, Riemannian manifold arithmetic, kernel bandwidth), not a simple formula —
exactly the class of code where an LLM-authored from-scratch implementation is most likely to
look plausible while being subtly wrong. The one exception (delta-hyperbolicity) is a plain
distance-matrix reduction with no such delicate machinery, but still has a "wrong way" (naive
brute force) that a planner should rule out explicitly.

## Common Pitfalls

### Pitfall 1: Method choice masquerading as a class-wide conclusion

**What goes wrong:** Concluding "Isomap failed, so we need a totally different tool" without
establishing which OTHER tools share the same assumption and would fail identically (just
invisibly).
**Why it happens:** The negative-eigenvalue diagnostic is specific to classical-MDS-style
methods; most alternatives don't expose an equivalent number.
**How to avoid:** GEOM-01's class-membership table (§Summary) — treat "doesn't show negative
eigenvalues" as "doesn't measure the problem," not "doesn't have the problem."
**Warning signs:** A candidate method's own documentation or paper never mentions
Euclidean-embeddability or metric validity at all.

### Pitfall 2: Correction-as-validation

**What goes wrong:** Applying Cailliez/Lingoes/clipping, seeing the gate pass, and treating that
as confirmation the geometry is "basically flat."
**Why it happens:** These corrections are guaranteed to produce a PSD matrix on any input.
**How to avoid:** If a correction is used at all, use it only as a labeled contrast baseline, and
report that it *cannot* fail regardless of input, per Pattern 1 above.
**Warning signs:** A pass rate of 100% across multiple correction methods tried — that is exactly
what the correction methods are designed to guarantee, not evidence of anything about the data.

### Pitfall 3: Single constant-curvature model on heterogeneous data

**What goes wrong:** Fitting a pure Poincare-ball (constant negative curvature everywhere)
embedding to data whose local curvature likely varies across regions (different galaxy
morphologies, different local density), and reading a mediocre fit as "hyperbolic embeddings
don't work here" rather than "a single curvature value doesn't work here."
**Why it happens:** Hyperbolic embeddings are the most heavily-tooled and most-cited candidate
(Nickel & Kiela 2017/2018), making them an easy default choice.
**How to avoid:** Prefer product/mixed-curvature (Gu et al. 2019) or at minimum explicitly check
whether the negative eigenvalue mass is concentrated in a pattern consistent with one constant
curvature, or diffuse/heterogeneous (consistent with the *existing* Phase 2 finding of a
"long diffuse negative tail, not one pathological... edge" — the same shape argument applies one
level up, to curvature homogeneity).
**Warning signs:** A single global curvature parameter fit with high residual variance across
regions.

### Pitfall 4: Graph-native curvature computed on the wrong graph or wrong k

**What goes wrong:** Building a fresh graph for Ollivier-Ricci (different k, different edge
weighting convention) instead of reusing k*=15, silently changing what's being compared against
Phase 2's findings.
**Why it happens:** `GraphRicciCurvature` expects a NetworkX graph with edge weights, and it's
easy to construct a new one from scratch rather than exporting the existing `nbrs_`/graph object
from the cached Isomap fit.
**How to avoid:** Export the k*=15 graph directly from `isomap.nbrs_` / the cached
`dist_matrix_`'s sparsity structure rather than rebuilding kNN from raw embeddings.
**Warning signs:** Curvature statistics that don't reproduce the connectivity/component-count
facts already established in Phase 1 (`ISO-01`).

### Sampled Gromov delta-hyperbolicity from the existing distance matrix

```python
# Source: synthesized from general Gromov four-point-condition literature (Jonckheere et al.,
# "Scaled Gromov four-point condition") [ASSUMED] -- no single canonical Python package found.
import numpy as np

def sampled_delta(D, n_samples=2000, rng=None):
    """D: precomputed geodesic distance matrix (already on disk from Phase 1-2)."""
    rng = rng or np.random.default_rng()
    n = D.shape[0]
    deltas = np.empty(n_samples)
    for i in range(n_samples):
        a, b, c, d = rng.choice(n, size=4, replace=False)
        s1 = D[a, b] + D[c, d]
        s2 = D[a, c] + D[b, d]
        s3 = D[a, d] + D[b, c]
        s = sorted([s1, s2, s3])
        deltas[i] = (s[2] - s[1]) / 2.0
    return deltas
```
This reuses `dist_matrix_` directly with no re-fit — cheap (2000 samples is well within the
literature's reported practice of using a few hundred to a few thousand sampled 4-tuples).

## Open Questions

1. **Does Ollivier-Ricci curvature's continuum-limit convergence to Ricci curvature hold under
   conditions this data plausibly satisfies?**
   - What we know: multiple papers (surfaced via search) establish convergence results for
     Ollivier-Ricci curvature on data clouds under a manifold-hypothesis-style setup.
   - What's unclear: the exact regularity/sampling-density conditions, and whether a
     ~20-25-dimensional manifold sampled at n=10,000 (roughly 400-500 points per intrinsic
     dimension on average, far sparser in effective per-dimension terms than low-dimensional
     graph-curvature demos usually use) plausibly satisfies them.
   - Recommendation: read arXiv:2307.02378 directly during phase execution before leaning on this
     claim for GEOM-04's argued judgment; treat it as `[CITED]`-strength at best here, not `[VERIFIED]`.

2. **Is a single evaluation criterion (e.g., pairwise-distortion) fair across coordinate-producing
   and graph-native candidates, or does comparing them at all require two different arguments?**
   - What we know: distortion/stress is well-defined for any coordinate-producing embedding;
     Ollivier-Ricci curvature has no natural "distortion of the original distances" number since
     it does not attempt to preserve them.
   - What's unclear: whether the phase should even attempt a single unified score, or instead
     argue the choice qualitatively (this connects directly to the Entanglement section).
   - Recommendation: decide this explicitly and pre-register it, rather than let it be implicit in
     whichever comparison table gets built first.

3. **The one variable never varied across all of Phase 2's evidence — the model architecture
   (DINOv3 ViT-B/16 only) — is unresolved and this phase inherits that uncertainty.** The
   packaged 35-model sweep (not yet run) could change how confidently a *particular* curved-target
   representation should be committed to versus kept provisional pending that sweep's result.
   Recommendation: the phase's GEOM-04 recommendation should be explicit about whether it is
   architecture-specific or expected to generalize, matching FINDINGS.md §8's own framing.

## Entanglement

*(Addresses research question 6 directly — this is the section most load-bearing for how the
planner splits the phase into plans.)*

1. **Representation family <-> Phase 3 decoder architecture viability.** The single largest
   entanglement (§Summary, Architecture Diagram). Coordinate-producing candidates preserve
   Phase 3's DEC/CURV requirement shape (re-specify the input, not the architecture).
   Graph-native candidates (Ollivier/Forman-Ricci) produce no coordinates, cannot feed a decoder,
   and compute a genuinely different curvature notion (intrinsic Ricci vs. the extrinsic mean-
   curvature *vector* CURV-01..03 specifically ask for) — choosing this path reopens Phase 3's
   requirements rather than re-specifying its input. **This must be decided before, not after,
   any detailed Phase 3 re-plan**, and the planner should treat "which side of this fork" as
   effectively the first decision the phase makes, gating almost everything downstream of it.

2. **Representation choice <-> working dimension (GEOM-05).** Curved target spaces can represent
   the same structure in fewer (or more) dimensions than a flat space would need for it — the
   striking data point found in this research is a hyperbolic embedding reaching MAP=0.989 on a
   hierarchy-reconstruction benchmark using only 2 dimensions where 200-dimensional Euclidean
   embeddings did worse. This means dimension cannot be fixed independently of, or prior to,
   the representation choice — each candidate needs its own stress/distortion-vs-dimension curve,
   and the three (representation, dimension, evaluation criterion) form one joint decision, not
   three sequential ones.

3. **Evaluation criterion <-> representation choice (Open Question 2).** Different candidate
   families have evaluation metrics that are not natively comparable (MDS-family: stress;
   hyperbolic/graph-embedding literature: distortion, mAP; graph-native: curvature-distribution
   shape, no distance-preservation number at all). The criterion must either be fixed to something
   computable across all candidates under consideration (e.g., pairwise geodesic-distance
   distortion, computable for any coordinate output) *before* candidates are shortlisted, or the
   shortlist itself must be narrowed first to families sharing a criterion — these cannot be fully
   sequenced apart.

4. **Correction-vs-retention stance (GEOM-03) <-> representation choice.** Choosing a
   pseudo-Euclidean/Krein representation *is* choosing to retain rather than correct the negative
   eigenvalues — the GEOM-03 judgment and the GEOM-04 recommendation are not independent
   questions answered in sequence; a Krein-space recommendation for GEOM-04 essentially answers
   GEOM-03 as a side effect, and vice versa.

5. **Compute budget <-> which k the graph-native candidate reuses.** If Ollivier-Ricci is pursued
   at all, its cost scales with edge count (`k`), and Phase 2 already showed larger `k`
   increasingly short-circuits/chordalizes the graph. Reusing the already-validated k*=15 graph
   (150,000 edges) is both the cheaper and the more defensible choice — recomputing at a different
   `k` reopens the k-sensitivity question Phase 2 closed.
