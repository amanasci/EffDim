# Phase 02.1 Fork Verdict — Coordinate-Producing vs Graph-Native

**Committed strictly after `02.1-PREREGISTRATION.md` (`faefac1`)**, against the fork test that
document fixed first; ordering proved mechanically (`git merge-base --is-ancestor` +
`git cat-file -e`).

## Fork Verdict

**Coordinate-producing branch.** Of the six families, four are coordinate-producing (hyperbolic
Poincare/Lorentz, mixed-curvature product, pseudo-Euclidean/Krein, diffusion maps), two
graph-native (Ollivier-Ricci, Forman-Ricci). Only coordinate-producing families can supply
DEC-01's decoder with something to fit — the fork test's definition determines this directly once
each output type is checked. Graph-native is set aside on requirement compatibility with its cost
recorded below, not on difficulty.

## Applying the Fork Test

The pre-registered test: coordinate-producing iff each point gets a finite real coordinate vector
a twice-differentiable map into R^768 can be fitted from — what DEC-01 (C2-smooth decoder) and
CURV-01..03 (batched torch.func Jacobian → first fundamental form; normal-projected ambient
Hessian → second; mean-curvature vector field) presuppose: a coordinate domain to differentiate
over.

| Family | Output | Coordinate vector? | Result |
|---|---|---|---|
| Hyperbolic (Poincare/Lorentz) | ball/hyperboloid point per input | Yes — differentiably related to a Euclidean chart | **Coordinate-producing** |
| Mixed-curvature product | tuple of per-factor coordinates, concatenable | Yes | **Coordinate-producing** |
| Pseudo-Euclidean/Krein | (p,q)-signature vector from top-p/top-q eigenvectors | Yes — the indefinite form lives in the distance computation, not the coordinate type | **Coordinate-producing** |
| Diffusion maps | leading diffusion eigenfunctions per point | Yes — same output type as Isomap, different kernel | **Coordinate-producing** |
| Ollivier-Ricci | scalar per edge of the k*=15 graph | No | **Graph-native** |
| Forman-Ricci | scalar per edge (combinatorial) | No | **Graph-native** |

## The Two Branches

**Coordinate-producing** (selected): a finite real vector per point in a target not required to be
flat — exactly DEC-01's expected input with the target re-specified. Curvature measured
analytically via the decoder's Jacobian/Hessian (CURV-01/02), producing CURV-03's vector. Every
candidate evaluated on the pre-registered DISTORTION/DISTORTION_SIGNED over the fixed 200,000-pair
sample plus its own Working-Dimension elbow.

**Graph-native**: scalar curvature per edge of the existing k*=15 graph (Ollivier via OT
comparison of neighbourhoods, Forman via combinatorics) — no embedding, nothing for a decoder.
Computes an **intrinsic** Ricci quantity, not the **extrinsic** mean-curvature vector CURV-01..03
ask for: different mathematical objects, not one quantity computed two ways. The continuum-limit
convergence claim (arXiv:2307.02378) is [CITED]-strength, unread this session; **this verdict does
not lean on it either way** — the disqualification is structural. Any later plan using the claim
must read the paper first.

## Graph-Native Branch Cost

Cost is a fact the reader is owed, never the reason the branch loses:

- **Three packages, none installed:** `networkx` (absent entirely), `GraphRicciCurvature`, `POT` —
  all SUS; each install behind its own blocking `checkpoint:human-verify` gate, none pre-approved.
- **The graph:** mandatory reuse of the validated k*=15 graph, exactly 150,000 edges
  (`codiag_k15_*.npz` edge_lengths length); another k reopens the closed k-sensitivity question.
- **Transport cost:** OT across every one of 150,000 edges; the exact LP is intractable at this
  scale — Sinkhorn entropic approximation is necessary, not optional.
- **An unbuilt fixture:** a synthetic weighted tree (known negative curvature) + near-regular
  expander (known near-zero/positive) at matched scale, required before any number is trusted;
  design-only today.

## What Phase 3 Inherits

**Coordinate-producing (selected):** all of DEC-01..05 and CURV-01..08 inherited, with exactly one
amendment (already in REQUIREMENTS.md's DEC header): "Isomap coordinates" reads as "the
coordinates of the representation chosen in Phase 02.1". DEC-01 and CURV-08 change referent only;
DEC-02..05 and CURV-01..07 are representation-independent and unchanged — CURV-03's vector is
exactly what a coordinate-producing decoder supplies.

**Graph-native (not selected):** DEC-01..05 inapplicable (nothing to decode); CURV-01/02
inapplicable (no decoder); CURV-03's extrinsic vector does not exist on this branch — replaced by
an intrinsic Ricci scalar/tensor, a different requirement; CURV-04 (no metric tensor), CURV-05 (no
decoder derivatives) dropped; CURV-06/07 re-architected around the tree-and-expander fixture
instead of flat-plane/sphere/saddle; CURV-08's analogue becomes "curvature only on the actual
k*=15 graph's edges, never a resampled or reweighted graph".

## What Phase 3 Re-opens

**Coordinate-producing:** nothing — a re-specification of Phase 3's input; requirement set and
text stand.
**Graph-native:** all thirteen DEC/CURV requirements — dropped, rewritten, or re-architected as
above, plus a REQUIREMENTS.md traceability update. This asymmetry is why the fork gates almost
everything downstream.

## Falsifier Status

Restated from the pre-registration: this verdict is overturned iff BOTH (a) real `DELTA_REL` sits
far from the tree anchor — indistinguishable from or closer to the flat-Euclidean anchor than the
reading rule allows — AND (b) the (p,q) ladder never drops DISTORTION materially below the q=0
baseline (which failed at m=0.412071) at any rung up to 40. **Neither condition tested yet** —
this verdict rests on the structural fork test alone. **Plan 02.1-03 tests it** (the
Krein/(p,q)-ladder probe and the delta probe produce exactly these two numbers). If both trip, the
verdict is revisited before 02.1-04's recommendation — a documented amendment, not a quiet edit.
