`build_gram_matrices` returns two dicts keyed by kernel name — `"linear"`, `"rbf_0.5sigma"`,
`"rbf_sigma"`, `"rbf_2sigma"` — one dict per modality, eight matrices total, each built exactly once
over all 10,000 points and stored at `dtype`. The RBF bandwidth for a modality is that modality's own
frozen scalar times the multiplier; the two modalities never share a scale, because HSC and Legacy
are different spaces with no reason to (D8-03). No subset index is accepted by this function, so no
call site can pass one and get a per-subset bandwidth.

`run_sigma(args)` is a pre-freeze measurement mode. It calls `load_pu_pair("hsc", "legacysurvey")`,
computes `median_pairwise_distance` once per modality over all 10,000 rows, prints each as a
`sigma_median_pairwise modality=<name> value=<full precision>` line, then calls
`build_gram_matrices` at the three multipliers and prints each build's kernel name, wallclock and
resulting dtype, plus the process peak RSS in MB read from `resource.getrusage`. It appends one JSONL
row per (modality, kernel) to the scratch record with the keys listed in this plan's artifacts
section, every value cast to a plain Python scalar. It does **not** call `assert_preregistered()`,
prints a banner saying it is a pre-freeze measurement producing no verdict number, REQUIRES
`--record-path`, and refuses to default onto any frozen record path — the same discipline
`--mode selfcheck` uses. Point it at `notebooks/.cache/08_scratch_sigma.jsonl`.

`run_sigma` computes no CKA value, constructs no density stratum and constructs no tertile. Those all
depend on constants that are still UNSET, and the whole point of this mode is that its two outputs
are pre-registration inputs under D8-03, not results. Print the two sigma values at full float
precision — never round a value that is about to become a frozen literal.

If the peak RSS exceeds 6 GB or the process is killed, fall back to building and releasing one RBF
rung at a time, caching each to `notebooks/.cache/` as a `.npy` through `cache.cache_path`, and record

  </action>

- **`GRAM_DTYPE = "float32"`** (frozen at 08-04). Eight float64 `(10000, 10000)` matrices are ~6.4 GB;
  float32 halves that to ~3.2 GB (RESEARCH.md A3). 08-01's `test_gram_dtype_agreement` is the evidence
  the choice does not move CKA beyond 1e-5. The one-at-a-time disk fallback is documented rather than
  a silent dtype downgrade, so a memory-constrained run changes runtime and not the number.
- **`--mode sigma` is a separate mode, not folded into `--mode sweep`.** D8-03 requires sigma to exist
  as a frozen constant before any subset exists; a sweep that computed it inline would recompute a
  pre-registered value at run time, which is precisely the pattern `assert_preregistered` exists to
  make impossible.
- **`load_pu_pair` and `append_record_row` are copied into Phase 8's runner rather than imported from
  07.1's.** `notebooks/diagnostics/` is a plain directory, not a package, and 07.1's runner performs
  module-level thread-environment writes that collide on import — 07.1 itself copied these from
  Phase 7 for the same reason and said so in its docstring.
</discretion_decisions>
