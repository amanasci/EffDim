<objective>
Build and run `notebooks/diagnostics/decoder_substrate_screen_run.py`: the four-seed, four-axis
screening sweep for both free candidates, and capture its tables for plan 02.6-06 to transcribe.

Purpose: SC-4 requires four seeds minimum with spread reported, and CLAUDE.md bars threshold tables
and heavy machinery from a sanity notebook — so the seed sweep cannot live in either admission
notebook. This is exactly the split Phase 02.4 already made when it moved its lambda sweep into
`notebooks/diagnostics/` for the same stated reason, and exactly what 02.5-09 did when it ran its
four-seed robustness check outside the notebook. The difference from 02.5-09: that sweep ran in a
scratchpad and left no re-runnable artifact. This one is committed.
Output: one runner script and its captured per-seed tables.
</objective>

<why_the_seed_sweep_is_the_point>
Plan 02.5-09 measured the CAE's Spearman running `-0.0604 / -0.1444 / 0.8665 / 0.4250` across four
torch seeds **at one configuration**, a range of `1.0109`. At seed 2 the CAE beat the raw-point
baseline on every axis at once; at seeds 0 and 1 it was indistinguishable from noise. A single-seed
admission result for any candidate in this phase would be a draw, not a result — SC-4 exists because
this project has already measured exactly that failure.

Two seeds in that table (0 and 3) also had essentially the same reconstruction quality (5.21% versus
5.50%) and Spearman differing by 0.49. Reconstruction quality does not predict curvature agreement
even across models of the same architecture on the same data, which is why the runner's table carries
reconstruction relative error in its own column beside the four axes rather than in place of any of
them.
</why_the_seed_sweep_is_the_point>
