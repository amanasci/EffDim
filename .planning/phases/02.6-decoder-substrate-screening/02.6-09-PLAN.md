<objective>
Build the persistent-homology agreement instrument (SC-3; D-01, D-03, D-04, D-05, D-06) and prove it
end to end on one candidate at one seed.

This is the phase's largest piece of genuinely new code. `ripser` and `persim` have been used exactly
once in this project — in `notebooks/quick_topoae_vs_cae_persistence.ipynb`, notebook-only, untested,
unpromoted. That quick task proved the library API works in this venv at these sample sizes, and it
surfaced two hazards that transfer directly onto this design. This plan promotes its helpers into a
tested sibling module under `notebooks/pu_manifold/`, generalised over any
(model diagram, reference diagram) pair rather than the quick task's TopoAE-versus-CAE framing, and
replaces its diameter-normalisation convention with D-05's reference-max-persistence rule.

Persistent homology needs no C2 guard, no autodiff and no chart-index care: a diagram is built from
point coordinates alone. `assert_c2_decoder` is therefore never called anywhere in this module, and
the CAE — excluded from the halted axis entirely because its chart-fragmented decoder cannot be
safely differentiated — needs no special casing here.

Purpose: everything the phase ranks on flows through this one module, so it is pinned against known
answers before any candidate touches it.
Output: `notebooks/pu_manifold/persistence_probe.py` and its test file.
</objective>

  order, exactly matching `02.6-SCREENING-RULE-02.md`'s ratified labels: the cross product of
  space in (`latent`, `decoder_image`), reference in (`intrinsic`, `ambient`), degree in (`H0`,
  `H1`) and distance in (`bottleneck`, `wasserstein`), joined by a pipe with a `_norm` suffix on the
  distance component — for example `latent|intrinsic|H1|wasserstein_norm`. This tuple is the one
  place the labels are written down in code; the runner, the notebooks and the findings document all
  key off it.

- `finite_pairs(dgm)` — the finite birth/death rows of one `ripser` diagram as a contiguous float64
  `(m, 2)` array, empty `(0, 2)` if none. Promote the quick task's version verbatim, including its
  docstring point that filtering the H0 diagram's single infinite death is required for correctness
  and not hygiene, because `persim`'s distances cannot consume it and an unfiltered max is infinite.

- `persistence_diagram(D, maxdim=PH_MAXDIM)` — takes a square symmetric float64 distance matrix and
  returns the filtered per-degree diagrams in RAW units. Normalisation is a caller-side division, not
  baked in, so the same raw diagram serves D-05's rule and any future convention without recomputing
  `ripser`.

- `max_persistence(dgm)` — the reference diagram's own scale per D-05: the largest life in the
  diagram, `0.0` for an empty diagram. Its docstring cites the thin-denominator travelling caveat by
  name and does not restate it.

- `saturation_value(ref_dgm)` — half the reference's longest life: the value a bottleneck distance
  takes and cannot exceed once nothing in the model diagram is close enough to match that bar. Its
  docstring cites the saturation travelling caveat by name.

- `is_saturated(value, ref_dgm, tol=1e-6)` — whether a bottleneck value sits on that point.

- `ph_agreement(model_dgm, ref_dgm)` — returns a dict with `bottleneck`, `wasserstein`,
  `ref_max_persistence`, `bottleneck_norm`, `wasserstein_norm`, `saturated`. Both normalised fields
  are the raw distance divided by `ref_max_persistence`, or `nan` when that denominator is not
  strictly positive. Do NOT floor the denominator and do NOT substitute a fallback — this function
  is policy-free by design; whichever of option group P was ratified is applied by the caller, and
  the ratified document is the only place it is written down.

- `cloud_distance_matrix(points, prescale)` — the one entry point that turns a point cloud into a
  distance matrix. `prescale` is a **required positional argument with no default**, so no call site
  can silently inherit a convention; when true it multiplies the cloud by
  `topoae.latent_unit_scale(cloud)` first and returns the applied scalar alongside the matrix, and
  when false it returns `1.0`. Distances go through `topoae.pairwise_distances_f64` unchanged — the
  float64 discipline is sealed, tested code and is not re-derived here. Document in the docstring
  that `latent_unit_scale` is a single global isotropic scalar, so it is an isometry up to uniform
  scale and cannot reorder neighbours, which is why it is safe to apply symmetrically to model and
  reference clouds alike.

- `readout_matrix(spaces, references, prescale)` — the phase's reporting unit. `spaces` maps
  `latent` and `decoder_image` to point clouds; `references` maps `intrinsic` and `ambient` to point
  clouds; `prescale` is again required with no default. It computes exactly one diagram per cloud
  (four `ripser` calls per candidate per seed — the 16 numbers are a reporting decomposition of two
  diagrams against two references at two degrees under two distances, not sixteen `ripser` calls)
  and returns one flat dict carrying every key in `READOUT_CELLS`, plus for each cell its raw
  distance under a `_raw` suffix, plus `ref_max_persistence` per (reference, degree), plus
  `saturated` per bottleneck cell, plus the applied scale per cloud. It returns **no** key that
  weights, sums, averages or ranks cells together; there is no composite figure anywhere in this
  phase.
