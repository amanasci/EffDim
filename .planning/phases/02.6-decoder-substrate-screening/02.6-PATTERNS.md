### `notebooks/pu_manifold/decoder_curvature.py` (utility, transform)

**Analog:** `notebooks/pu_manifold/chart_curvature.py` (full file read this session; 788 lines)

**Module docstring / header conventions to copy** (lines 1-70 of the analog):
- Module-level `import torch` and `from torch.func import hessian, jacrev, jvp, vmap` — this module is exempted from `pu_manifold/__init__.py`'s eager imports for the same reason (`cae.py`, `curvature.py`, `mknn.py` already are), so Phase-1-only callers don't need torch.
- `CURVATURE_CONVENTION = "trace"` must be re-declared identically (`H = tr_g(II)`, never the averaged `H/d`) — this is the single most expensive thing to get wrong per the analog's own docstring, and it is asserted equal to `curvature_probe.CURVATURE_CONVENTION` by an existing regression-guard-style test convention.
- `VMAP_CHUNK = 32` — import unchanged from `chart_curvature`, do not redefine. It is a reproducibility constant (`vmap(hessian(f))` is NOT bit-reproducible across differing batch widths), not a tuning knob.

**The map that gets differentiated — exact code to adapt** (`chart_decoder_map`, lines 173-199, and the RESEARCH.md Pattern 1 worked-out version, lines 216-259 of `02.6-RESEARCH.md`):
```python
# analog: chart_curvature.chart_decoder_map(model, chart_idx) — TWO-hop compose
# (chart_decoders[chart_idx] then embedding_decoder). The new module's decode_one
# is ONE hop — model.decode(z) is the entire decoder for PlainAutoEncoder, chart-routed
# or not (TopoAE trains the identical cae.PlainAutoEncoder class).
def plain_decoder_map(model):
    def decode_one(z: torch.Tensor) -> torch.Tensor:
        return model.decode(z.unsqueeze(0)).squeeze(0)
    return decode_one
```
**Critical pitfall named explicitly in the analog's own docstring (lines 178-187) and restated in RESEARCH.md line 261:** never wrap `model.forward` — it returns `{"z":..., "y":...}` and re-derives `z` internally, so differentiating it would measure the curvature of the encoder-composed round-trip map, not the decoder's own image manifold. Use `model.decode` directly.

**Guards to reuse unchanged, by import, not by copy:**
- `assert_c2_activation(model)` (lines 131-167) — raises `ValueError` naming the activation unless C2-smooth; both `PlainAutoEncoder` and the TopoAE-trained `PlainAutoEncoder` use `activation="silu"` by default so this passes, but the guard must still run first (a non-C2 decoder silently returns an all-zero second fundamental form, "the single most dangerous failure mode in this module").
- `_pad_to_chunk` (lines 230-237) — pads a short final chunk by repeating its last row; import or duplicate verbatim (Open Question 1 in RESEARCH.md flags duplicate-vs-share as Claude's discretion, recommending duplicate — this codebase's established pattern at every prior sibling-module insertion).
- `_assert_float64` (lines 202-223) — refuses float32 model/inputs; second derivatives are exactly where float32 noise shows first.

**Core chunked-differentiation pattern to mirror** (`_chunked_jacobian`, lines 240-248, and the Hessian-chunking loop inside `chart_mean_curvature`, lines 340-386):
```python
def plain_decoder_curvature(model, z: torch.Tensor) -> torch.Tensor:
    assert_c2_activation(model)
    decode_one = plain_decoder_map(model)
    parts_J, parts_H = [], []
    for start in range(0, z.shape[0], VMAP_CHUNK):
        real = z[start:start + VMAP_CHUNK]
        padded = _pad_to_chunk(real)
        parts_J.append(vmap(jacrev(decode_one))(padded)[: real.shape[0]])
        parts_H.append(vmap(hessian(decode_one))(padded)[: real.shape[0]])
    J = torch.cat(parts_J, dim=0)      # (batch, out_dim, latent_dim)
    Hess = torch.cat(parts_H, dim=0)   # (batch, out_dim, latent_dim, latent_dim)
    g = torch.einsum("boi,boj->bij", J, J)
    g_inv = torch.linalg.inv(g)   # analog uses torch.linalg.solve against a batched
                                    # identity instead — better conditioned, costs nothing
                                    # extra; prefer that form, matching chart_mean_curvature
    proj = torch.eye(J.shape[-1], dtype=J.dtype)[None] - torch.einsum(
        "boi,bij,bpj->bop", J, g_inv, J
    )
    II = torch.einsum("bop,bpjk->bojk", proj, Hess)
    H = torch.einsum("bij,boij->bo", g_inv, II)
    return H
```
**Note (RESEARCH.md's own flagged deviation, chart_mean_curvature docstring lines 284-294):** the sealed analog does NOT materialize the `(out_dim, out_dim)` projector or the full `II` tensor — it traces first and projects second via a `chart_dim x chart_dim` solve, because at `out_dim = 768` a batch of 32 explicit projectors is 151 MB float64. RESEARCH.md's own Pattern 1 snippet (reproduced above) is the illustrative, unoptimized form; the planner should decide whether the new module needs the same memory optimization (`PlainAutoEncoder`'s `in_dim` is the same 768-dim PU embedding, so the same memory pressure applies) or whether the simpler form suffices for a Swiss-roll-only (`out_dim=3`) sanity check. This is a genuine open decision, not resolved by either source document.

**Return-shape convention to match** (`chart_mean_curvature`'s dict, lines 269-274, `curvature.py`'s norm convention, lines 401-412): return `{"H_vec": (batch, out_dim), "H_norm": ..., "metric_condition_number": ..., ...}` — norm of the curvature *vector*, never a signed scalar (no canonical normal direction at codimension > 1).

```python
def _flat_plane_fixture(n, D, seed):
    rng = np.random.default_rng(seed)
    uv = rng.uniform(-1.0, 1.0, size=(n, 2))
    X = np.zeros((n, D)); X[:, :2] = uv
    Q, _ = np.linalg.qr(rng.standard_normal((D, D)))
    return X @ Q.T

def _sample_sphere(d, radius, n, seed):
    # true ||H|| = d / radius exactly, trace convention
    rng = np.random.default_rng(seed)
    pts = rng.standard_normal((n, d + 1))
    return radius * pts / np.linalg.norm(pts, axis=1, keepdims=True)
```
**Known-answer assertion pattern to mirror** (lines 87-107):
```python
def test_centroid_estimator_known_curvature():
    # (a) flat: median ||H|| < 1e-6 * scale  (scale = 1/mean_nn_dist)
    # (b) sphere R=1.5, d=2: |median_est - 2/R| / (2/R) < 0.20   -- O(r^2) finite-radius
    #     band, not a tuning knob
```
**Adapting for `decoder_curvature.plain_decoder_curvature`:** since the new module differentiates a *decoder* (`z -> ambient`), not a point cloud, the fixture must be pushed through a trivial linear or `PlainAutoEncoder`-shaped decoder whose analytic curvature is known exactly — VALIDATION.md Wave 0 names exactly this ("a sphere known-answer test (`H = d/R`) and a flat-plane test (`H_norm == 0.0` exactly), both differentiated through a trivial linear / `PlainAutoEncoder`-shaped decoder"). A flat linear map (`z -> Az + b`) has `II = 0` everywhere by construction (zero Hessian), giving an exact `H_norm == 0.0` test with no finite-sample band needed — stronger than the point-cloud flat test's `< 1e-6 * scale` tolerance, because there is no neighbourhood-radius bias here at all (this is the decoder arm's whole statistical advantage per `chart_curvature.py`'s own module docstring, lines 23-32). A trivially-parameterized sphere immersion (e.g. `z -> R * (cos-like stereographic map)`,  or reuse the same closed-form sphere embedding the fixture module already contains) gives the exact `H = d/R` known answer with no finite-radius bias either, since this is now exact autodiff, not a k-NN estimator — the 20% band in the analog exists ONLY because that test differentiates a point cloud, not a function; a decoder-arm sphere test should assert near machine precision, not a percentage band.

**Confirmed: no existing `test_chart_curvature.py`.** `notebooks/pu_manifold/tests/` contains `test_cae.py`, `test_curvature_probe.py`, `test_geometry_probes.py`, `test_pu_manifold.py`, `test_topoae.py` — no test file for `chart_curvature.py` itself exists in this repo, despite `chart_curvature.py`'s own docstrings referencing tests like `test_chart_curvature_uses_trace_convention_not_averaged`, `test_chart_curvature_dxd_solve_matches_explicit_projector`, `test_chart_curvature_field_reassembles_in_row_order` by name.
