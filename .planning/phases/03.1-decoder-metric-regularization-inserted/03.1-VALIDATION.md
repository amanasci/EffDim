## Sampling Rate

- **After every task commit:** Run the targeted quick command for the module touched
  (`test_decoder_priors.py` for D-12 work, `test_curvature_probe.py` for D-15 work)
- **After every plan wave:** Run `.venv/bin/python -m pytest notebooks/pu_manifold/tests/ -q`
- **Before `/gsd-verify-work`:** Full suite green **and** the new runner's `--anchor-check`
  passing — per D-13 the exact-equality anchor is itself a gate, not merely a test
- **Max feedback latency:** quick command < 60s

## Wave-Parallelism Constraint

**The five plans run strictly sequentially, waves 1 through 5, with no cross-plan parallelism.**
This is deliberate rather than an oversight: plans `03.1-03` and `03.1-04` measure wall-clock
seconds-per-epoch and seconds-per-row at the real architecture, and a co-scheduled CPU-heavy job
would contaminate every timing that sizes the 8-hour ladder run. Each expensive plan states the
no-co-scheduling requirement in its own objective, and threat `T-03.1-06` records the risk.
