## Decisions Made

- **Promoted the absolute-scale fields to primary** (this plan's `<assumption_delta_decision>`, `promote`): `cond(g)` measured ranking two uniformly-collapsed seeds ahead of the one healthy fit in Phase 3, an exact consequence of it being scale-invariant. `lambda_min`, `lambda_max` and `log10_det_g` are now the primary metric-health read; `cond(g)` is retained (CURV-04's flagging clause still needs it, and Phase 3's sealed records store only it) but a `cond(g)` improvement paired with a falling `lambda_max` is now scored `COLLAPSE`, never success.
- **`calibrate_weights`'s penalty measurement stays outside `torch.no_grad()`** (deviation, documented below): wrapping the real Hessian computation in `no_grad()` broke `christoffel_penalty`'s `jacfwd(jacfwd(...))` forward-over-forward composition on this torch build. `float(tensor.detach())` gets the identical one-shot read without disabling the autograd machinery the decomposition needs.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `torch.no_grad()` around `calibrate_weights`'s penalty measurement broke forward-over-forward Hessian AD**
- **Found during:** Task 3 (manual verification of `calibrate_weights` beyond the plan's stated acceptance criteria, before committing)
- **Issue:** An initial implementation wrapped the whole measurement block -- `base_recon` and both penalty calls -- in a single `torch.no_grad()` context, on the reasoning that no training happens in this function. That broke real (non-mocked) execution with `NotImplementedError: Trying to use forward AD with aten::silu_backward that does not support it.` `christoffel_penalty`'s Hessian goes through `jacfwd(jacfwd(decode_one))`; on this torch build (2.13.0+cpu), the forward-over-forward decomposition path for `silu`'s second derivative itself needs an active (backward-mode) autograd graph to decompose against, so disabling grad entirely broke it. The bug was invisible under the acceptance criterion's own test (a mocked zero-penalty stub that never reaches the real Hessian code path).
- **Fix:** Kept `base_recon`'s measurement under `torch.no_grad()` (it only touches a forward pass and `chart_loss`, no Hessian), and left the two penalty calls (`isometry_penalty`, `christoffel_penalty`) outside `no_grad()`, calling `.detach()` on each returned tensor before `float(...)` to get a clean one-shot read without either building a retained graph or disabling the decomposition machinery.
- **Files modified:** `notebooks/diagnostics/decoder_prior_ladder_run.py`
- **Verification:** Re-ran `calibrate_weights` on a real (non-mocked) matched-architecture model and confirmed it returns finite weights for both modes with zero `UserWarning`s; re-ran the mocked-zero-penalty `ValueError` test to confirm the refusal path still fires; re-ran the full test suite (315 passed, 1 skipped) and the `--dry-run`/`--smoke` verify commands.
- **Committed in:** `a345889` (Task 3 commit; the fix landed before the commit, so no separate commit was needed)
